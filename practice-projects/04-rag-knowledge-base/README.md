# 项目四：企业级 RAG 知识库问答系统（RAG Knowledge Base）

> **项目目标**：用 Spring AI 构建一个"上传文档 → 自动切片向量化入库 → 智能问答（带引用溯源）→ Agent 工具调用"的企业知识库系统，把 AI 工程能力写进简历，这是 P7+ 之后最值钱的差异化能力。
> **预计周期**：6-8 周（配合学习阶段五）
> **最终成果**：可对话的知识库系统 + RAGAS（RAG 评估框架）评估报告 + Agent 工具演示 + 架构复盘

## 业务场景

企业内部有大量文档（产品手册、制度规范、历史工单），员工查找低效。做一个"企业百事通"：
- 上传 PDF/Word/Markdown，自动学习知识
- 员工自然语言提问，回答**附带原文引用**（可溯源、可验证）
- 接入业务工具：问"我的订单到哪了"能直接调订单接口回答
- 回答必须**忠实于知识库**（Grounding，即答案有据可依），拒答编造

## 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 应用框架 | Spring AI 1.x | Java 生态原生，与 Spring Boot 无缝；简历友好 |
| 大模型 | DeepSeek / 通义千问（OpenAI 兼容协议） | 国内可直连，成本低；OpenAI 兼容接口随时可换 |
| 向量库 | PostgreSQL + pgvector | 一个库搞定向量+业务数据，运维简单；Milvus 留作进阶 |
| 文档解析 | Apache Tika / Spring AI ETL | 统一解析 PDF/Word/Markdown |
| 前端 | 任一 SSE 客户端（curl 即可） | 重点在服务端流式输出 |

## 核心数据流

```
【入库链路（离线/低频）】
上传文档 → Tika 解析为纯文本 → 切分 Chunk（块）→ Embedding（向量化）
        → pgvector 存储（向量 + 原文 + 元数据）

【问答链路（在线/高频）】
用户提问 → 查询改写（结合多轮历史）→ 混合检索（向量 + BM25 关键词）
        → Rerank（重排序精选 Top5）→ 组装 Prompt（含引用编号）
        → LLM 流式生成（SSE）→ 回答 + 引用来源
        →（可选）Agent 判断：需要查订单？→ Function Calling（函数调用）
```

## 面试价值点

1. RAG 解决 LLM 什么问题？和微调（Fine-tuning）怎么选？（知识时效性/私有知识/成本）
2. 切分策略怎么定？切大了小了各有什么问题？（语义完整性 vs 检索精度）
3. 纯向量检索为什么不够？混合检索怎么融合？（语义相似 ≠ 关键词命中；RRF 融合）
4. 怎么防止模型胡说八道？（Grounding Prompt + 引用溯源 + 拒答策略 + 忠实度评估）
5. Agent 的 Function Calling 原理？（模型输出结构化调用意图，执行权永远在应用侧）
6. 生产上怎么评估 RAG 效果？（RAGAS 四指标 + 线上用户反馈双闭环）

## 通用开发规范（四个项目统一）

- 模块：`rag-app`（问答 API）、`rag-ingest`（入库 Job）、`rag-common`
- 所有 LLM 调用必须：有超时、有重试、有 Token 用量统计、Prompt 走配置可热更
- 密钥不进代码库：环境变量注入 `OPENAI_API_KEY`（密钥，即调用大模型的凭证）
