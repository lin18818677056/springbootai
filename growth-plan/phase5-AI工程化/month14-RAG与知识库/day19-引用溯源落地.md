# Day 19 · 引用溯源落地：让每个 [n] 都靠得住

> **今日目标**：把引用从"Prompt 里的要求"变成"后端验证过的契约"——引用编号校验（防引用幻觉）、snippet 回显（前端可点开）、引用正确率纳入评测。
> **时长**：编码 2h / 评测 1.5h / 输出 0.5h
> **今日产出**：引用校验器 + 引用正确率报告 + 前端展示契约
> **对照教程**：`ai-learning/04-RAG检索增强.md` 第 5 节 Faithfulness 相关

## 1. 知识地图（先讲人话）

```
day06 让模型"标注 [n]"——但模型标注的 [n] 可靠吗？
  不可靠！引用也有幻觉（Citation Hallucination）：
  · 编号幻觉：答案标了 [4]，但这次只注入了 3 个块
  · 错位幻觉：内容明明来自块 1，它标了 [2]
  · 张冠李戴：句子 A 的信息标了块 B（更隐蔽）
  —— 模型是概率系统，"标注出处"这个动作本身也是接龙出来的，
  可能对也可能错。用户点开 [2] 发现内容对不上 → 信任崩塌比不标还惨。

解法：后端引用校验器（模型说不算，代码说了算）：
  ① 编号存在性校验：答案里的 [n] 必须在本次注入的块编号范围内
     （超范围的 → 剥掉该标注 or 整句降级为"未引用"）
  ② snippet 回显：citations 里带原文片段（后端从父块里截取），
     前端点开显示——用户核对的是"真原文"，不依赖模型转述
  ③（进阶，记录思路）句子级归因校验：把"答案句+所指块"给打分模型
     判相关性——day12 重排的 LLM 打分手艺复用，成本高、抽样用

信任链设计（本日的哲学）：
  模型输出 → 代码校验 → 用户可核验
  三层里只要"代码校验"这一层是确定性的，信任就有锚点
  （和 M13 的"防御链"同哲学：AI 的输出，永远过确定性检查）
```

## 2. 核心概念（中英对照+大白话）

| 英文 | 中文 | 大白话解释 |
|------|------|-----------|
| Citation Hallucination | 引用幻觉 | 编号/出处也是编的（模型说 [4] 却只有 3 块） |
| Citation Validation | 引用校验 | 后端验证 [n] 的存在性与指向合理性 |
| Snippet | 原文片段 | citation 附带的原文摘录（点开核对用） |
| Attribution | 归因 | 哪句话来自哪块资料（句子级溯源） |
| Verifiability | 可核验性 | 用户能自己验证答案（信任的锚点） |
| Post-processing | 后处理 | 生成之后的确定性检查层（剥假引用/脱敏/记账） |

## 3. 动手实操：校验器编码+评测

### 3.1 引用校验器（50 行内的确定性代码）

```java
// kb/service/CitationValidator.java
public CitationReport validate(String answer, List<CitedChunk> injected) {
    Set<Integer> validNos = injected.stream()
        .map(CitedChunk::no).collect(toSet());
    // ① 抠出答案里所有 [n]：
    Matcher m = Pattern.compile("\\[(\\d+)]").matcher(answer);
    List<Integer> cited = new ArrayList<>();
    while (m.find()) cited.add(Integer.parseInt(m.group(1)));
    // ② 编号存在性：不在注入范围内的标注 → 剥掉并记日志
    List<Integer> bogus = cited.stream()
        .filter(n -> !validNos.contains(n)).toList();
    String cleaned = bogus.isEmpty() ? answer : stripMarks(answer, bogus);
    // ③ 组装 citations（带 snippet——从父块截取标注相关的原文）：
    return new CitationReport(cleaned, toCitations(cited, injected), bogus);
}
// RagService 在发送 delta 之前调用——假引用到不了用户眼前
// bogus 非空时记 metrics：citations_bogus_total（引用幻觉率监控）
```

### 3.2 引用正确率评测（30 条考卷跑一遍）

```
给 30 条端到端考卷加两个判分维度：
  引用有效率：答案里的 [n] 全部真实存在且指向合理 → 记 1 分
  核对成本：点开 citation 能否在 10 秒内确认句子出处（人肉抽 10 条）
《引用评测记录》（填实测）：
  未加校验器：引用有效率 __%（有 [4] 幻觉/错位现场 __ 处）
  加校验器后：剥掉假标注 __ 处，有效引用 100%（剥掉的句子无标注，
  可接受——宁缺毋假）
```

### 3.3 前端展示契约（对接约定，前端 30 分钟能接）

```
citation 帧结构（day15 契约②的最终版）：
  { no: 1, docTitle: "退款政策 v2.3",
    snippet: "退款将在 3~5 个工作日原路返回。",   // 后端截取的真原文
    updatedAt: "2026-09-01" }                    // 用户可看资料新旧
交互约定：
  正文里的 [1] 渲染成可点角标 → 弹层显示 docTitle+snippet+更新时间
  → 用户完成"点开-核对-放心"闭环（信任链最后一公里）
```

## 4. 面试连接

**Q：RAG 的引用溯源怎么保证可信？模型的标注错了怎么办？（信任设计题）**
> 关键认知：模型标注的引用本身也是生成出来的，同样会幻觉——我们实测遇到过标了不存在的 [4]、内容来自块 1 却标 [2] 的错位。所以引用必须过一道确定性校验，模型说不算，代码说了算。校验器做三件事：编号存在性校验，超范围的标注直接剥掉并计数上报——宁缺毋假，没标注的句子可以接受，假标注是信任事故；snippet 回显，citation 里的原文片段由后端从父块截取，用户核对的是真原文不是模型转述；引用幻觉率进监控，某天突然升高通常意味着 Prompt 或检索变了，是个很好的变更信号。交互上正文角标可点开，弹层显示文档标题、原文片段和资料更新时间，用户十秒内能完成核对——可核验性是信任的锚点。这个设计哲学和整体防御链一致：AI 的输出永远过确定性检查，引用是给用户看的最后一道防线，必须由代码守，不能交给概率。
