## 1. 知识地图（先讲人话）

```
RAG 的监控比普通服务多一层"质量监控"——
  传统服务：能响应+响应快 = 健康
  RAG 服务：能响应 ≠ 健康！它可能"流利地答错"（无声故障三兄弟）：
    · 知识过期（day23 剧本）
    · 检索悄悄劣化（新文档切坏了/嵌入模型悄悄换了）
    · 生成漂移（有人改了 Prompt 没跑回归）
  所以 RAG 日报 = 传统指标 + 质量指标 一起看。

《RAG 日报六指标》（M13 day26 日报的 RAG 扩展版）：
  传统侧：成功率 / P95 延迟 / 日成本（三数）
  质量侧（RAG 特有）：
    ④ 拒答率：拒答占比——突然升高=检索坏了或知识库缺内容（Signal！）
    ⑤ 缓存命中率：跌了=问题分布变了/缓存坑触发了
    ⑥ 每周质量抽查：30 条考卷跑四指标（周报，防无声劣化）
  红灯线：拒答率 >30% 红（正常 10~20%）| P95 >8s 红 |
          命中率跌破基线一半红 | 周抽检 Faithfulness <0.85 红

压测思路（M13 day27 的延续，RAG 版三处不同）：
  ① 分段压：检索段（毫秒级，瓶颈在 DB）和生成段（秒级，瓶颈在
     Ollama 算力）分开压——混在一起压不出结论
  ② 缓存开关对照组：开缓存压一轮（真实生产画像）+关缓存压一轮
     （最坏情况容量线）
  ③ TTFT 仍是体感核心（day18 延迟拆解的并发版）
```

### 3.2 分段压测（三组实验）

```powershell
# 组① 检索段单压：只调 Retriever（绕过生成），1/8/32 并发
#   预期：PGVector 毫秒级，瓶颈出现在 DB 连接池（连接数配置！）
# 组② 生成段单压：固定检索结果，只调 Ollama，1/2/4/8 并发
#   预期：本地 7b 天花板 2~4 路（M13 day27 的数字复现）
# 组③ 全链路压：开缓存 vs 关缓存各压一轮
#   开缓存：命中率 ~60% → 等效吞吐放大（命中请求不吃算力）

```

## 4. 面试连接

**Q：RAG 服务上线后怎么监控？压测怎么做？（生产化收口题）**
> RAG 监控的特殊性在于"能响应不等于健康"——它会流利地答错。所以我的日报是传统加质量两组指标。传统侧：成功率、P95 延迟、日成本三数。质量侧三个 RAG 特有信号：拒答率，突然升高说明检索坏了或知识库缺内容，是最灵敏的异动信号；缓存命中率，跌了说明用户问题分布变了；每周质量抽检，三十条考卷跑四指标，专门防无声劣化——知识过期、检索悄悄变差、生成漂移这三兄弟都不报错，只有定期抽检能捉住。我们还做过一次无声劣化演习：故意把检索候选集改小，日报的拒答率红线当晚就亮了——证明监控不是摆设。压测上我坚持分段：检索段毫秒级瓶颈在数据库连接池，生成段秒级瓶颈在算力，混在一起压不出结论；同时开关缓存各压一轮，开缓存是生产画像，关缓存是最坏容量线。结论落到容量数字：天花板乘零点七定限流线，超出排队或拒掉。这套东西的哲学和 M6 稳定性一脉相承——只是指标从延迟错误率换成了质量四指标，多了拒答率这个 AI 特有的信号灯。
