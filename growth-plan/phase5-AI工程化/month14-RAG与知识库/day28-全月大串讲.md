## 1. 四周主线（先讲人话）

```
W1 世界观（day01~07）：RAG = 给大模型发一本"只属于你的教材"
  开卷考试类比贯穿全月。三笔账（窗口装不下/API 成本差百倍/中间会遗忘）
  证明私有知识场景 RAG 是首选。Embedding=文字变坐标（意思近坐标近，
  两大软肋：否定词/专有名词）。30 行 MiniVectorStore 戳穿原理 →
  PGVector 上生产线。切分=做卡片盒（每块独立可读）。
  最小 RAG 跑通 + 有据生成三板斧（Grounding/引用溯源/拒答）。

W2 检索进阶（day08~14）：先有考卷，再谈优化（对拍方法论第六次上场）
  一条优化台账讲完全周：
    v0 纯向量（MRR 0.42）→ BM25 单路 → RRF 融合（比名次不比分数）
    → Rerank 精排（海选 20 精评 5）→ 父子块（子块检索取爹重排）
    → MRR 0.71
  每一步都是"先量后改、改完对拍"——检索优化不是玄学，是工程。

W3 工程化（day15~21）：实验件 → 工程件（项目四上线）
  复用 W2 成品检索器 + 接入 M13 意图分类器 + Spring 分层。
  入库五步一事务（幂等三保险）/ 查询八步编排 + SSE 三帧流式
  / 引用宁缺毋假（代码校验说了算）/ 权限检索前过滤（默认拒绝）。

W4 生产化（day22~27）：能跑 → 能管
  RAGAS 四指标（质量看得见）/ 更新链路（无声过期三道防线）
  / 成本账 ¥0.0092/次 + QA 缓存三坑 / 意图路由门卫
  / 日报六指标（拒答率是最灵敏信号）/ 三预案真点火（第三季，
  还真挖出一个缓存联动 bug）。
```

## 4. 电梯演讲（两版）

```
【对老板版 · 30 秒】
咱们的客服文档有几千页，用户问题五花八门。让 AI 裸答会编造，
让人工翻文档太慢。我们给 AI 配了一个"自动查资料"的系统：先从
文档里找出最相关的三段，再让它照着这三段回答，答案必须标"出自
哪一段"。现在一问一答成本不到一分钱，答不出自动转人工不硬编，
答案能溯源——用户能查、审计也能查。

【对面试官版 · 30 秒】
架构一句话：双路检索（向量+BM25）→ RRF 融合 → Rerank 精排 →
父子块补上下文 → 有据生成（引用+拒答）→ QA 缓存。质量用两条
考卷双卡：检索评测集看 HitRate/MRR，周抽检跑 RAGAS 四指标。
工程上：入库幂等三保险、权限检索前过滤、客户端安全带五件套、
三预案真点火（挖出过缓存联动 bug）。容量结论：安全并发 __ 路，
单次成本 ¥0.0092，P95 __ s。
```
