# Day 09 · 混合检索 BM25：给向量请个老搭档

> **今日目标**：搞懂 BM25（关键词检索打分算法）和向量的互补关系——向量认意思不认字，BM25 认字不认意思，双路并行互为兜底；用评测集实测两路各自在哪些题型上翻车。
> **时长**：概念 1h / 双路对比实验 2h / 输出 0.5h
> **今日产出**：简易关键词打分器 + 双路对比成绩单（消融实验第一枪）
> **对照教程**：`ai-learning/04-RAG检索增强.md` 第 4 节

## 1. 知识地图（先讲人话）

```
day02 留的伏笔今天兑现：向量对"专有名词"不敏感——
  它认意思不认字面，"max_tokens"和"MAX_TOKENS_LIMIT"意思近但字面全不同；
  反过来很多场景恰恰要"认字"：
  · 产品型号：问"XR-500Pro 怎么重置"——要精确命中含这个型号的块
  · 人名/错误码：问"ORDER_4021 报错"——字面就是唯一线索
  · 缩写黑话：公司内部术语"SOP-07"，向量可能把它揉进"流程"的语义里

BM25 = 30 年功力的关键词打分算法（Elasticsearch/MySQL 全文索引的内核）
  大白话版打分逻辑（先懂思想，公式不用背）：
  ① 这块里"查询词"出现越多 → 分越高（词频）
  ② 但常见词（的/是/怎么办）要打折——稀有词才值钱（逆文档频率）
     类比：图书管理员找书——"计算机"这种词哪家书架都有不算线索，
     "章鱼烧"这种词出现就基本锁定了
  ③ 太长的块要惩罚（长块天然词多，不是真相关）

双路并行的互补关系（今天的核心认知）：
           |  换说法题 |  术语/型号题 |  否定题
  向量路    |   强 ✓    |    弱 ✗     |   弱 ✗（day02 实测）
  BM25 路   |   弱 ✗    |    强 ✓     |   强 ✓（"不"字是实打实的字符）
  → 各自的软肋正好是对方的长处——所以生产检索都是双路并行
  （教程 Level 2 配置：向量 + 关键词路 + 融合 + 元数据过滤）
```

## 2. 核心概念（中英对照+大白话）

| 英文 | 中文 | 大白话解释 |
|------|------|-----------|
| BM25 | 关键词打分算法 | 词频×稀有度×长度惩罚（ES 内核，30 年老将） |
| TF (Term Frequency) | 词频 | 查询词在这块里出现几次（多=相关信号） |
| IDF (Inverse Document Freq) | 逆文档频率 | 越稀有的词越值钱（"章鱼烧">"计算机"） |
| Hybrid Retrieval | 混合检索 | 向量路+关键词路并行再融合（day10 融合） |
| Full-text Search | 全文索引 | MySQL/ES 的关键词检索能力（BM25 变体） |
| Tokenization | 分词 | 中文要先切词再匹配（老朋友：M10 Hive/ES 的分词器） |

## 3. 动手实操：双路对比实验

### 3.1 写个迷你 BM25（50 行内，体会思想）

```java
// MiniBM25.java —— 思想演示版（生产用 ES/PG 全文索引，不自己造）
// 打分 = Σ(词频 × IDF) × 长度惩罚
// ① 把每块分词（中文按 jieba 式工具或简单 2-gram 切）
// ② 建"词→块列表"倒排索引（哪块含哪个词——M10 倒排索引的复习！）
// ③ 查询：切词 → 每个词找含它的块 → 按 BM25 公式打分排序
// 数据量小（<几千块），这个迷你版完全够今天的实验
```

```
复习钩子（跨月联动）：倒排索引 = M10 Elasticsearch 章的老朋友——
  "词 → 文档列表"的目录。BM25 就是给这个目录配的打分规则。
  大数据月学的知识在 AI 月接上了——跨月同构又一例。
```

```
《双路对比成绩单》（填实测，典型分布）：
  问题类型 | 向量路 Hit | BM25 路 Hit | 结论
  直问     |   高 ✓     |    高 ✓     | 都行
  换说法   |   中       |    低 ✗     | 向量赢（意思近）

  否定     |   低 ✗     |    中       | BM25 略赢（"不"是字符）

```

## 4. 面试连接

**Q：为什么 RAG 要混合检索？只用向量不行吗？（W2 必考题）**
> 不行，向量有明确的死穴。它认意思不认字面，对专有名词、产品型号、错误码、内部缩写这类"字面即唯一线索"的查询很弱——问 XR-500Pro 怎么重置，向量可能把所有"重置"相关的块都排前面，就是排不到含这个型号的块；否定句也是它的软肋，"支持退货"和"不支持退货"相似度能到 0.9。BM25 正好相反：词频乘逆文档频率的打分，认字不认意思，专有名词精确命中一枪一个，但换个说法就抓瞎——"怎么退货"搜不到"七天无理由"那块。我们用二十题评测集实测过双路分布：换说法类向量赢，术语类 BM25 赢，正好互补，所以生产检索必须双路并行再融合。实现上 PG 的全文索引或 ES 都行，我实验时手写过迷你 BM25，本质就是 M10 学的倒排索引加打分规则——大数据月的老知识在 AI 月直接复用。融合怎么做下一天讲，重点是认知：混合检索不是锦上添花，是互补刚需。
