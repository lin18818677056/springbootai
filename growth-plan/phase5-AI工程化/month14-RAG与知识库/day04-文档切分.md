# Day 04 · 文档切分：效果的第一决定因素

> **今日目标**：搞懂为什么说"切分决定 RAG 下限"；六种切分策略各治什么病；用同一份文档三种切法对比检索效果，亲手感受切坏的灾难现场。
> **时长**：概念 1h / 对比实验 2h / 输出 0.5h
> **今日产出**：三种切法对比实验记录 + 《切分策略选择卡》
> **对照教程**：`ai-learning/04-RAG检索增强.md` 第 3 节

## 1. 知识地图（先讲人话）

```
为什么切分是第一决定因素？——检索检的是"块"，不是"整篇文档"。
  块切坏了，后面全白搭：检索把断章取义的碎片喂给模型，
  模型照着碎片一本正经地答错（垃圾进垃圾出）。

类比：把一本书做成知识卡片盒。
  切太碎（每张卡片只有半句话）→ 检索到也看不懂说了啥
  切太大（一张卡片整章）→ 检索时"相关的和无关的"粘在一起，
    真正相关的段落被稀释，窗口还被塞满（回到 M13 day01 的全塞困境）
  好的切法 = 沿着"意思的自然边界"撕（章节/段落/话题转折处）

六种策略一张表（先记人话版，参数后调）：
  ① 固定长度+重叠：每 400 字切一刀，相邻块重叠 50 字 → 快速兜底
    （重叠 = 相邻卡片复制一小段，防止答案恰好被切在刀口上）
  ② 递归切分：先按段落切，段落太长再按句子切，句子还长按词切
    → 通用推荐（尊重自然边界，边界优先于长度）
  ③ 结构感知：按标题/章节/表格边界切 → 手册规范类首选（最尊重作者）
  ④ 父子块：小块负责"被检索准"，命中后把它爹（大块）喂给模型
    → 检索精度和上下文完整兼得（精确定位+完整语境，day13 细讲）
  ⑤ 语义切分：相邻句子向量相似度骤降处切 → 效果好成本高，二期优化
  ⑥ 表格特殊处理：整表转 Markdown 成一块 + 行级补充 → 参数表价格表

验收标准一句话（今天最重要的输出）：
  每一块独立可读——不看上下文，也知道这块在说什么。
```

## 2. 核心概念（中英对照+大白话）

| 英文 | 中文 | 大白话解释 |
|------|------|-----------|
| Chunking | 切分 | 文档→小块（知识卡片） |
| Chunk Size | 块大小 | 每块多少 token（300~500 起步） |
| Overlap | 重叠 | 相邻块复制的部分（10~20%，防刀口切断答案） |
| Recursive Splitting | 递归切分 | 段落→句子→词逐级降级（边界优先） |
| Structure-aware | 结构感知 | 按标题/表格边界切（尊重文档结构） |
| Parent-Child | 父子块 | 子块检索、父块喂模型（两全法） |

## 3. 动手实操：一份文档三种切法对比

### 3.1 准备实验材料

```
test-doc.txt：自己写一篇 800 字《客服退款政策》，
  必须包含三个特点（模拟真实文档）：
  ① 一个 7 天无理由规则的完整段落（答案候选①）
  ② 一句横跨两段的完整规则："退款将在 3~5 个工作日
     （切到下一段）原路返回。"（故意让答案跨段——刀口实验）
  ③ 一张 3 行的运费表（表格实验）
```

### 3.2 三种切法分别入库+检索对比

```powershell
# 流程：每种切法 → 每块调 /api/embeddings → 存进 day03 的存储
# → 用三个问题检索："7天无理由怎么算""退款多久到账""运费谁出"
# → 记录每次检索 Top1 是不是正确的块

切法A：固定 100 字硬切（故意切坏）
切法B：递归切分（段落优先，超长降级到句子，overlap 50 字）
切法C：结构感知（按标题切）
```

```
《对比实验记录表》（填实测）：
  问题                | 切法A Top1        | 切法B Top1      | 切法C Top1
  7天无理由怎么算      | 断章碎片 ✗        | 完整段 ✓        | 完整段 ✓
  退款多久到账        | "原路返回"被切两半 | 靠 overlap 拼回 | 完整段 ✓
  运费谁出            | 表格被撕碎 ✗      | 碎片 ✗          | 整表一块 ✓
结论预告：切法A 检索分数看起来不低但块不可读 → 生成环节必然胡说
  （这就是"切分决定下限"的现场证据）
```

### 3.3 《切分策略选择卡》（抄作业卡）

```
拿到一份文档，四问定切法：
  ① 是手册/规范/有标题结构吗？→ 结构感知（首选）
  ② 是纯散文/聊天记录/无结构？→ 递归切分（300~500T，重叠 10~20%）
  ③ 有参数表/价格表吗？→ 整表 Markdown 一块+行级补充
  ④ 检索总是"找到了但答不全"？→ 上父子块（day13）
□ 抽查纪律：随机抽 10 块，每块默读一遍——读不通的块=垃圾，
  回去调切法（这条比任何参数都灵）
```

## 4. 面试连接

**Q：RAG 效果不好，你从哪开始优化？（M14 的"系统题"，答案是先切分）**
> 我的排查顺序是数据看两头，先切分再检索再生成。切分是下限：块切得稀碎，比如固定一百字硬切，会把"退款三到五个工作日原路返回"从中间切断，检索回来的块断章取义，生成必然胡说——我们做过对比实验，同一份文档三种切法，硬切的检索分数看着不低但块不可读，答案全错；递归切分加重叠就稳了。我的切分验收标准是一句话：每块独立可读，随机抽查十块，读不通就回去重切。策略选择上手册规范类用结构感知，按标题章节切；无结构文本用递归切分三百到五百 token 重叠一成；表格整块转 Markdown；检索准但答不全再上父子块——小块定位准，大块语境全。很多团队效果差第一反应是换模型，其实八成是切分和检索的问题——模型只决定上限，切分才决定下限。
