> **主参考**：`ai-learning/04-RAG检索增强.md`（本月的"教材"，README 和各 day 反复引用）

## 一、本月目标（说完人话再说术语）

```
M13 结尾我们留了个悬念：模型会胡说，防线之一是"把对的资料喂给它"。
本月就把这件事做透——RAG（Retrieval-Augmented Generation，检索增强生成）：

类比：开卷考试。
  M13 的模型 = 闭卷考生（只靠脑子里训练时背的，过时的、私有的都不会）
  RAG      = 开卷考生（先翻书找到相关段落，再照着书写答案，还能标注"出自第几页"）

四个硬指标（月底逐条验收）：
  ① 答案有据：每句话能溯源到知识库的哪篇文档哪一段
  ② 检索要准：该找到的资料找得到（不是"搜到了但排最后"）
  ③ 知识能更新：文档改了，答案跟着变（没有更新链路的 RAG 一上线就过期）
  ④ 权限不越界：你无权的文档，问破天也检索不到
```

## 六、本月心法

```
RAG 的三句大白话（面试和实操都靠它们定调）：
  ① 切分决定下限：切得稀碎，模型再强也答不对（垃圾进垃圾出）
  ② 检索决定上限：找不齐资料，模型只能编（先有尺子再优化）
  ③ 工程闭环比模型效果更难：更新链路/评估体系/权限过滤——demo 一天，
     生产三个月。这也是为什么企业级 RAG 是架构师活，不是调参侠活。
```
