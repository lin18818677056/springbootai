# Day 08 · 检索评测先行：先有尺子，再谈优化

> **今日目标**：W2 开门第一件事不是调优，是建尺子——对拍方法论第六次上场；搭好检索评测集（20 题）和两个检索指标，让 W2 后面每一步优化都有数字证据。
> **时长**：评测集 2h / 脚本 1.5h / 输出 0.5h
> **今日产出**：检索评测集 v1（20 题）+ `eval_retrieval.ps1` + v0 检索基线分数
> **对照教程**：`ai-learning/04-RAG检索增强.md` 第 5 节

## 1. 知识地图（先讲人话）

```
为什么优化前先建尺子？
  反面教材：凭感觉调——改了 chunk_size 觉得"好像好点了"，
  换个问法又觉得"好像差了"——感觉会被新鲜感骗（ placebo 效应在调参界
  一样灵验）。没有尺子的优化 = 玄学，面试时说"感觉变好了"=减分。

对拍方法论第六次上场（这条线是你的面试杀手锏，续上）：
  M8 离实对拍（MySQL 替换 Redis 验证）→ M10 Hive vs MySQL
  → M11 Spark 对照 → M12 Flink 双引擎 → M13 AI 评测 50 条
  → M14 检索评测：同一个思想——先定义"标准答案"，再让系统答题打分

检索评测和 M13 生成评测的区别（今天容易混，先分清）：
  M13 测的是"答案对不对"（生成质量）
  今天测的是"资料找没找对"（检索质量）——不含模型，纯看检索环节
  为什么要分开？——错要错得明白：答案错可能是检索没找到（检索的锅），
  也可能找到了没答好（生成的锅）。分开测才能定位到环节（教程第 7 节
  "数据看两头"的实操基础）。

两个指标（检索界的"体温计"）：
  Hit Rate 命中率：Top-K 里有没有正确块（有=1 无=0，最粗但最直观）
  MRR 平均倒数排名：找对了但排第几？（第 1 名=1 分，第 2 名=0.5……）
    —— 大白话：命中率管"找没找到"，MRR 管"找得靠不靠前"
```

## 2. 核心概念（中英对照+大白话）

| 英文 | 中文 | 大白话解释 |
|------|------|-----------|
| Golden Set | 黄金评测集 | 带标准答案的考卷（这里=问题+正确的块） |
| Hit Rate @K | K 命中率 | 正确块出现在 Top-K 里的比例 |
| MRR (Mean Reciprocal Rank) | 平均倒数排名 | 找到时平均排多前（排名越前分越高） |
| Context Recall | 上下文召回 | 该找到的资料都找到了吗（RAGAS 四指标之一） |
| Baseline | 基线 | 优化前的分数存档（没基线=没法证明优化了） |
| Ablation | 消融实验 | 逐个加/减组件看分数变化（证明每个组件的功劳） |

## 3. 动手实操

### 3.1 建检索评测集 v1（20 题，格式是关键）

```
eval-retrieval.tsv，每行三列（TAB 分隔）：
  问题 <TAB> 正确块的 doc_id:chunk_id <TAB> 问题类型
  怎么退货          <TAB> refund-faq:3        <TAB> 换说法
  退款多久到账      <TAB> refund-faq:5        <TAB> 直问
  7天无理由怎么算    <TAB> refund-faq:3        <TAB> 术语
  运费谁出          <TAB> shipping:1          <TAB> 直问
  ...(20 条：直问 6 / 换说法 6 / 术语 4 / 否定 2 / 库外 2)
出题技巧（考卷质量决定尺子质量）：
  · 换说法题：故意用和原文不同的词问（考病①）
  · 否定题：问"不支持XX的场景"（day02 否定词软肋的实战版）
  · 库外题：知识库里没有的问题（考拒答/考"不知道"）——它不算命中率，
    单独统计"库外乱答率"（应该为 0）
```

### 3.2 评测脚本骨架

```powershell
# eval_retrieval.ps1 —— 跑一遍考卷，出两个分数
$hit = 0; $rrSum = 0; $n = 0
Get-Content eval-retrieval.tsv | ForEach-Object {
    $f = $_ -split "`t"
    $qv = (嵌入 $f[0])                          # 问题变坐标
    $top5 = (PGVector 最近 5 块)                # 取 Top5
    $rank = 在 $top5 里找 $f[1] 的名次          # 1~5，没找到=0
    if ($rank -ge 1) { $hit++; $rrSum += (1.0 / $rank) }
    $n++
}
"HitRate@5 = $([math]::Round($hit/$n*100,1))%"
"MRR       = $([math]::Round($rrSum/$n,3))"
# 把分数存 baseline-w2.txt——下周每项优化前先看它
```

### 3.3 拿 v0 测出基线（今天的仪式感）

```
跑 eval_retrieval.ps1，预期（朴素 v0 的典型成绩）：
  HitRate@5 ≈ 60~75%（换说法题大面积丢分——病①的量化证据）
  MRR ≈ 0.5 上下（找到了也常排第 3、4 位——病②的证据）
  库外乱答率 = 记下来（day06 拒答策略后应为 0）
→ 把三组数按问题类型拆开（直问/换说法/术语/否定）——
  弱项分布就是你 W2 的优化路线图：
  换说法丢分多 → day11 查询改写优先；术语丢分多 → day09 BM25 优先
```

## 4. 面试连接

**Q：RAG 优化你怎么证明有效？（工程严谨性必考）**
> 先有尺子再优化。我建了检索评测集，二十道题带标准出处，覆盖直问、换说法、术语、否定和库外五种类型；两个指标，HitRate 看找没找到，MRR 看找得靠不靠前，库外题单独统计乱答率必须为零。用这套尺子给朴素版测出基线：命中率七成左右，换说法类丢分最狠。后面每个优化都做消融——只加一个组件重跑同一套考卷，分数涨了才算数：混合检索治术语类，查询改写治换说法类，重排抬 MRR。生成和检索分开测，答案错能定位是没找到还是没答好。这套东西本质是对拍方法论——我做的每个系统优化都坚持同一套流程：先定义标准答案和指标，测基线，逐项消融，用数字说话。RAG 最大的坑就是把 demo 当产品，没有评估体系的 RAG 优化全靠感觉，跟没测压测就说性能好一样不可信。
