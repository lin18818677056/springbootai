# Day 10 · RRF 融合：两个评委的名次合并术

> **今日目标**：解决"双路结果怎么合并"——RRF（倒数排名融合）；理解为什么不比分数比名次；用 RRF 合并双路跑评测集，完成消融实验第二枪。
> **时长**：概念 1h / 融合实操 2h / 输出 0.5h
> **今日产出**：RRF 融合器（30 行内）+ 融合后成绩单 + 《优化台账》第二行
> **对照教程**：`ai-learning/04-RAG检索增强.md` 第 4 节 RRF

## 1. 知识地图（先讲人话）

```
昨天的双路结果长这样：
  向量路 Top5：块A(0.82) 块B(0.79) 块C(0.71) ...
  BM25 路 Top5：块D(15.2) 块A(12.8) 块E(9.1) ...
  问题来了：怎么合成一个总榜？
  块A 向量 0.82、BM25 15.2——这俩数能直接加吗？
  不能！量纲不同：余弦是 0~1，BM25 是 0~几十。
  直接加权 = 拿"温度"和"体重"加一起算健康分——荒谬。

RRF 的聪明之处：不比分数，比名次。
  大白话：每个评委报名次，名次靠前的加分，两榜相加定总分。
  公式人话版：某块的 RRF 得分 = Σ 各路给的 1/(k+名次)，k 常取 60
    · 向量路第 1 名 → 1/61；BM25 路第 2 名 → 1/62
    · 块A = 1/61 + 1/62 = 0.0326（两路都认可 → 高分）
    · 块D = 0 + 1/61 = 0.0164（只有一路认可 → 低一半）
  为什么 k=60？——压平名次差距：让"第 1 名"别比"第 3 名"高太多，
  避免某一路的头名碾压一切（60 是经验值，不用纠结）

类比：两家美食排行榜合成总榜。
  大众点评榜第 1 + 米其林榜第 3 的店 > 只上单一榜单第 1 的店
  —— 两边都说好才是真的好（共识加权）

融合后成绩单预期（消融第二枪）：
  融合榜 = 两路长处叠加：换说法题靠向量路抬进来，
  术语题靠 BM25 路抬进来 → HitRate 应显著超过任何单路
```

## 2. 核心概念（中英对照+大白话）

| 英文 | 中文 | 大白话解释 |
|------|------|-----------|
| RRF (Reciprocal Rank Fusion) | 倒数排名融合 | 按名次给分合成总榜（不管原始分数） |
| Rank Fusion | 名次融合 | RRF 的统称思想 |
| Scale Mismatch | 量纲不一致 | 0~1 的分和 0~几十的分不能直接加 |
| Consensus | 共识加权 | 多路都认可的块分高（两边都说好） |
| k (常取 60) | 平滑常数 | 压平名次差距的经验值 |
| Ablation Study | 消融实验 | 逐项加组件看涨分（优化台账的记账法） |

```java
// score(chunk) = Σ 1/(60 + rank_i)，rank 从 1 数
// 步骤：
// ① 每路结果按名次给分：1/(60+1), 1/(60+2)...
// ② 同一块在两路都出现 → 分数相加（共识信号）
```


## 4. 面试连接

**Q：双路检索的结果怎么融合？为什么用 RRF？（检索融合标准题）**
> 关键认知是两路的分数量纲不同不能直接加——余弦是 0 到 1，BM25 是 0 到几十，直接加权等于拿温度加体重。RRF 的解法是只报名次不报分数：每个块在各路的得分是一除以六十加名次，两路同现就加总，共识块自然浮到顶部。k 取 60 是经验值，作用是压平名次差距，防止单路头名碾压。我实测过融合收益：二十题评测集上，纯向量命中率七成，融合后到八成五左右，换说法和术语两类同时改善——因为每类的强路把对方漏掉的块抬进来了。工程细节两个：融合前每路放宽取 Top20 给对方长处留名额，融合后再截 Top5；某一路故障时降级单路跑，可用性优先，fallback 计数进监控。为什么不训练融合权重——中小知识库样本少容易过拟合，RRF 零参数免训练，先把简单的用到极致，效果不够再上学习型方案。这个思路和我做技术选型一脉相承：能简单就别复杂，每个组件都要用数据证明它值得存在。
