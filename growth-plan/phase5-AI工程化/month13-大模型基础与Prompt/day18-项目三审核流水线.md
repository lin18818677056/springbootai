## 1. 实现设计（先讲人话：为什么要有审核层）

```
分类器的盲区：它只会分"是什么类"，不会判断"危不危险"
  "再不退款我就去投诉你们到倒闭！" → 分类器：refund/high ✓
  但这条要不要"特殊照顾"（安抚话术/上报主管/防升级）？——需要第二双眼

审核流水线设计（级联第二级）：
  分类器输出 need_human=false 且 category≠unknown 的工单
      ↓ 触发条件（规则先行，别什么都问模型——便宜手段优先）
  高风险特征：金额 ≥500 元的退款 / 情绪激烈词（投诉/曝光/工商/315）
      ↓
  二级审核 Prompt（模板⑧）：
    Role: 你是售后风险审核专员
    Task: 复查工单风险等级（high/medium/low）+ 给处理建议（≤80 字）
    Constraint: 只评估风险不执行任何动作；建议必须合规（不承诺赔偿金额）
    输出 Schema: {"risk":"...","suggestion":"...","violations":[...]}
      ↓
  路由三岔口：
    risk=low   → 自动生成回复草稿（进客服工作台，人点发送）
    risk=medium → 回复草稿+标记"建议主管复核"
    risk=high  → 直接进人工队列（AI 不碰）+ 告警

降级设计（M6 稳定性思想的平移——超时/重试/降级三件套）：
  审核调用超时（>10s）→ 该单直接进人工队列（宁慢勿错）
  模型连续失败 2 次 → 熔断 5 分钟：期间全部工单走人工队列，
  并发告警（模型挂了不能拖垮整个客服系统——故障隔离）
  —— 和 Flink 的"上游挂了别瞎重启作业"同一哲学：快速失败+隔离爆炸半径
```

## 2. 核心概念（中英对照+大白话）

| 英文 | 中文 | 大白话解释 |
|------|------|-----------|
| Secondary Review | 二级审核 | 级联第二级：专查高风险的"复核岗" |
| Rule-first Routing | 规则先行路由 | 能用规则判断的别问模型（省钱+稳定） |
| Circuit Breaker | 熔断 | 模型连挂就停用一段时间，全量走人工 |
| Graceful Degradation | 优雅降级 | AI 挂了系统还能转（人工队列兜底） |
| Blast Radius | 爆炸半径 | 模型故障波及范围——被熔断机制压到最小 |
| Suggestion Draft | 建议草稿 | AI 写的回复稿——发送权永远在人 |

## 3. 动手实操：造零件+降级演练+串联

### 3.1 步骤①：实现审核流水线

```
伪代码骨架：
  def review(ticket, cls_result):
      if cls_result.need_human or cls_result.category == "unknown":
          return route_to_human(ticket)          # 分类器已认怂 → 直送人工
      if not is_high_risk(ticket.text):          # 规则先行：不是高风险不劳烦模型
          return draft_reply(ticket, cls_result)
      try:
          audit = llm_call(模板⑧, ticket, timeout=10)   # 二级审核
          validate(audit)                                 # 防御链（day10 原样复用）
          return route_by_risk(audit)
      except Timeout:
          metrics.inc("audit_timeout")
          return route_to_human(ticket)          # 超时 → 人工兜底
  熔断器：连续失败 2 次 → open 5 分钟 → half-open 试探 1 次 → 恢复或继续 open
```

## 4. 面试连接

**Q：你的审核流水线怎么设计的？模型挂了怎么办？（稳定性+架构题）**
> 设计上三个要点。规则先行：高风险特征（大额退款、激烈情绪词）先用规则筛，只有命中的才调模型复查——大部分工单根本不用花这个钱，便宜手段优先。级联分工：分类器管"是什么"，审核层管"危不危险"，职责分离各自评测。路由三岔口：低风险出回复草稿、中风险加主管复核标记、高风险直接人工队列——AI 全程只有建议权，发送权和赔付权永远在人。稳定性上平移了我做微服务时的三件套：超时 10 秒——超时的单宁慢勿错直接转人工；熔断——模型连续失败 2 次就 open 5 分钟，期间全量走人工队列，half-open 探活恢复；降级演练真做过——把模型端点改成假地址，验证了熔断开启期间用户无感知、恢复后自动闭合。核心哲学和我在流处理里的一致：故障不可怕，可怕的是爆炸半径失控和静默丢失——我的系统里每张工单都有明确归宿，没有黑洞单。
