# Day 10 · 结构化输出：让模型吐机器可读的结果

> **今日目标**：掌握结构化输出三板斧（Prompt 约束/JSON 模式/Schema 约束）；建立"解析失败"的完整防御链（重试/修复/兜底）——这是 AI 应用从"玩具"变"工程"的分水岭。
> **时长**：概念 1h / 实操 2h / 输出 0.5h
> **今日产出**：三板斧对照实验 + 《结构化输出防御链》
> **对照教程**：`ai-learning/02-Prompt工程.md`（结构化部分）

## 1. 知识地图（先讲人话）

```
为什么结构化输出是分水岭？
  给人看的回答：错别字/啰嗦都无所谓，人脑自动纠错
  给程序看的回答：多一个逗号、少一个引号 → JSON 解析直接炸
  —— AI 应用 = 模型输出 + 程序消费；程序消费的第一道门就是解析
  —— 所以"让模型稳定吐合法 JSON"是 AI 工程的必修课

三板斧（从便宜到贵，逐级升级——day04 的工程纪律再现）：

  板斧① Prompt 约束（零成本，靠"嘴遁"）
    在 Prompt 里给出格式模板+要求"只输出 JSON，不要任何解释"
    + few-shot 给个例子（day12 的姿势）
    可靠性：~90%，够 demos，不够生产

  板斧② JSON 模式（厂商保证，语法合法）
    请求里开 "response_format": {"type": "json_object"}
    模型保证输出语法上合法的 JSON（引号/括号闭合）
    但不保证字段对/值对——"合法"≠"符合你的 Schema"

  板斧③ Schema/结构化输出模式（最强，字段级保证）
    直接传 JSON Schema（字段名/类型/枚举值全约束）
    模型被约束在 Schema 里生成——字段名拼错都不可能
    注意：各家支持度不同（协议覆盖面——day08 选型指标之一）

解析失败的防御链（生产必配，四道）：
  ① 校验：JSON 解析 + 字段校验（类型/必填/枚举）——Jackson 一把梭
  ② 修复：轻度损坏自动修（尾部多余逗号/markdown 代码围栏剥离）
  ③ 重试：把错误信息喂回去让模型自己改（"你上次的输出缺 type 字段，修正"）
     —— 重试要带上限（比如 2 次），防止无限循环烧钱
  ④ 兜底：重试用尽 → 降级路径（默认值/规则引擎/转人工）
```

## 2. 核心概念（中英对照+大白话）

| 英文 | 中文 | 大白话解释 |
|------|------|-----------|
| Structured Output | 结构化输出 | 让模型输出 JSON/XML 等程序可读格式 |
| response_format | 响应格式参数 | 开 JSON 模式的开关（板斧②） |
| JSON Schema | JSON 模式定义 | 字段名/类型/枚举的"合同"（板斧③） |
| Validation | 校验 | 解析后检查字段类型/必填/取值范围 |
| Retry with Feedback | 带反馈重试 | 把报错喂回模型让它自己修 |
| Fallback | 兜底 | 重试用尽后的降级路径（永远要有） |

## 3. 动手实操：三板斧+防御链全链路

### 3.1 实验①：板斧①的 10% 翻车现场

```
Prompt："分析这条客服工单，输出 JSON：{\"category\":\"...\",\"priority\":\"高/中/低\"}。
        工单：〈粘贴一条工单〉只输出 JSON。"
连跑 10 次（temperature 0.3），逐条用 PowerShell ConvertFrom-Json 试解析：
  预期：8~9 次成功；翻车模式通常是——
    "好的，以下是 JSON："（带了废话前缀）
    ```json 围栏（markdown 格式）
    尾巴加了解释
—— 把翻车样本存下来（防御链实验的素材）
```

### 3.2 实验②：板斧②③升级对比

```powershell
# 板斧②：请求体加 "response_format": {"type": "json_object"}
# （Ollama 支持 format: "json"；OpenAI 兼容协议各家字段略有差异——查文档）
# 重跑 10 次 → 语法全部合法；但检查字段名：category 还是 cate？字段可能漂
# 板斧③：能传 schema 的厂商跑同样实验 → 字段级稳定
# 记录三行结论：板斧① 语法偶炸 / 板斧② 语法稳字段漂 / 板斧③ 全稳
```

### 3.3 实验③：防御链四道全走一遍（今天的重头戏）

```
用实验①的翻车样本走防御链：
  ① 校验：ConvertFrom-Json 失败 → 计数；成功但缺字段 → 计数（两类失败分开统计！）
  ② 修复：写 3 行清洗函数——剥离 ``` 围栏、截取第一个 { 到最后一个 } 之间、
     去尾部逗号 → 再解析
  ③ 重试：仍失败的，构造新请求："你上次输出：〈原文〉。错误：JSON 解析失败，原因...。
     请只输出修正后的 JSON"（带上限 2 次）
  ④ 兜底：重试用尽 → 返回默认分类+标记"转人工"
记录：10 条样本最终成功率 = ___%（防御链的价值：从 ~90% → ~100%）
```

## 4. 面试连接

**Q：怎么让大模型稳定输出结构化数据？（AI 工程必考实操题）**
> 三板斧从便宜到贵逐级上。第一级 Prompt 约束：给格式模板加 few-shot 示例，可靠性九成左右，翻车模式主要是带废话前缀和 markdown 围栏——demo 够用。第二级 JSON 模式：开 response_format 的 json_object，厂商保证语法合法，但字段名仍可能漂移——"合法"不等于"符合我的 Schema"。第三级 Schema 约束：直接传 JSON Schema，字段名类型枚举全部锁死，这是生产首选，但要检查各家协议支持度。无论用哪级，防御链必须配齐四道：解析加字段校验、轻量修复（去围栏截取）、带反馈重试（把报错喂回去，上限两次防循环烧钱）、最终兜底（默认值或转人工）并记录失败样本回炉评测集。我实验里同样 10 条样本，裸 Prompt 成功率九成，防御链兜完接近全量——差的这一成就是线上事故率。

**Q：模型输出的 JSON 解析失败，线上怎么处理？（追问，考生产思维）**
> 分即时处理和长期治理。即时：防御链自动走——修复、重试、兜底，用户无感；同时把失败样本落库。长期：失败样本是金矿——它们暴露了 Prompt 的边界情况，每周回炉：加 few-shot 示例、收紧 Schema、或升级板斧等级；另外监控两个分离的失败率——语法失败率（该升级 JSON 模式）和字段校验失败率（该收紧 Schema），两者病因不同，混在一起治会开错药。这和我在数据链路里的对拍思想一致：失败不是噪声，是免费的测试用例。
