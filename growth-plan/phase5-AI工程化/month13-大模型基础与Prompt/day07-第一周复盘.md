```

第 4 站【day04 训练三部曲】：上学/岗培/带教

  → 纪律：参数管过程不管对错；只调一个旋钮
第 6 站【day06 幻觉】：天性不是 bug
  → 三高发场景+知识截止；四道防线（溯源/注入/校验/兜底）
```

## 3. 《评测量表 v0》（W2-W3 每个项目都要用的"打分尺"）

```
对模型输出打分，从"感觉不错"升级为"可量化"：
  维度① 正确性：事实/逻辑对不对（0/1/2：错/部分对/对）
  维度② 完整性：要求覆盖的点都覆盖了吗（漏点清单）
  维度③ 格式：结构化要求（JSON/字数/格式）达标吗（能被程序解析=硬门槛）
  维度④ 安全：有没有幻觉/越界/敏感内容（一票否决项）
打分姿势：每题写"评分+扣分原因"——原因比分数重要（和 code review 一个道理）
day19 起升级为正式评测集（50 条）+盲评流程
```

## 4. 面试连接

**Q：你们团队怎么判断大模型应用的效果好坏？（W1 收束题，考方法论）**
> 核心是把"感觉不错"变成可量化的评测体系，我分三层。第一层评什么：四个维度——正确性、完整性、格式达标、安全合规，其中格式是硬门槛（JSON 解析不过直接判 0），安全是一票否决。第二层怎么评：建业务评测集（真实样本 50 条起步），固定 temperature 和 seed 保证可复现，盲评打分并写扣分原因——原因比分数重要。第三层怎么用：每次改 Prompt、换模型、调参数，先跑评测集再上线，看分数变化而不是看个别案例——这和我在数据链路里"实时账要拿离线真相源对拍"是同一个方法论：概率系统的输出不能靠感觉验收，要靠制度化的交叉验证。
