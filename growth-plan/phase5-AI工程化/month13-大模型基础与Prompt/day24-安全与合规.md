# Day 24 · 安全与合规：AI 应用的三道关

> **今日目标**：把 day13 的 Prompt 安全扩展成完整的 AI 安全合规视图——数据安全关（进）、内容安全关（出）、行为安全关（动作）；对照《生成式 AI 服务管理暂行办法》梳理检查清单。
> **时长**：概念 1h / 自查实操 2h / 输出 0.5h
> **今日产出**：工单系统安全合规自查表（三道关全过一遍）+ 《AI 合规红线卡》
> **对照教程**：`ai-learning/07-AI应用架构与安全.md`

## 1. 知识地图（先讲人话）

```
AI 应用 = 数据进 + 内容出 + 动作执行，三道关各管一头：

关① 数据安全（管"进"——用户数据去哪了）：
  数据出境：用户数据发境外 API = 跨境传输（红线！先问合规再接）
  数据最小化：Prompt 里只放必要的字段（别把整张用户表塞给模型）
    —— day13 的"特权最小化"的数据版
  脱敏进模：手机号/身份证先脱敏再进 Prompt（模型只需要语义，不需要真号）
  训练数据权属：用用户数据微调/评测前，查用户协议授权范围

关② 内容安全（管"出"——模型说了什么）：
  违规内容：涉政/涉暴/色情/歧视——平台责任（生成式 AI 办法明确要求）
  幻觉承诺：模型承诺"已退款/已赔付"——业务级事故（day13 防御②的扩展）
  侵权内容：生成内容抄袭/诽谤真实个人企业
  防御：输出扫描（敏感词+业务承诺模式正则）+ 人工抽检机制 + 用户举报通道

关③ 行为安全（管"动作"——模型能干什么）：
  权限最小化：模型能调的工具/接口按最小权限配（M15 Agent 时代更致命）
  高危动作人工闸：退款/改密码/发通知——程序侧二次确认（day13/18 已落）
  操作留痕：模型的每次"建议"和人的每次"采纳"都留审计日志
    —— 出事能回答"这个决定是谁做的"（AI 辅助决策的责任链）

合规基座（国内背景，工程师要知道的框架）：
  《生成式 AI 服务管理暂行办法》：备案（面向公众的服务）/ 内容标识 /
    训练数据合规 / 用户投诉机制
  《个人信息保护法》：处理个人信息需告知+授权（AI 功能也要）
  工程师落地版：三道关自查表 + "拿不准就问法务"（合规不是工程师单挑的事）
```

## 2. 核心概念（中英对照+大白话）

| 英文 | 中文 | 大白话解释 |
|------|------|-----------|
| Data Minimization | 数据最小化 | 只给模型必要字段（别整表投喂） |
| PII Masking | 个人信息脱敏 | 手机号变 138****1234 再进 Prompt |
| Content Moderation | 内容审核 | 输出的违规内容扫描（机器+人工） |
| Human Oversight | 人类监督 | 监管要求的"人在回路"（建议权红线的法理依据） |
| Audit Trail | 审计留痕 | 谁在什么时候采纳了 AI 的什么建议 |
| Filing/Registration | 备案 | 面向公众的生成式服务要向监管备案 |

## 3. 动手实操：给工单系统过三道关

### 3.1 关①自查：数据进（逐条对照）

```
工单系统数据流自查：
  □ 用户工单文本发给了谁？（本地 Ollama=不出境 ✓ / 某境外 API=红线 ✗ → 换）
  □ Prompt 里有没有非必要 PII？
    检查实测：分类器 Prompt 目前带工单全文——里面有手机号吗？
    改造：进模前正则脱敏（11 位手机号 → 138****5678），
    语义不受损（分类不需要真号），脱敏后评测集重跑验证分数不掉
  □ 评测集里的真实工单脱敏了吗？（day15 攒考卷时"脱敏改写"——现在复核一遍）
  □ 记忆摘要里会不会攒下敏感信息？（摘要存哪、存多久、谁能看——定留存策略）
```

### 3.2 关②自查：内容出

```
  □ 输出扫描规则清单：涉政敏感词表 / 业务承诺模式（已退款|已到账|已赔付）
  □ 人工抽检机制：每天随机抽 __ 条 AI 草稿人工复核（抽检率 __%）
  □ 用户侧举报/纠错入口（监管要求+真实需求）
  □ AI 生成内容标识：对外展示的 AI 回复标注"AI 助手生成"（办法要求+用户知情权）
```

### 3.3 关③自查：动作与留痕

```
  □ 模型可触达的动作清单盘点：目前只有"分类/草稿/审核意见"（全建议类 ✓）
  □ 未来加工具调用时（M15）：退款类工具永久排除在模型可达范围外（架构级红线）
  □ 审计日志：call_log 里已有模型侧留痕；补"人工采纳记录"字段
     （建议→谁采纳→改没改→最终发了什么——责任链闭环）
  □ 《AI 合规红线卡》成文：
     1. 用户数据不出境（选型 day22 合规件已一票否决境外 API）
     2. PII 进模必脱敏
     3. 模型无执行权（建议权红线）
     4. AI 内容对外必须标识
     5. 高危动作必须人工二次确认
     6. 拿不准的问法务，别自作主张
```

## 4. 面试连接

**Q：AI 应用的安全合规你们怎么做的？（架构+合规复合题）**
> 我按数据流的三道关来布防。数据进：数据不出境是选型一票否决项——境外 API 再好直接出局；PII 进模必脱敏，手机号身份证正则打码后再进 Prompt，模型只需要语义不需要真号，脱敏后评测集重跑验证业务分数不掉；数据最小化，Prompt 里只放必要字段。内容出：输出侧敏感词加业务承诺模式双扫描——尤其防模型"承诺已退款"这种业务事故；对外 AI 内容做生成标识；每天按比例人工抽检。行为上：模型全程只有建议权没有执行权，高危动作程序侧强制人工二次确认，这是架构级红线；所有建议和采纳留审计日志，责任链闭环。合规框架上对照生成式 AI 管理办法：备案、内容标识、投诉机制这些是产品侧配合的，工程师的核心是把三道关做进系统而不是写在文档里。最后一句话总结：AI 安全是系统工程，靠纵深防御，不靠单点；拿不准的合规问题必须拉法务，工程师不自作主张。
