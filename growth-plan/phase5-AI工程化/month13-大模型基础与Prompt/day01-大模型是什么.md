# Day 01 · 大模型是什么：一个"超级文字接龙"程序

> **今日目标**：用"下一个词预测"一句话讲清 LLM 本质，并亲手推出四个工程结论——这四个结论是整个 AI 工程化的地基（评测/记忆管理/RAG/知识更新全都从这里长出来）。
> **时长**：概念 1h / 实操 1h / 输出 0.5h
> **今日产出**：四个工程结论的手写推导 + 第一次模型对话记录（正/降级路径）
> **对照教程**：`ai-learning/01-大模型基础原理.md` 第 1 节

## 1. 知识地图（先讲人话）

```
大模型的本质 = 超大规模的"文字接龙"：
  输入：中国的首都是
  模型脑内概率分布：北京 89% | 上海 3% | 南京 1% | ...
  输出：按概率"抽"一个词 → 拼回输入 → 接着预测下一个词（自回归生成）
  —— 它不是在"查资料"，是在"猜下一个词"，只是猜得极其好

由本质亲手推出四个工程结论（比背原理重要一万倍）：
  ① 它是概率模型，没有确定性
     → 同一问题两次回答可能不同（采样温度控制随机度）
     → [兑现 M12 思考题②] 这和"实时账 vs 离线账"的差异同源：
       系统输出不确定 → 都必须靠"验证体系"兜底，不能靠祈祷
       （离线账=真相源兜底实时账；评测集=真相源兜底模型输出，day19 见）
  ② 它没有记忆
     → 所谓"多轮对话"，是把历史消息重新发给它
     → 上下文窗口（记忆容量）装不下的就"忘了"（day02 细讲）
  ③ 它会编造（幻觉 Hallucination）
     → 不知道时也会"顺着接"——接龙游戏的天性
     → 这就是 RAG 与引用溯源存在的理由（M14 主线的存在证明）
  ④ 知识有截止日期
     → 训练数据有时间终点，昨天发生的新闻它不知道
     → 所以生产系统不能拿模型当数据库用
```

## 2. 核心概念（中英对照+大白话）

| 英文 | 中文 | 大白话解释 |
|------|------|-----------|
| LLM (Large Language Model) | 大语言模型 | 读过整个互联网的"文字接龙冠军" |
| Inference | 推理 | 用模型生成结果的过程（"调用大模型"的学名） |
| Autoregressive | 自回归 | 一个词一个词往外蹦，每个词都基于前面已生成的内容 |
| Sampling | 采样 | 从概率分布里"抽签"选下一个词 |
| Temperature | 温度 | 抽签的"手抖程度"：0=永远选最大概率；越高越随机 |
| Hallucination | 幻觉 | 不知道也硬说，一本正经地编造 |
| Prompt | 提示词 | 你发给模型的输入（本月的主角，day11 起） |

## 3. 动手实操：亲手感受"概率"和"随机"

### 3.1 路径①：Ollama 本地跑（推荐，零成本）

```powershell
# 安装 Ollama（官网下 Windows 版）后：
ollama run qwen2.5:7b
# 内存不够就换小的：ollama run qwen2.5:3b（流程完全一样）

# 实验①：同一问题问三遍（体会随机性）
>>> 用一句话介绍 Kafka
>>> 用一句话介绍 Kafka
>>> 用一句话介绍 Kafka
# 预期：三遍措辞都不同——这就是 temperature>0 的采样随机

# 实验②：固定温度再问三遍（体会确定性）
>>> /set parameter temperature 0
>>> 用一句话介绍 Kafka   （连问三遍）
# 预期：三遍几乎一字不差——temperature=0 ≈ 贪心选最大概率
```

### 3.2 路径②：无模型降级（人肉模拟，诚实记录）

```
没有 Ollama/网络也挡不住今天的概念：
  自己当一回模型——把"中国的首都是__"这个接龙，
  分别用"贪心"（每次选最大概率）和"随机"（允许选小概率词）玩 5 轮，
  体会：随机=多样但可能跑偏；贪心=稳定但呆板
  —— 这就是 temperature 旋钮的本质（诚实记录：本次为降级实验）
```

```
实验③：把"接龙"玩到失控（幻觉体感）
  问模型一个不存在的东西（如"介绍一下 xx 公司 2019 年的内部规定"）
  —— 如果它煞有介事地编了一堆：恭喜，亲眼见到幻觉了
  记录：编造的内容+你当时"差点信了"的感受（这就是用户的感受）
```

## 4. 面试连接

**Q：用一句话讲清大模型的原理？（开场必考，答出工程结论=加分）**
> 大模型本质是超大规模的"下一个词预测"：给定前文，按概率分布采样下一个词，再拼回去继续，自回归地生成整段回答。这个本质直接推出四条工程结论：它是概率模型、同一问题两次回答可能不同，所以生产上必须建评测体系而不是靠感觉；它没有真正记忆，多轮对话靠重发历史，受上下文窗口限制；它会幻觉，不知道也会顺着编，所以知识密集场景必须外挂 RAG 加引用溯源；知识有截止日期，时效性内容必须外部注入。这四条结论就是我后面做 AI 应用架构的出发点的全部——模型本身解决"生成"，工程解决"可靠"。

**Q：为什么大模型回答每次都不一样？能让它一样吗？（追问）**
> 采样机制决定的：模型输出的是概率分布，temperature>0 时按分布随机抽签。能压但不能根除——把 temperature 设 0（贪心）或固定 seed 可以近似可复现，但批处理/硬件差异下仍可能有微小波动。工程态度是"别追求确定性，追求可验证"：确定性交给结构化输出和代码逻辑，模型只负责它擅长的语义理解部分；输出正确性由评测集和规则校验兜底——这和我在 Flink 里"实时链路再准也要离线账对拍"是同一个思想。
