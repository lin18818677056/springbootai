## 1. 知识地图（先讲人话）

```
模型"不够懂你"时的三档手段（从便宜到贵，工程纪律第 N 次上场）：

手段① Prompt 工程（几乎免费，灵活度最高）
  系统提示+few-shot+结构化输出——本月 W2/W3 全是在干这个
  边界：示例有限（token 贵）、太深的领域模式教不动

手段② RAG 检索增强（便宜，治"不知道"）
  原理：回答前先去知识库检索相关资料，塞进上下文让模型"开卷考试"
  治：知识注入——公司制度/产品文档/时效信息
  优点：知识随时更新（换文档就行）、可溯源（答案带出处）、错了改文档
  —— M14 主线，今天只立决策点

手段③ 微调 Fine-tuning（贵，治"不会做"）
  用自己的数据继续训练，把"行为"烧进模型
  治：风格（永远亲~开头）/ 格式习惯（复杂 JSON 结构）/ 领域术语的深层理解
  代价：数据要标注（千~万级样本）、训练要算力、更新要重训、无法溯源

LoRA（Low-Rank Adaptation）微调的"平替神器"：
  全参微调 = 给大脑做全麻手术（动全部参数：贵、危、要海量数据）
  LoRA = 外挂一个小插件训练（冻结原模型，只训一个几十 MB 的"补丁"）
    —— 成本低一个量级；一个基座+多个插件=一个模型多种人格
    —— 企业微调的事实标准（记：面试说微调必带 LoRA）

《定制手段决策树》（贴墙）：
  模型答不好？
  ├─ 是"不知道资料"？ → RAG（知识类 90% 的需求都是这个）
  ├─ 是"格式总漂"？   → 先 Prompt+Schema（day10 三板斧），实在不行再微调
  ├─ 是"风格不对"？   → few-shot 顶不住 → 微调（LoRA）
  ├─ 是"领域术语深"？（医疗缩写/法律黑话）→ 混合：RAG 给术语表 + LoRA 教语感
  └─ 是"知识又新又多"？ → 别想了，RAG + 检索质量优化（M14）

工单系统要不要微调？（今天的决策实战）：
  分类 → few-shot 够（评测分数说了算）
  记忆/摘要 → Prompt 手段够
  审核 → Prompt+规则够
  知识问答（M14 要加的）→ RAG（产品文档会更新，微调等于自杀）
  结论：全链路 0 微调——不是微调不好，是"便宜手段全试过且够用"
  —— 这个"想清楚为什么不用"比"用了高级手段"更是架构师信号
```

## 2. 核心概念（中英对照+大白话）

| 英文 | 中文 | 大白话解释 |
|------|------|-----------|
| RAG | 检索增强生成 | 开卷考试：先查资料再回答（M14 主线） |
| Fine-tuning | 微调 | 继续训练改行为（贵、慢、不可溯源） |
| LoRA | 低秩适配 | 只训小插件不动大脑的省钱微调 |
| Frozen Weights | 冻结参数 | 原模型不动的部分 |
| Adapter | 适配器插件 | LoRA 产出的"人格补丁" |
| Knowledge Injection | 知识注入 | 让模型"知道"新东西的手段统称 |

## 3. 动手实操：决策树实战演练

### 3.1 演练①：十个场景快判（先自己判再对答案）

```
1. 客服回答永远用公司规定话术开头 → 行为/风格 → few-shot 试试 → 顶不住再 LoRA
2. 回答要基于今年新版报销制度 → 知识 → RAG
3. 工单分类格式偶发漂移 → 格式 → Schema 约束（板斧③）而非微调
4. 医疗器械说明书问答（术语密集+文档会更新）→ RAG 给文档 + 术语表注入
5. 让输出永远是严格的嵌套 JSON（Schema 搞不定）→ 微调（格式习惯烧进去）
6. 模型不知道昨天上架的商品 → RAG（时效知识）
7. 法律文书摘要要特定法言法语风格 → LoRA（风格）
8. 内部黑话缩写理解（如"三限房""双集中"）→ RAG 术语表优先；深层语感再 LoRA
9. 多语言客服（小语种质量差）→ 换模型（选型问题，day22）而非微调
10. 老板问"能不能把公司 wiki 喂给模型" → 这就是 RAG（M14 开工）
判完自评：__ /10（错的归因：知识/行为分不清，还是手段边界记不住）
```

### 3.2 演练②：LoRA 认知卡（不用真训，但要能讲）

```
《LoRA 认知卡》：
  是什么：冻结基座，只训练一个低秩"补丁"矩阵（几十 MB 级）
  为什么便宜： trainable 参数量降 2~3 个量级 → 算力和数据需求同降
  怎么用：一个基座 + 多个插件 = 一套底座多种人格（售后人格/法务人格）
  何时选：Prompt 手段确实顶不住 + 样本能标出几千条 + 有基本算力
  面试锚点：全参微调是"开颅手术"，LoRA 是"戴眼镜"——
           度数合适就别开颅
```

### 3.3 演练③：工单系统定制决策记录

```
按决策树把工单系统五个环节过一遍（day21 资产的补充文档）：
  环节 | 需求 | 手段决策 | 理由
  分类 | 类别判断 | Prompt+few-shot | 评测分数已达标
  回复 | 多轮对话 | Prompt+记忆管理 | day17 方案
  审核 | 风险分级 | Prompt+规则先行 | 规则扛大头

结论一句话：本月 0 微调，M14 上 RAG——每一步都有依据，没有一步是赶时髦
```

## 4. 面试连接

**Q：什么时候需要微调大模型？什么时候用 RAG？（必考决策题）**
> 金句是"RAG 管知识，微调管行为"，展开成一个决策树：先问"模型是不知道资料，还是不会做事"。不知道资料——公司制度、产品文档、时效信息——全走 RAG：知识换文档就更新、答案可溯源、错了改文档，成本和维护量低一个量级；微调做知识是三输：更新要重训、无法解释出处、还容易把旧知识练串。不会做事——说话风格、复杂格式的肌肉记忆、领域术语的深层语感——才考虑微调，且纪律是从便宜到贵逐级上：先 few-shot，顶不住再上 LoRA。LoRA 是微调的平替：冻结基座只训一个几十 MB 的插件，成本降几个量级，还能一个基座配多个人格插件。我在自己的工单项目里做过完整决策：五个环节走完全链路 0 微调——分类和审核 Prompt 手段评测分数就够，知识问答规划了 RAG，风格暂无硬需求。我的观点是：想清楚为什么不用高级手段，比用上高级手段更是架构师信号。
