## 1. 六线串讲（W2 的完整故事线）

```
第 1 站【day08 API 裸调】：OpenAI 兼容协议=大模型界 JDBC
  请求三要素（model/messages/参数）+ 响应四看点（content/usage/finish_reason）
  finish_reason=length=截断信号——字段会说话
第 2 站【day09 流式输出】：SSE 打字机
  总时长没变，TTFT 决定体感；delta 拼接责任在你；交互必须流/批处理别流
第 3 站【day10 结构化输出】：工程化分水岭
  三板斧（Prompt 约束→JSON 模式→Schema 约束）+ 防御链四道（校验/修复/重试/兜底）
第 4 站【day11 四件套】：Role/Task/Constraint/Example
  A/B 实验：最不能省 Constraint，最能提准 Example；Prompt 版本管理意识
第 5 站【day12 few-shot/CoT】：给例子 vs 教思路
  2×2 决策表：治"长得不对" vs 治"想得不对"；推理模型内置 CoT
第 6 站【day13 安全攻防】：注入=Prompt 界 SQL 注入
  纵深防御五道；最硬的防御是"结构化输出+权限隔离"（模型无执行通道）

串联理解：W1 知道模型"是什么"，W2 掌握"怎么用"——
  协议（day08）→ 体验（day09）→ 程序可消费（day10）→ 指令体系（day11-12）
  → 安全边界（day13）
  每一站都留了生产级"卡片"：这些卡片就是 W3 项目的零件库。
```

## 5. 面试连接

**Q：你做 AI 应用开发的方法论是什么？（W2 收束题，考体系化）**
> 我把它总结成"四层工程化"。第一层协议层：基于 OpenAI 兼容接口做薄封装，关注 usage 成本统计和 finish_reason 健康信号。第二层契约层：所有要被程序消费的输出走结构化 Schema，配防御链——校验、修复、带反馈重试、兜底，失败样本落库回炉。第三层指令层：Prompt 用四件套标准结构写、版本化管理，few-shot 覆盖边界 case，推理场景上 CoT，所有变更拿评测集验证。第四层安全层：分隔符隔离防注入、最小特权、输出扫描、高危动作程序侧二次确认。这个体系不是我发明的，是把数据链路的方法论平移过来的——契约层对应 Flink 的 Schema 和幂等 Sink，指令层对应 SQL 口径管理，安全层对应接口的权限设计。AI 应用不神秘，工程纪律换了个领域而已。
