# Day 06 · 幻觉与知识截止：模型为什么一本正经地胡说

> **今日目标**：理解幻觉的产生机制（不是 bug，是接龙天性）、知识截止的含义；掌握工程上的四道防线——这节课是 M14 RAG 主线的"存在证明"。
> **时长**：概念 1h / 实操 1.5h / 输出 0.5h
> **今日产出**：幻觉分类实验记录 + 《幻觉防线四件套》
> **对照教程**：`ai-learning/01-大模型基础原理.md` 第 1 节（工程结论③④展开）

## 1. 知识地图（先讲人话）

```
幻觉 Hallucination = 不知道也硬说，一本正经地编造

为什么不是"bug"而是天性？（回到接龙本质）
  模型的使命是"生成流畅合理的文本"，不是"只说自己确定的事"
  问它"张三 2019 年的论文叫什么"——它没见过，但接龙惯性会让它
  编一个"听起来极像论文标题"的东西（格式对、语气稳、内容是编的）
  —— 最可怕之处：编得和你见过的真答案一模一样的"可信度"

幻觉的三个高发场景（生产排查重点）：
  ① 问超出知识范围的事（冷门人名/内部数据/太新的信息）
  ② 长输出后段（前面编了一点没被发现，后面"顺着"继续圆）
  ③ 模糊问题（问题本身可做多解时，它选一个自信地说）

知识截止 Knowledge Cutoff：
  训练数据有时间终点（如"2024 年 10 月"）→ 之后的事它一概不知
  且它"不知道自己不知道"——不会说"这事我不知道"，而是自信地猜
  —— 生产红线：任何时效性内容（价格/库存/政策/新闻）禁止直接问模型

《幻觉防线四件套》（工程降幻觉的标准动作，M14 会全部实现）：
  ① 溯源：要求"只依据以下资料回答，并标注出处"→ 答案可验证
     （无资料时明确回答"不知道"——Prompt 里必须显式写）
  ② 注入：把可靠资料放进上下文（RAG 的雏形——今天用"复制粘贴"模拟，M14 自动化）
  ③ 校验：输出后程序校验（引用是否真存在于资料里/数字是否在合理范围）
  ④ 兜底：置信度低/校验不过 → 转人工（AI 应用的"快速失败"）
```

## 2. 核心概念（中英对照+大白话）

| 英文 | 中文 | 大白话解释 |
|------|------|-----------|
| Hallucination | 幻觉 | 不知道也硬编，且编得很有说服力 |
| Knowledge Cutoff | 知识截止 | 训练数据的时间终点，之后的事不知道 |
| Grounding | 锚定/溯源 | 让回答"有据可依"（引用真实资料） |
| Citation | 引用 | 答案标注出处（可信 AI 的标配） |
| Confidence | 置信度 | 模型"觉得自己有多对"（但常高估） |
| Human-in-the-loop | 人机协同兜底 | 低置信场景转人工（防线的最后一道） |

## 3. 动手实操：幻觉解剖实验

### 3.1 实验①：三个高发场景逐一复现（有模型）

```
场景① 冷门追问：
  "介绍一下王建军 2018 年发表的《分布式缓存一致性研究》这篇论文的主要观点"
  —— 大概率是编的（这个人/这篇论文是虚构的），看它编得多认真
场景② 时效追问：
  "今天股市行情怎么样？"
  —— 不知道今天是什么时候，还要编一个"行情"（知识截止实锤）
场景③ 模糊追问：
  "这个配置该怎么调？"（不给任何上下文）
  —— 它会自信地给出一套"通用正确但可能完全不对"的答案

记录格式：问题 | 模型回答摘要 | 编造点在哪 | 用户的"上当点"在哪
```

### 3.2 实验②：四道防线逐个上（Prompt 手法预演 RAG）

```
防线实验（用实验①的场景②改）：
原版："今天股市行情怎么样？" → 编造
改① 加溯源约束："仅根据我提供的资料回答，资料里没有就回答'我不知道'。
     资料：〈空〉" → 预期：老实说不知道（防线①②起效）
改② 给真资料："资料：2026-09-28 上证指数收报 xxxx 点（我编的测试数据）。
     问题：今天股市行情？" → 预期：按资料回答（这就是 RAG 的本质动作！）
—— 今天的结论：RAG = 溯源约束 + 自动化资料注入，没有魔法（M14 揭晓自动化部分）
```

```
实验③（降级也做）：编造识别训练
  找 3 段 AI 生成的"知识性回答"（自己生成或网上找），
  标出哪些事实陈述可以验证、哪些是"格式正确但查无此事"
  —— 练的是"对 AI 输出的怀疑本能"（工程师的肌肉记忆）
```

## 4. 面试连接

**Q：什么是大模型幻觉？生产上怎么防？（AI 应用必考第一题）**
> 幻觉是模型"不知道也硬编"的现象——本质不是 bug，是接龙天性：它的使命是生成流畅文本，而不是只说确定的事，所以编出来的东西格式正确、语气自信，极具迷惑性。工程上我布四道防线：第一道溯源约束，Prompt 里显式要求"只依据给定资料回答，没有就说不知道"，把"可以编"变成"必须锚定"；第二道知识注入，把可靠资料放进上下文喂给它（生产上就是 RAG 自动化检索注入）；第三道程序校验，答案里的引用和数字做规则校验，引用不存在或数字越界就拦截；第四道人工兜底，低置信或校验不过的转人工。另外一条红线：任何时效性内容（价格、库存、政策）禁止裸问模型——知识截止决定了它必错，这类字段永远走数据库或 RAG 实时注入。

**Q：为什么模型不会说"我不知道"？（追问，考机制理解）**
> 因为训练目标就没有这个倾向——SFT 和 RLHF 教的是"好好回答"，绝大多数训练样本都有完整答案，"坦承不知道"的表达在语料里占比极低，接龙惯性自然往"给出一个答案"方向走。所以要靠工程补：Prompt 里显式给"我不知道"这个选项并给示例（few-shot 姿势，day12）；RAG 场景下"资料里没有"要被定义为合法甚至优先的回答路径。一句话：模型的不确定表达是训练出来的稀少，工程上要把它设计成常见。
