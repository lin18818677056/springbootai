# Day 04 · 训练三部曲：模型是怎么"长大"的

> **今日目标**：用"上学→岗前培训→老员工带教"讲清预训练/SFT/RLHF 三段训练各在造什么；搞懂基座模型 vs 对话模型的区别；记住选型金句"RAG 管知识，微调管行为"。
> **时长**：概念 1h / 实操 1h / 输出 0.5h
> **今日产出**：三部曲对照表 + "微调还是不微调"决策卡
> **对照教程**：`ai-learning/01-大模型基础原理.md` 第 3 节

## 1. 知识地图（先讲人话）

```
把模型当"培养一个新员工"就全懂了：

阶段① 预训练 Pre-training（上学读书，十几年）
  教材：万亿级 token 的互联网文本
  学什么：语言规律+世界知识（语法、常识、事实的统计规律）
  毕业生：基座模型 Base Model——"会说话，不懂事"
    （你问"怎么退货"，它可能接着写一篇"退货流程的小说"——它在接龙，不是在回答）

阶段② 监督微调 SFT（岗前培训，几周）
  教材：十万级人工标注的"问题-标准回答"对
  学什么：按指令好好回答（问答的格式、角色、边界）
  毕业生：会聊天的模型——"懂事"了

阶段③ RLHF 人类反馈强化学习（老员工带教+价值观校准）
  教材：人类对多个回答的排序（哪个更有用/诚实/无害）
  学什么：往"人类喜欢"的方向对齐
  毕业生：对话模型（Chat Model）——调 API 用的都是这个三件套毕业的成品

由此推出的选型决策（工程重点）：
  ① 基座 vs 对话模型：做应用调的都是对话模型（成品）；做研究/二次训练才碰基座
  ② 微调 Fine-tuning 到底动不动？
     —— 微调改的是"行为"（风格/格式/领域术语的答题习惯）
     —— 注入"知识"不要微调：知识更新快、需要溯源，交给 RAG（M14 主线）
     —— 金句：RAG 管知识，微调管行为（面试高频，背下来）
  ③ LoRA：不重训整个模型（全参微调=给大脑做手术，贵且危险），
     只外挂一个小"插件"训练（成本低一个量级）——企业微调的事实标准
```

## 2. 核心概念（中英对照+大白话）

| 英文 | 中文 | 大白话解释 |
|------|------|-----------|
| Pre-training | 预训练 | 上学：海量文本学语言规律，产出基座模型 |
| Base Model | 基座模型 | 会接龙不懂事；适合再加工，不适合直接对话 |
| SFT | 监督微调 | 岗前培训：标注问答教它"按指令回答" |
| RLHF | 人类反馈强化学习 | 老员工带教：按人类偏好排序校准 |
| Alignment | 对齐 | 让模型行为符合人类意图/价值观的总称 |
| Fine-tuning | 微调 | 用自己的数据继续训练，改"行为" |
| LoRA | 低秩适配微调 | 不动大脑只训小插件；企业微调首选 |
| Instruction Tuning | 指令微调 | SFT 的别称（按指令回答） |

### 3.2 实验②："微调还是不微调"决策卡（模拟决策）

```
场景判断练习（先自己判，再看答案）：
  A. 让客服模型永远用"亲~"开头、口语化风格 → 微调（行为/风格 ✓）
  B. 让模型知道公司 2025 年最新报销制度 → RAG（知识 ✗ 别微调：更新要重训、无法溯源）
  C. 让模型输出稳定的 JSON 格式 → 先 Prompt+结构化输出（day10），
     搞不定再微调（格式是行为，但先试便宜的手段）
  D. 医疗术语缩写的精准理解 → 微调（领域术语=行为习惯的深层定制 ✓）
  E. 模型不知道昨天发布的新闻 → RAG/外部注入（知识截止，day06）
  结论卡：行为/风格/格式/术语 → 微调（LoRA）；知识/时效/溯源 → RAG
```

## 4. 面试连接

**Q：预训练、SFT、RLHF 分别在做什么？（原理题，用类比答=沟通力信号）**
> 我用培养新员工类比：预训练是上学读书——用万亿 token 的语料学会语言规律和世界知识，产出的是"会说话不懂事"的基座模型，你问它问题它可能接着写小说，因为它只是在做文字接龙；SFT 是岗前培训——用十万级标注问答教它"按指令好好回答"；RLHF 是带教校准——用人类对回答的排序，让它往有用、诚实、无害的方向对齐。我们调 API 用的都是三步全做完的对话模型。这个认知直接决定工程选型：基座模型是给二次训练用的原料，做应用永远拿对话模型+工程手段。

**Q：什么场景该微调？什么场景该用 RAG？（选型金句题，必考）**
> 金句：RAG 管知识，微调管行为。判断标准是"要改的是知道的事还是做事的方式"。注入知识——公司制度、产品文档、时效信息——用 RAG：知识可以随时更新、可以引用溯源、错了换文档就行，微调做知识既贵（每次更新重训）又不可解释（说不出答案出处）。改变行为——说话风格、输出格式习惯、领域术语的理解方式——用微调（一般上 LoRA，成本低一个量级）。还有一个务实原则：格式类需求先试 Prompt 加结构化输出这种便宜手段，确实搞不定再上微调——手段从便宜到贵的顺序尝试，是工程纪律。
