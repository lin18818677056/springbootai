# Day 20 · 成本与限流：给 AI 应用装"电表和闸门"

> **今日目标**：把 usage 记账变成成本看板；实现三层省钱杠杆（缓存/精简/降级模型路由）；配置限流与重试（M2/M5 老方法在 AI 场景的平移）。
> **时长**：看板 1.5h / 省钱实验 1.5h / 输出 0.5h
> **今日产出**：成本日报 SQL/脚本 + 三层省钱对照数据 + 《限流重试配置卡》

## 1. 知识地图（先讲人话）

```
AI 应用的"电费单"结构：
  月成本 = Σ(每次调用: 输入token×输入单价 + 输出token×输出单价)
  —— day08 起每次调用都落了 usage，今天把这些账聚合成看板
  成本日报三个必看数：日均成本 / 单均成本 / token 消耗 TOP 请求
  （单均成本突涨=Prompt 失控或循环调用；TOP 请求=优化靶子）

三层省钱杠杆（从省到猛，逐层上——工程纪律再现）：

杠杆① 缓存（最优先，免费的午餐）：
  语义缓存：相同/相似问题直接返回缓存答案（"怎么退款"一天被问 800 遍）
  前缀缓存：system 提示词不变的部分，部分厂商按"缓存命中"打折
  —— M4 Redis 缓存思想直译：命中率高=省钱；但要答"缓存失效策略"（知识更新要清）

杠杆② 精简 Prompt（结构性省钱）：
  system 从 800 token 精简到 300 → 每次调用省 62% 输入费 ×全量请求
  历史摘要压缩（day17 已做）——多轮对话最大的省钱点
  —— 用评测集护航：精简后分数不能掉（day19 SOP 的时机③）

杠杆③ 模型路由（按难度分诊）：
  简单分类 → 小模型（便宜 10 倍）；复杂推理 → 大模型
  —— "规则先行（day18）"的进阶版：规则不行上小模型，小模型不行上大模型
  路由器本身用规则/小分类器实现（不能为了省钱再造个更贵的路由）

限流与重试（闸门，M2/M5 平移）：
  限流三层：按用户（防单人刷爆）/按全局（模型方配额）/按成本（日预算熔断线）
  重试节奏：429（限流）→ 指数退避重试（1s/2s/4s，上限 3 次——M5 消息重试阶梯同款）
  5xx → 换备用模型重试一次 → 还不行走降级（人工队列）
  日预算熔断：当天模型花费超预算 80% 预警、100% 只跑缓存+人工
  —— "预算也是资源，超了也要熔断"——成本维度的稳定性设计
```

## 2. 核心概念（中英对照+大白话）

| 英文 | 中文 | 大白话解释 |
|------|------|-----------|
| Cost Dashboard | 成本看板 | 日均/单均/TOP 三数齐（电费单读法） |
| Semantic Cache | 语义缓存 | 相似问题命中同一答案 |
| Model Routing | 模型路由 | 简单题小模型、难题大模型的分诊台 |
| Exponential Backoff | 指数退避 | 1s/2s/4s 的重试节奏（M5 老朋友） |
| Budget Circuit | 预算熔断 | 日花费超线就降级（钱也是资源） |
| Cost per Query | 单均成本 | 每次问答花多少钱（效率核心指标） |

### 3.2 步骤②：三层杠杆逐个实测

```
实验① 缓存命中率测算：
  把评测集 50 条里"同类问法"的题目数一下（如 8 条退款咨询其实共享 3 个意图）
  假设语义缓存命中 → 潜在节省 = 重复题数/总题数 = __%
实验② 精简 Prompt 对照：
  system 800→300 token，重跑评测集：分数从 __% → __%（必须不掉，掉了回炉）
  输入成本降幅 = __%（算给老板看的数字）
实验③ 模型路由模拟：
  50 条里规则能判 __ 条（0 成本）/ 小模型能判 __ 条（单价 p1）/ 需大模型 __ 条（单价 p2）
  全量大模型账单 vs 路由后账单 = ____ vs ____（省 __%）
  —— 记住验证纪律：路由后的分类正确率必须复测（省钱不能省质量）
```

### 3.3 步骤③：《限流重试配置卡》

```
《限流重试配置卡》（贴墙）：
  限流：用户级 10 次/分；全局按模型配额 80% 预警线；日预算 100% 熔断线
  重试：429 → 指数退避 1s/2s/4s 上限 3 次
        5xx → 备用模型重试 1 次 → 人工队列
        超时 → 不重试直接人工（宁慢勿错，day18 原则）
  熔断：连续失败 2 次 open 5 分钟（day18 熔断器复用）
  记账：每次调用（含失败的）都落 call_log——失败也花钱，账要记全
```

## 4. 面试连接

**Q：AI 应用的成本怎么控制？（成本治理题，P7 信号）**
> 我分四步。第一步可观测：每次调用的 usage 落库，日报盯三个数——日均成本、单均成本、token 消耗 TOP 请求；单均突涨通常是 Prompt 失控或循环调用 bug，TOP 请求就是优化靶子。第二步省钱杠杆按性价比上：先语义缓存——高频重复问题直接命中缓存，这个免费；再精简 Prompt——system 从 800 压到 300 token，全量请求的输入费直接降六成，前提是评测集分数不能掉；然后模型路由——规则能判的不调模型、简单题走小模型、难题才上大模型，路由本质上是个"分诊台"。第三步闸门：用户级和全局限流、429 指数退避重试、5xx 换备用模型。第四步预算熔断：日花费超 80% 预警、100% 只跑缓存和人工——把成本当资源做稳定性设计，超预算也要熔断。这套框架的每一步都有对照数据：精简省多少、路由省多少，都是实测数字，不是拍脑袋。
