# Day 12 · Few-shot 与思维链：给例子 vs 教思路

> **今日目标**：分清两大提准手段的适用边界——few-shot（给例子，教"长什么样"）和 CoT（教思路，让"先想后答"）；用对照实验测出各自在分类题和推理题上的增益。
> **时长**：概念 1h / 实操 2h / 输出 0.5h
> **今日产出**：2×2 对照实验记录 + 《手段选型卡》+ 模板④⑤入库
> **对照教程**：`ai-learning/02-Prompt工程.md`

## 1. 知识地图（先讲人话）

```
两大提准手段，解决两种不同的"不会"：

Few-shot（给例子）："你看，这种工单就该这么分"
  zero-shot：直接下指令，不给例子
  one-shot / few-shot：给 1 个 / 2~3 个输入输出示例
  原理：模型的模仿能力远强于理解能力（day11 结论）
  治什么病：格式不稳、边界 case 漂移、风格不统一
    —— 示例就是"活的标准答案"，比形容词描述管用十倍
  代价：每个示例都占 token（示例长度×个数，直接进成本）

CoT 思维链（Chain of Thought，教思路）："先一步步分析，再给结论"
  原理：让模型把中间推理写出来——"脑子里的草稿纸摊开"
    接龙模型每一步只预测下一个词；逼它"先写推理再写答案"，
    相当于把复杂题拆成一串简单题
  治什么病：需要多步推理的题（数学/规则判断/因果分析）
    —— 直接要答案容易错；"让我们一步一步思考"就能显著提准
  代价：输出变长（推理过程也是 token，费钱+费时）
  进化：现在的推理模型（o1/DeepSeek-R1 类）内置了 CoT——
    你不用教它思考，它自己思考；普通对话模型才需要你用 Prompt 逼

2×2 决策表（背下来）：
  ┌──────────────┬─────────────┬──────────────┐
  │              │ 简单任务     │ 推理任务      │
  ├──────────────┼─────────────┼──────────────┤
  │ 格式/边界问题 │ few-shot     │ few-shot+CoT │
  │ 无格式问题    │ 直接问       │ CoT          │
  └──────────────┴─────────────┴──────────────┘
  一句话：few-shot 治"长得不对"，CoT 治"想得不对"；两个病都有就都上
```

## 2. 核心概念（中英对照+大白话）

| 英文 | 中文 | 大白话解释 |
|------|------|-----------|
| Zero-shot | 零样本 | 直接下指令，不给例子 |
| Few-shot | 少样本 | 给 1~3 个示例，靠模仿提准 |
| CoT (Chain of Thought) | 思维链 | "先一步步推理再给答案"的 Prompt 手法 |
| Intermediate Steps | 中间步骤 | 摊开的"草稿纸"（推理过程） |
| Reasoning Model | 推理模型 | 内置 CoT 的新一代模型（思考是自带的） |
| Prompt Cost | 提示成本 | 示例都占 token——提准手段也有账单 |

## 3. 动手实操：2×2 对照实验

### 3.1 准备两组题（各 6 条，含标准答案）

```
A 组（分类题，考 few-shot）：6 条工单判断类别（refund/logistics/consult）
  其中 2 条是"边界件"（如"退款了但物流显示已签收"——既是退款又涉物流）
B 组（推理题，考 CoT）：6 条规则判断题
  例："会员日全场 9 折，VIP 再享 95 折；满 300 减 40 与折扣不叠加取低者。
      VIP 会员买 350 元商品（会员日），应付多少？"（人工先算出标准答案）
```

### 3.2 实验①：分类题上 few-shot 的增益

```
四版 Prompt 各跑 A 组 6 题：
  ① zero-shot：只有四件套（无示例）→ 边界件正确 __/2
  ② one-shot：加 1 个普通示例 → __/2
  ③ few-shot：加 2 个示例（其中 1 个就是边界件）→ __/2
  预期：③ 的边界件全对——"示例里见过同款"比"指令里描述"管用
  记录：格式达标率三版各 __/6（few-shot 顺带压格式）
```

### 3.3 实验②：推理题上 CoT 的增益

```
四版 Prompt 各跑 B 组 6 题（对照标准答案）：
  ① 直接问："应付多少？" → 正确 __/6
  ② CoT："请先列出折扣规则的应用顺序，逐步计算，最后给答案" → __/6
  ③ few-shot 误用：给 1 个"直接给答案"的示例 → __/6（提准有限——病不对药）
  预期：② 显著优于 ①③——推理病要用推理药
  记录：② 的输出 token 比 ① 多多少（CoT 的账单）
```

### 3.4 实验③：模板④⑤入库

```
模板④ 分类器加强版：四件套 + 2 个示例（含 1 个边界件）——day16 项目直接用
模板⑤ 规则推理版：Task 后加"步骤：1.列出适用的规则 2.按顺序应用 3.最后给结论"，
  Constraint 加"先展示推理过程再给最终答案"——对账/合规判断场景用
```

## 4. 面试连接

**Q：few-shot 和 CoT 分别解决什么问题？怎么选？（手段选型题）**
> 一句话：few-shot 治"长得不对"，CoT 治"想得不对"。few-shot 是给输入输出示例——模型的模仿能力远强于理解能力，示例就是活的标准答案，对格式不稳、边界 case 漂移立竿见影，我实验里分类任务加了边界示例后，边界件正确率明显提升；代价是示例占 token，直接进成本。CoT 是让模型先写推理再给答案——把复杂题拆成一串简单题，对多步推理任务（规则叠加计算、因果判断）提升显著，我实验里折扣叠加计算题直接问错一半以上，加"先列规则再逐步算"后基本全对；代价是输出变长费钱费时。选型按 2×2 表：格式/边界问题用 few-shot，推理问题用 CoT，两个病都有就都上。另外要注意推理模型（o1/R1 这类）内置了 CoT，不需要再用 Prompt 逼它思考——手段跟着模型形态走。

**Q：给多少个 few-shot 示例合适？示例怎么挑？（追问实操）**
> 数量上 1~3 个性价比最高，不是越多越好——每个示例都是 token 成本，而且示例太多会稀释注意力，反而降低关键约束的存在感。挑选比数量重要，两个原则：一是覆盖边界 case——最难的、最容易分错的那类样本要有一个示例（我实验里边界件示例是提准主力）；二是和线上数据同分布——示例的写法、长度、格式要贴近真实输入，拿精心修饰过的示例教出来的是"考试型选手"。最后一条工程纪律：示例变更也是 Prompt 变更，要走评测集验证，不能拍脑袋换。
