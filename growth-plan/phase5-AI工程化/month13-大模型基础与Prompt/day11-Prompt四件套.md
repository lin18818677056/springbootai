# Day 11 · Prompt 四件套：把"玄学"变成工程

> **今日目标**：建立写 Prompt 的标准结构——角色（Role）/任务（Task）/约束（Constraint）/示例（Example）四件套；用 A/B 对照实验验证"结构化 Prompt 比随手写好在哪"。
> **时长**：概念 1h / 实操 2h / 输出 0.5h
> **今日产出**：《Prompt 模板库》前 3 个模板 + 四件套 A/B 实验记录
> **对照教程**：`ai-learning/02-Prompt工程.md`

## 1. 知识地图（先讲人话）

```
坏 Prompt 和好 Prompt 的区别，就是"口头派活"和"写需求文档"的区别：
  口头："帮我看看这个工单" → 员工自由发挥，每次干法都不一样
  文档："你是售后专家，判断以下工单的类别和优先级，
         按固定格式输出，先看这几个例子" → 每次干法稳定
  —— 模型就是那个" infinitely 听话但需要说明白的员工"

Prompt 四件套（标准结构，背下来）：
  ① Role 角色：你是谁（"你是电商售后客服质检专家"）
     —— 激活对应领域的"语料区"；角色越具体，输出越专业
  ② Task 任务：干什么（"判断工单类别：退款/物流/其他，并给优先级"）
     —— 一句话说得清；动词开头；别一次塞三个任务（拆分，day18 级联）
  ③ Constraint 约束：怎么干（"只依据工单内容；不确定输出 unknown；
     类别必须是三选一；输出 JSON；不超过 50 字"）
     —— 约束是质量的护栏：格式约束+内容约束+安全约束
  ④ Example 示例：照这个样子（1~3 个输入输出示例——few-shot 的最小形态）
     —— 示例是最高效的指令：模型模仿能力 >> 理解能力

对照实验设计（控制变量法——M11/M12 老方法第 N 次上场）：
  同一个任务、同一个模型、同一批 10 条输入：
    A 组：随手一句话 Prompt
    B 组：四件套完整 Prompt
  用 day07 的《评测量表 v0》打分 → 数据说话
```

## 2. 核心概念（中英对照+大白话）

| 英文 | 中文 | 大白话解释 |
|------|------|-----------|
| Role | 角色 | "你是谁"——激活专业语料区 |
| Task | 任务 | "干什么"——一句话说得清 |
| Constraint | 约束 | "怎么干"——格式/内容/安全三重护栏 |
| Example | 示例 | "照这个样子"——模仿优于理解 |
| Zero-shot | 零样本 | 不给示例直接干 |
| Few-shot | 少样本 | 给 1~3 个示例再干（day12 展开） |
| Prompt Engineering | 提示工程 | 把写 Prompt 当正经工程做（本月主题） |

## 3. 动手实操：A/B 对照实验

### 3.1 实验①：坏 Prompt vs 四件套（10 条工单）

```
准备 10 条客服工单（真实感要够：混合退款/物流/咨询，含 1~2 条模糊的）

A 组 Prompt："帮我处理这个工单：〈工单〉"
B 组 Prompt：
  ── Role：你是电商售后系统的工单分类器。
  ── Task：判断工单类别（refund 物流 logistics 咨询 consult 三选一）
     和优先级（high 当天必须处理 / medium / low）。
  ── Constraint：只依据工单文本判断，不要臆测；模糊工单输出 category=unknown；
     只输出 JSON：{"category":"...","priority":"..."}，不要任何解释。
  ── Example：输入"我买的手机壳三天了还没发货" →
     {"category":"logistics","priority":"medium"}

打分（评测量表 v0）：
  格式达标率：A ___/10，B ___/10
  分类正确率（人工对答案）：A ___/10，B ___/10
  模糊件处理（该 unknown 的输出 unknown）：A ___，B ___
预期结论：B 组格式 100% 或接近、分类稳定性显著高——"工程化 Prompt 的价值"有数了
```

### 3.2 实验②：四件套逐件拆（归因实验）

```
从 B 组出发，每次只摘掉一件，看哪件最伤：
  - 摘 Role：分类稳定性下降 ___（角色定专业语料区）
  - 摘 Constraint：格式翻车+臆测上升（约束是护栏，最不能省）
  - 摘 Example：模糊件的判断漂移（示例压住边界 case）
  —— 归因结论：三件里最不能省的是 Constraint（防翻车）
     最能提准的是 Example（边界 case 靠示例教）
```

### 3.3 实验③：模板库前三件（攒资产）

```
《Prompt 模板库》开张（存 git，本月攒到 ≥8 个——README 验收④）：
  模板① 分类器模板（今天的 B 组，参数化：{{类别枚举}} {{示例}} {{输出格式}}）
  模板② 摘要模板：Role=编辑，Task=把以下内容压缩成 ≤N 字摘要，
        Constraint=保留关键数字和结论，不添加新信息
  模板③ 信息抽取模板：Role=数据分析师，Task=从文本抽取字段，
        Constraint=只输出 JSON，字段缺失填 null（配 day10 防御链）
```

## 4. 面试连接

**Q：怎么写好一个 Prompt？有什么方法论？（Prompt 工程核心题）**
> 我的标准结构是四件套：Role 角色定"你是谁"——激活模型对应领域的专业语料区；Task 任务一句话说清"干什么"，动词开头，复杂任务拆分不硬塞；Constraint 约束是护栏——格式约束（输出 JSON、字数）、内容约束（只依据材料、不确定输出 unknown）、安全约束；Example 示例是最高效的指令——模型的模仿能力远强于理解能力，一两个输入输出示例能压住边界情况。方法论上我坚持两件事：一是 Prompt 也走版本管理，改 Prompt 等于改代码，要有评测集护航（day19）；二是用 A/B 对照实验验证效果，我做过同任务 10 条样本的对照——四件套版分类稳定性和格式达标率显著高于随手写的版本，其中最不能省的是约束、最能提准的是示例。Prompt 是新世纪的 SQL：会写和写好，产出天差地别。

**Q：Prompt 写得越长越好吗？（误区判断题）**
> 不是，方向恰恰相反。day03 讲过注意力平方代价：Prompt 每长一截，费用按输入 token 涨、延迟按平方涨。而且长 Prompt 里指令互相稀释，模型反而容易漏关键约束。我的纪律：系统提示词控制在几百 token 内；能一句话说清的不写三句；示例挑最有代表性的 1~3 个，不是越多越好——示例太多同样占窗口又稀释注意力。判断标准是评测集分数：改 Prompt 以"分数持平或更好且 token 更少"为目标，精简也是优化。
