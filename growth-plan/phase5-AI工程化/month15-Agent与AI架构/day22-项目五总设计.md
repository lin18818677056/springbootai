## 1. 知识地图（先讲人话）

```
零件库存盘点（25 天攒的家底，今天全部进场）：
  W1：单工具闭环（三道闸）+ 工具考卷 20 题 + 五条军规
  W2：ReAct 循环（THINK/ACT）+ 三层刹车 + 多跳检索
      + 参数幻觉考卷 + 四层纵深 + 退款审批流
  W3：意图路由+动态挂载 + KbMcpServer + 主管模式经验 + 四问决策卡
  老家底：M13 意图分类器 / M14 检索器+引用校验+权限过滤 / 客户端五件套

三条架构决策（每条都有"为什么"）：
  决策① kbSearch = M14 检索器直接包成工具（不重写）
    为什么：M14 的混合检索+Rerank+引用+权限过滤是现成资产，
    Agent 化不推翻它——RAG 是 Agent 循环里的一个工具（day01 结论）
  决策② 路由前置：M13 意图分类器 → 动态挂载工具子菜单
    为什么：day06 考卷证明菜单越长选择越糊；day20 三方案对比
    证明"路由+单 Agent"是质量成本最优解（四问决策卡的产物）
  决策③ MCP 边界：kbSearch/queryOrder 内部直挂（低延迟），
    kbSearch 另开 MCP Server 供外部宿主（共享）；processRefund
    永不出 MCP（高危只走自家审批闭环）
    为什么：day15 冷静剂+day16 暴露清单——标准服务于真需求

《项目五架构图》（组装说明书）：
  用户 → 工单系统(Host)
    → M13 分类器（意图路由：闲聊/知识/办事/多跳）
    → AgentLoop（ReAct+三层刹车+思考留痕）
        工具菜单=按路由动态挂载
        kbSearch(M14检索器) / queryOrder / queryStock
        processRefund → 审批流(day13) → 真执行
    → 引用校验(M14)+权限(M14) → SSE 流式(M13/M14) → 用户
  外部宿主 ↔ KbMcpServer(HTTP) ↔ 同一套工具层
```

## 5. 面试连接

**Q：讲讲你这个 Agent 项目的整体架构？（项目主线题，3 分钟版）**
> 这个项目是把前 25 天的零件组装成生产系统，三条架构决策撑起骨架。第一，检索不重写：M14 的混合检索加 Rerank 加引用校验直接包成 kbSearch 工具，因为我们的判断是 RAG 就是 Agent 循环里的一个工具——知识问题走检索，办事问题走业务工具，边界早在 day01 就划清。第二，路由前置：M13 的意图分类器先判意图，按业务域动态挂载工具子菜单——这一步是拿数据换来的：工具考卷证明菜单越长选择越糊，三方案对比证明路由加单 Agent 是质量成本最优解。第三，MCP 划边界：内部调用走进程内直挂保低延迟，kbSearch 同时开一个 MCP Server 给外部宿主共享，而退款工具永远不对外暴露——高危操作只走自家审批闭环，两级确认，模型只发起、人工才点头。安全上四层纵深全程在线：解析白名单、参数三查、权限双保险、全量审计，外加 ReAct 循环的三层刹车——轮次上限、Token 预算、重复检测。上线前有一份 30 题端到端考卷：工具选择、多跳、幻觉参数、注入拦截四层一起考，指标不达标不放行。一句话总结：这不是一个新系统，是把 25 天攒的正确零件按正确位置组装——每个零件都被考卷验过，组装完再整体考一遍。
