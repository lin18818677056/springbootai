## 1. 知识地图（先讲人话）

```
Agent 的"能响应 ≠ 健康"更甚：
  RAG 会"流利地答错"，Agent 会"高效地办错事"——
  而且多一层"抽风不可预测性"（昨天预案①演示过）
  所以日报 = 传统指标 + Agent 行为指标 + 质量抽检 三层

《日报六指标·Agent 版》：
  传统侧：成功率 / P95 延迟 / 日成本（三数，口径沿用 M13/M14）
  Agent 行为侧（今天新增）：
    ④ 熔断率：loop_guard/budget/max_iter 三种 status 占比
       ——最灵敏信号（M14 拒答率的 Agent 版）：突增=模型/工具出问题
    ⑤ 轮次分布：P50/P95 轮数——悄悄变多=模型变笨或描述变坏
    ⑥ 工具成功率：分工具统计——单个工具成功率跌=那个工具坏了
  质量侧（周报）：30 题端到端考卷跑一遍（day22 承诺的常态化）
  红灯线四条：
    熔断率 >5% 红 | P50 轮数 >3 红 | 单工具成功率 <90% 红 |
    周考卷任一指标跌破基线 80% 红

无声劣化演习（监控有效性的期末考）：
  故意搞破坏：悄悄把 kbSearch 描述里"政策"两个字删掉
    （上周说过的"描述也是代码"——改了没人评审就是无声劣化）
  → 跑一天模拟流量 → 看日报：
    预期：政策类问题工具选择错→轮次变多+工具成功率异动+周抽检跌
  → 恢复 → 指标回落
  □ 演习结论：六指标能捉住"描述级"的细微劣化——监控不是摆设
```

## 2. 核心概念（中英对照+大白话）

| 英文 | 中文 | 大白话解释 |
|------|------|-----------|
| Circuit-breaker Rate | 熔断率 | 熔断会话占比（Agent 时代的第一信号灯） |
| Round Distribution | 轮次分布 | 会话轮数的 P50/P95（悄悄变多=有情况） |
| Per-tool Success | 分工具成功率 | 单工具的体检表（坏一个揪一个） |
| Silent Degradation | 无声劣化 | 描述改坏这类不报错的坏（周抽检的天敌） |
| Baseline Drift | 基线漂移 | 指标缓慢偏离（靠周抽检+环比发现） |
| Behavioral Metric | 行为指标 | Agent 特有：熔断/轮次/工具成功率 |

## 4. 面试连接

**Q：Agent 服务上线后你怎么监控？什么信号最重要？（生产化收口题）**
> Agent 的监控比 RAG 又深一层：RAG 会流利地答错，Agent 会高效地办错事，还有模型抽风的不可预测性——所以我的日报是三层。传统侧成功率、P95、日成本三数，口径和前两个月一致。Agent 行为侧三个新指标：熔断率是最灵敏的信号灯，三种熔断原因分開统计——重复检测触发多说明模型在转圈，预算触发多说明成本异常；轮次分布，P50 轮数悄悄变多往往意味着模型变笨或者工具描述被改坏，我们管这叫无声劣化——描述也是代码，改了没人评审它不报错但质量在掉；分工具成功率，坏一个揪一个，不会让单个工具的病被平均数掩盖。质量侧每周跑 30 题端到端考卷，这是防无声劣化的最后防线。有效性我们真验证过：演习里悄悄删掉 kbSearch 描述里的关键词，当天熔断率、轮次、工具成功率三个行为指标全部越线，周考卷的选择正确率也跌——三层指标互相印证，细微劣化藏不住，恢复后全回基线。告警接通后按分级路由：熔断率即时通知值班，考卷跌基线邮件次日处理，成本异常标红。总结一句话：从 M13 到现在，日报的进化史就是"能响应不等于健康"这句话的三次升级——LLM 版、RAG 版、Agent 版，健康的定义越来越深，信号灯就越来越多。
