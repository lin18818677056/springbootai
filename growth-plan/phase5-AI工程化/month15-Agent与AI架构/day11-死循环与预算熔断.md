# Day 11 · 死循环与预算熔断：给循环装两层刹车

> **今日目标**：人为造一个死循环工具，亲眼看 Agent 烧起来；落地两层刹车（MAX_ITERATIONS 轮次上限+Token 预算熔断）和第三招（重复检测提前熔断）；熔断后的降级链收口。
> **时长**：造故障 0.5h / 实操 2h / 输出 0.5h
> **今日产出**：死循环实验记录（烧钱曲线）+ 两层刹车代码 + 重复检测器
> **对照教程**：`ai-learning/05-Agent与MCP协议.md` 第 5 节风险表第一行
> **验收级问题预热**："如果模型今天抽风连续调错 20 次工具，最坏损失是什么？"

## 1. 知识地图（先讲人话）

```
Agent 死循环的三种成因（都见过真车翻）：

成因① 磨洋工型：工具一直报错，模型用同一个错法反复重试
  （第 3 轮和第 7 轮的 ACT 一模一样——没从报错里学到东西）
成因② 踢皮球型：工具 A 的结果说"详情请查 B"，工具 B 的结果说
  "请先用 A 查"——模型在两个工具之间转圈
成因③ 自我怀疑型：模型答完又反悔，自己问自己，越想越多
  （ReAct 的思考显式化偶尔会放大这个——想出瘾来了）

两层刹车（教材防御表的第一行，今天实装）：

刹车① MAX_ITERATIONS 轮次上限（硬顶）：
  for (int round = 1; round <= MAX_ITER; round++)  ← 就是 day02 那个循环边界
  取值经验：单工具任务 3、多跳任务 5、周报类 8（按类型动态定，day10 已预埋）

刹车② Token 预算熔断（软顶）：
  每轮累计 usage（M13 的 parseAndMeter 直接复用！）
  超预算立即熔断——轮次没到但钱烧完了也得停
  单任务预算示例：本地模型≈无成本但有时间上限；API 模型按单次任务
  封顶（如 50K token）——这笔账 day24 压测时精算

第三招 重复检测（提前熔断，比硬顶省一轮）：
  连续 N 轮（如 2 轮）的 ACT 完全相同 → 判定"磨洋工"→ 提前刹车
  ——成因①的直接解药；踢皮球型用"工具对访问序列去重"检测

熔断之后（降级三件套，M12/M13/M14 的老三样）：
  ① 留痕：熔断原因+已完成的轮次记录全存（审计要能回放）
  ② 诚实话术："这个问题我处理遇到困难，已转人工"（不装答完）
  ③ 转人工：工单带思考链摘要（人工接手不用从头看）
```

## 2. 核心概念（中英对照+大白话）

| 英文 | 中文 | 大白话解释 |
|------|------|-----------|
| Infinite Loop | 死循环 | Agent 停不下来（磨洋工/踢皮球/自我怀疑） |
| MAX_ITERATIONS | 轮次上限 | 硬顶刹车（循环次数封顶） |
| Token Budget | Token 预算 | 软顶刹车（花费封顶，到线熔断） |
| Circuit Breaker | 熔断器 | 到阈值就断（M6 熔断器的 Agent 版） |
| Repetition Detection | 重复检测 | 连续相同 ACT 提前刹车（省一轮是一轮） |
| Budget Exceeded | 预算超限 | 熔断原因的一种（留痕必记字段） |

### 3.3 两层刹车+重复检测（各 10 行）

```java
// AgentLoop.java —— 刹车段
long usedTokens = 0;
String lastAct = null; int sameCount = 0;
for (int round = 1; round <= MAX_ITER; round++) {          // 刹车①：硬顶
    LlmResp resp = llm.chat(prompt, history);
    usedTokens += resp.usage.totalTokens;
    if (usedTokens > TOKEN_BUDGET)                          // 刹车②：软顶
        { degrade("BUDGET_EXCEEDED", round, trace); return; }
    String act = extractAct(resp);
    if (act.equals(lastAct) && ++sameCount >= 2)            // 第三招：重复检测
        { degrade("REPEAT_LOOP", round, trace); return; }
    else sameCount = 0;
    lastAct = act;
    // ... 正常执行（三道闸+观察回填）
}
degrade("MAX_ITER", MAX_ITER, trace);                      // 硬顶触发也走降级
```

```powershell
# 装好刹车重跑死循环工具：
#   □ 预期：REPEAT_LOOP 在第 3~4 轮触发（比硬顶省十几轮）
#   □ 降级三件套验证：留痕完整/话术诚实/工单带思考链摘要
#   □ 再跑踢皮球工具对（A 指 B、B 指 A）→ 轮次硬顶兜住
```

## 4. 面试连接

**Q：Agent 死循环怎么办？你的生产配置是什么？（可靠性必问）**
> 我先把死循环分三类，因为成因不同解法不同：磨洋工型是工具报错后模型用同一个错法反复重试；踢皮球型是两个工具的结果互相指路，模型在中间转圈；自我怀疑型是模型答完又反悔自己问自己。刹车我装了三层。第一层轮次上限，这是硬顶，按任务类型动态设：单工具任务 3 轮、多跳 5 轮、周报类 8 轮。第二层 Token 预算熔断，软顶——轮次没到但预算烧完也立即停，这个计量直接复用我在客户端里做的 usage 解析，单任务封顶，超了熔断。第三层是重复检测，连续两轮行动完全相同就提前刹车，这一招专门治磨洋工，比等硬顶省十几轮的成本。我做过实弹实验：造了一个永远返回"信息不足请再查"的工具，无刹车时跑满五十轮，Token 消耗是正常任务几十倍——这条烧钱曲线我留在演练记录里；装上重复检测后第三四轮就熔断了。熔断之后三件套：全量留痕能回放、诚实话术不装答完、转人工的工单带思考链摘要让人接手不用从头看。回到那个验收级问题：模型抽风连调二十次，最坏损失就是二十轮的 token 钱加一次转人工——可控、可解释、可回放。
