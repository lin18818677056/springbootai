## 1. 知识地图（先讲人话）

```
教材原话（上线前的灵魂拷问）：
  "如果模型今天抽风连续调错 20 次工具，最坏损失是什么？"
  ——答不上来就是没做防护。

今天把这个问题变成一张可打钩的检查单（验收四部曲第四季：
  M12 预案清单 → M13 六项 → M14 六项 → 今天 Agent 五项）：

《Agent 上线检查单》五项：
  ① 迭代上限：MAX_ITER 按任务类型配置 + 重复检测在岗
     证据：day11 烧钱曲线（无刹车 50 轮）vs 装刹车后 3~4 轮熔断
  ② 权限闸门：解析白名单+参数三查+归属校验+按角色菜单
     证据：day12 红蓝三连演练全拦截记录
  ③ 预算熔断：TOKEN_BUDGET 精算配置 + 误杀/虚设双边界验证
     证据：day24 预算精算与验证记录
  ④ 审计留痕：全量 trace+工具审计+脱敏+可回放
     证据：day23 破案实验（留痕定位 __ 分钟）
  ⑤ 人工确认：高危操作全走审批流 + 审批状态模型改不了
     证据：day13 注入三连全卡审批环节

《最坏损失评估》正式作答（填实数）：
  场景：模型抽风，连续 20 次工具调用全错
  损失清单：
    token 损失：20 轮 × 单轮 __T = __T ≈ ¥__（本地≈占卡 __s）
    ——但实际烧不到 20 轮：重复检测第 3~4 轮就熔断
    业务损失：查询类工具只读无业务损失；
      退款类被审批闸拦（模型根本执行不了真操作）
    数据损失：只读工具+参数校验 → 0
  结论一句话：最坏损失 = 三四轮的 token 钱 + 一次转人工，
    可控、可解释、可回放 —— 这句话就是五项防线的价值证明
```

## 2. 核心概念（中英对照+大白话）

| 英文 | 中文 | 大白话解释 |
|------|------|-----------|
| Launch Checklist | 上线检查单 | 五项全过才放行（不满足即整改） |
| Worst Case Assessment | 最坏损失评估 | 抽风场景的损失清单（答不出=没防护） |

```

  ① 工具/菜单变更 → ② 权限相关项必须回归（day12 三连重跑）

```

## 4. 面试连接

**Q：你的 Agent 项目怎么判断可以上线？（收口题，检查单是答案）**
> 我们有一张五项检查单，不过不放行，每项都挂实验证据而不是口头保证。第一项迭代上限：轮次按任务类型配置，重复检测在岗——证据是死循环实验的无刹车基线对比，装刹车后三四轮就熔断。第二项权限闸门：解析白名单、参数三查、归属校验、按角色菜单四层——证据是红蓝三连演练全拦截的记录。第三项预算熔断：Token 预算是按实测精算的，单轮均值乘轮次上限乘安全系数，误杀和虚设两个边界都验证过。第四项审计留痕：全量 trace 加工具审计，脱敏落库可回放——证据是留痕破案实验，一次描述 bug 从发现到定位只花了几分钟。第五项人工确认：退款这类高危操作全走两级审批，审批状态由应用侧管理，模型说用户同意了不算数。基于这五项，我可以正面回答那个验收级问题——模型抽风连调二十次工具，最坏损失是什么：查询工具只读没有业务损失，高危操作被审批闸拦死，重复检测让循环三四轮就停，最坏就是几轮的 token 钱加一次转人工——可控、可解释、可回放。另外检查单有维护纪律：工具变更权限项必回归，换模型全单回归，每月抽查防劣化。上线不是一次考试，是一套持续生效的门禁。
