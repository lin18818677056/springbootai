# Day 23 · 观测与全量留痕：能回放才能复盘

> **今日目标**：落地 agent_session 全量留痕（每轮思考/行动/观察进 trace）；写一个最小回放工具；用"故意埋 bug→靠留痕定位"实验证明留痕的价值；处理留痕的隐私与存储代价。
> **时长**：留痕落地 1.5h / 回放实验 1h / 输出 0.5h
> **今日产出**：trace 写入链路 + replay.ps1 回放脚本 + 一次"靠留痕破案"的记录
> **对照教程**：`ai-learning/05-Agent与MCP协议.md` 第 5 节风险表末行

## 1. 知识地图（先讲人话）

```
传统服务的排障靠日志：请求进出、异常堆栈。
Agent 的排障靠"回放"：它当时在想什么、想调什么、看到了什么——
  每一轮的 THINK/ACT/观察，就是案发现场的完整监控录像。

留痕三原则（设计 trace 时的铁律）：
  ① 全量：一轮都不少（day08 的 trace.record 种子今天收成果）
  ② 结构化：不是一坨文本，是 jsonb 里的结构（能查能统计）
  ③ 可回放：拿着 trace 能在测试环境"重演"这次会话
    ——用户投诉"它给我答错了"，你能还原当时的每一步判断

trace 的字段（能回答三个问题就是合格的留痕）：
  每轮记录：round / think / act / observation / tokens / latency_ms
  会话级：  intent / status / total_tokens / rounds
  三个问题：
    Q1 它为什么调这个工具？→ 看 think
    Q2 它看到了什么才这么答？→ 看 observation
    Q3 它卡在哪/为什么熔断？→ 看 status+最后一轮

隐私与脱敏（留痕的代价面）：
  思考链可能复述用户敏感信息（手机号/地址）
  → 落库前过脱敏（正则打码），保留"能看懂思路"的程度即可
  审计日志同理（day04 闸三的字段也要脱敏）

存储代价（诚实的账，M16 伏笔预埋）：
  一次多跳会话 trace 几十 KB；日千次会话=日增几十 MB
  方案：同步写会拖慢主链路 → 异步写（队列缓冲）
  更省：trace 采样（全量留 7 天，之后只留会话级摘要）
  ——这两条优化 M16 性能优化月会真做，今天先记坑
```

## 2. 核心概念（中英对照+大白话）

| 英文 | 中文 | 大白话解释 |
|------|------|-----------|
| Full Tracing | 全量留痕 | 每轮思考/行动/观察全记录（监控录像） |
| Session Replay | 会话回放 | 拿 trace 重演一次会话（案发还原） |
| Structured Trace | 结构化痕迹 | jsonb 存储，能查能统计（不是日志串） |
| PII Masking | 隐私脱敏 | 思考链落库前打码（PII=个人身份信息） |
| Async Write | 异步写 | 留痕不拖慢主链路（队列缓冲） |
| Debuggability | 可调试性 | 出问题能在 minutes 内定位到轮次 |

## 4. 面试连接

**Q：Agent 服务的可观测性怎么做？出问题怎么排查？（生产化必问）**
> 传统服务排障看日志，Agent 排障靠回放——它和传统服务最大的区别是中间过程是模型的判断，不留痕就永远不知道它为什么这么干。我的留痕三原则：全量，每一轮的思考、行动、观察都记，一轮不缺；结构化，存 jsonb 不是文本串，轮次、token、延迟都能查能统计；可回放，拿着 trace 能在测试环境重演整场会话。设计标准是能回答三个问题：它为什么调这个工具——看思考；它看到了什么才这么答——看观察；它为什么熔断——看状态加最后一轮。有个真实案例：工具考卷里库存类三题全军覆没，没有留痕时只能对着最终答案猜；回放思考链直接看到它写"没有找到适合查库存的工具，用知识库搜搜看"——一眼定位是工具描述写得太含糊，从发现到定位几分钟，这就是留痕的实锤价值。两个代价也要管：隐私上，思考链会复述用户敏感信息，落库前正则脱敏；存储上，多跳会话的 trace 几十 KB，同步写会拖慢主链路，我们异步写加采样——全量留七天、之后降级成会话级摘要。日报侧从会话表出四个信号：轮次分布、熔断率、工具成功率、token 分布，熔断率突增就是模型或工具出问题的第一报警。
