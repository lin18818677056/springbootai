# Day 08 · ReAct 循环：让模型先想后做

> **今日目标**：把 day02 循环里的"思考"从黑盒变成显式输出——这就是 ReAct（Reason+Act）；升级 MiniAgent 为 ReAct 版；体会思考显式化的三重收益（可调试/更准/可观测）。
> **时长**：理论 0.5h / 实操 2h / 输出 0.5h
> **今日产出**：ReActAgent.java（思考显式版）+ 前后对比记录 + 失败自愈案例一个
> **对照教程**：`ai-learning/05-Agent与MCP协议.md` 第 3 节

## 1. 知识地图（先讲人话）

```
ReAct = Reason（推理）+ Act（行动），教科书定义：
  思考 → 行动 → 观察 → 再思考 → …… → 最终答案
听起来就是 day02 的循环？差别在一个字：
  day02：模型直接输出行动（TOOL|queryOrder|...）——为什么调它？
  day08：模型先输出思考再输出行动——"用户想查物流，消息里有
        S 开头单号，符合 queryOrder 的使用条件，我调它"
  这一步"把想法说出来"，就是 R。

类比：新员工两种干活方式。
  默默干活（day02）：直接交结果——错了你不知道他怎么想的
  边想边汇报（ReAct）："我看了下这个需求，应该是 A 原因，
    我打算先查 X 再查 Y"——想错了一眼就能看出来！

思考显式化的三重收益（今天逐一验证）：
  ① 可调试：出错时回放思考链，一眼看到"它哪一步想歪了"
    （day23 全量留痕的基石——留的不只是动作还有想法）
  ② 更准：被要求先讲理由，模型被迫"过一遍脑子"，
    工具选择/参数填写质量都会提升（和人类一样：嘴比脑快就出错）
  ③ 可观测：思考摘要是日志里最值钱的一段——用户投诉时，
    你能还原"系统当时是怎么理解的"

代价（工程师要心里有数）：
  思考也是 token——每轮多花输入+输出 token；
  思考内容可能泄漏给用户（要在展示层过滤）；
  小模型的思考可能是"装样子"（先有结论再编理由）——
  别全信，考卷说了算（day06 的考卷现在派上第二用场）。
```

## 2. 核心概念（中英对照+大白话）

| 英文 | 中文 | 大白话解释 |
|------|------|-----------|
| ReAct | 推理-行动循环 | 先思考再行动再观察的循环模式（Agent 的经典款） |
| Chain of Thought | 思维链 | 把推理过程写出来（ReAct 的"R"就是它进循环） |
| Observation | 观察 | 工具结果回填历史（循环的第三步） |
| Thought Trace | 思考痕迹 | 每轮思考的记录（调试和审计的金矿） |
| Self-healing | 自愈 | 模型看到工具报错后自己改道重试（今天实战） |
| Post-hoc Rationalization | 事后合理化 | 小模型"先有结论再编理由"的毛病 |

## 3. 动手实操：MiniAgent 升级 ReAct 版

### 3.1 输出协议升级（一行变两段）

```
旧协议（day03）：TOOL|工具名|参数   或   ANSWER|答案
新协议（ReAct）：
  THINK: <一两句为什么>
  ACT: TOOL|工具名|参数      或      ACT: ANSWER|答案
应用侧只对 ACT 行动手，THINK 行进日志和审计（不执行任何东西！）
——注意：思考再"真诚"也不改变安全模型：执行权还是在应用侧
```

### 3.2 ReActAgent.java（关键改动 20 行）

```java
// ReActAgent.java —— 在 day02 骨架上升极
for (int round = 1; round <= MAX_ITER; round++) {
    String out = llm.chat(systemReActPrompt, history);   // 要求先 THINK 后 ACT
    String think = extractSection(out, "THINK:");        // 思考：只记录，不执行
    String act   = extractSection(out, "ACT:");          // 行动：解析执行
    trace.record(round, think, act);                     // 全量留痕（day23 的种子）
    if (act.startsWith("ANSWER")) { return emit(act, think); }
    String[] p = act.substring(5).split("\\|");
    ToolResult r = tools.invoke(p[0], p[1]);             // 三道闸在 invoke 里（day04）
    history.add("观察: " + r.forModel());                // 成功结果/结构化错误都回填
}
```

## 4. 面试连接

**Q：讲讲 ReAct，思考显式化有什么实际好处？（模式识别题）**
> ReAct 就是推理加行动的循环：模型每轮先输出思考——为什么下一步这么做，再输出行动——调什么工具带什么参数，应用侧执行后把观察结果回填，循环直到给出答案。它和我们默认的隐式循环的区别，就在把思考从黑盒变成显式输出。实际好处我实测过三个：第一是可调试，出了错回放思考链，一眼看到它哪一步想歪了，不用猜；第二是质量，被要求先讲理由，模型相当于被迫过一遍脑子，我们用同一份二十题工具考卷对比过，思考显式化之后选择正确率有提升；第三是自愈，最典型的案例：用户少打了订单号的 S 前缀，第一轮参数校验报错，思考链里模型自己反应过来"报错说缺 S，补上再试"，第二轮就查成功了——隐式循环下它要么放弃要么胡说。代价也要讲清楚：思考是额外 token，展示层要过滤别把内心戏漏给用户，而且小模型的思考可能是事后合理化，先有结论再编理由，不能全信，还是要靠考卷说话。安全模型不变：思考只是日志，执行权永远在应用侧。
