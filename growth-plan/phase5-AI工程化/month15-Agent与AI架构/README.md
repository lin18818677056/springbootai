# Month 15 · Agent 与 AI 架构：从"会聊天"到"会办事"

> **本月一句话**：给 M14 的知识库助手装上手脚——Function Calling 让模型会点菜、ReAct 让它会走一步看一步、MCP 让工具即插即用；同时学会架构师最重要的一课：知道什么时候**不该**用 Agent。
> **主参考**：`ai-learning/05-Agent与MCP协议.md`（本月的"教材"，README 和各 day 反复引用）
> **本月大项目**：项目五《智能工单助手 Agent 化》——把项目四的 RAG 问答升级为能查工单/查库存/（人工确认后）办退款的 Agent

## 一、本月目标（说完人话再说术语）

```
M14 结尾留了两笔账：
  ① 资料明明检索对了、塞进上下文了，模型还是答错/答偏/懒得用
     ——靠"喂资料"到头了。新思路：让模型自己决定"要不要查、查什么"。
  ② 多跳问题（"A 公司法人控股的 B 公司主营什么"）一次检索根本不够
     ——需要查了再查、走一步看一步。

这两笔账的答案就是 Agent（智能体）：
类比：新员工 + 工具箱。
  M14 的 RAG = 给新员工一本《公司手册》（只能翻书回答）
  M15 的 Agent = 给新员工一个工具箱+一张工单系统账号
    （能自己查系统、自己打电话、自己填表——但每一步都在你眼皮底下）

核心心法（教材三句本质，本月反复出现）：
  ① 模型不执行任何东西，只输出"调用意图"——执行权永远在应用侧
  ② Agent = LLM 做决策引擎 + 传统代码做手脚与安全带
  ③ 所有可靠性问题（死循环/幻觉参数/越权）都发生在循环里，
    也都在循环里防御

四个硬指标（月底逐条验收）：
  ① 工具选得对：多工具场景模型选择正确率 ≥80%（有考卷为证）
  ② 循环刹得住：人为造死循环，MAX_ITERATIONS+Token 预算能熔断
  ③ 参数信不过：幻觉参数/越权调用被服务端校验拦下
  ④ 工具能外接：项目四的工具包成 MCP Server，生态宿主可调用
```

## 四、环境准备（延续 M14，无新增安装）

```
已有（M13/M14 装好的）：Ollama + qwen2.5:7b / nomic-embed-text、PGVector、项目四全套
本月正路径：Ollama /api/chat 原生 tools 字段（qwen2.5 系支持 function calling 模板）
本月降级路径（诚实记录）：
  tools 输出不稳/格式漂移 → 手写"JSON 意图协议"兜底：
    Prompt 里约定模型只输出 {"tool":"...","args":{...}} 或 {"answer":"..."}
    ——教学价值反而更高：亲手解析一遍，Function Calling 的本质就看穿了
MCP 教学版：手写 JSON-RPC 模拟协议交互（day17），Spring AI MCP starter 作为
  延伸（有网络依赖时降级，不阻塞主线）
```

## 六、本月心法

```
三句大白话（面试和实操都靠它们定调）：
  ① 模型不干活只点菜：执行权永远在应用侧——这是安全模型的根，
    权限校验/参数校验/审计日志全部长在应用侧，不信任模型任何自述
  ② 所有可靠性问题都发生在循环里，也都在循环里防御：
    死循环→迭代上限；幻觉参数→白名单校验；越权→服务端权限；
    烧钱→Token 预算熔断
  ③ 知道什么时候不该用 Agent，比会用 Agent 更值钱：
    单 Agent+好工具能解决的，别上 Multi-Agent（每加一个 Agent，
    延迟/成本/调试难度都乘上去）
```
