> **今日目标**：对拍方法论第七次上场——先给模型的工具选择能力出考卷（20 题五类型），建"选择正确率"基线；跑出 v0 数字；用 day05 的描述优化做第一次对拍（台账第一行）。
> **时长**：出卷 1h / 实测 1.5h / 输出 0.5h
> **今日产出**：工具选择考卷 20 题 + eval_tool.ps1 骨架 + v0 基线与第一行台账
> **对照教程**：`ai-learning/05-Agent与MCP协议.md` 第 2 节
> **方法论血缘**：M8 压测基线 → M14 检索考卷 → 今天工具考卷（第七次）

## 1. 知识地图（先讲人话）

```
昨天证明了"描述影响选择"，今天把这件事变成可测量的工程：
  没有考卷的优化叫玄学，有考卷的优化叫台账。

对拍老配方（第七次，闭着眼都能背了）：
  ① 出考卷：20 题，每题标注"标准答案"（应该调哪个工具）
  ② 定指标：选择正确率 = 选对工具的题数 / 总题数
    （先只考"选没选对"，参数对不对 day12 再考——一次只量一件事）
  ③ 跑基线：v0（day05 好描述版）先量出数字
  ④ 改一变量 → 再量 → 台账记一行

考卷五类型（照抄 M14 检索考卷的分类学）：
  ① 明确办事型（6 题）：带单号查物流 → queryOrder
  ② 政策知识型（5 题）：退款多久/发票怎么开 → queryPolicy(RAG)
  ③ 库存查询型（3 题）：XX 还有货吗 → queryStock
  ④ 高危操作型（3 题）：我要退款 → processRefund（必须带人工确认）
  ⑤ 陷阱型（3 题）：闲聊/投诉/不含单号的模糊问 → 不该调任何工具
    （陷阱题是照妖镜——day05 坏描述的误触发就栽在这里）

本月优化台账（和 M14 台账同款格式，今天开张）：
  版本 | 改了什么                     | 选择正确率
  v0   | 好描述版四工具（day05 成果） | __%（今天填）
  v1   | 动态挂载（分类器先判域）     | __%（day22 项目五再做）
```

## 2. 核心概念（中英对照+大白话）

| 英文 | 中文 | 大白话解释 |
|------|------|-----------|
| Tool Selection Accuracy | 工具选择正确率 | 考卷里选对工具的比例（本月主指标） |
| Trap Questions | 陷阱题 | 不该调工具的题（照出"手痒"的模型） |
| Ablation | 消融实验 | 一次只改一个变量，看指标动不动（老规矩） |
| Baseline | 基线 | 优化前的数字（没有它，优化无从谈起） |
| False Trigger | 误触发 | 不该调的时候调了（陷阱题抓的就是它） |
| Miss | 漏调 | 该调的时候没调（用户白问一轮） |

## 3. 动手实操：出卷与实测

### 3.1 考卷格式（eval/tool_exam.jsonl，每行一题）

```
{"id":"T01","type":"order","q":"订单 S20260912003 到哪了？","expect":"queryOrder"}
{"id":"T07","type":"policy","q":"退款多久能到账？","expect":"queryPolicy"}
{"id":"T15","type":"trap","q":"你们这服务也太差了吧","expect":"NONE"}
{"id":"T18","type":"refund","q":"订单 S202609120037 我要退款","expect":"processRefund"}
…（共 20 行，五类型配比 6/5/3/3/3）
```

### 3.2 eval_tool.ps1 骨架（M14 eval_retrieval.ps1 的兄弟版）

```powershell
# 读考卷 → 逐题带四工具菜单调模型 → 解析意图 → 对比 expect → 统计
# 输出一张成绩单：
#   总正确率 __% | 各类型：order __% policy __% stock __%
#               refund __% | trap（误触发率）__%
# □ 陷阱题单独看：误触发率是"手痒程度"，和正确率一样重要
#   （正确率 90% 但陷阱全灭 = 见题就调 = 生产上全是无效查询）
```

## 4. 面试连接

**Q：你怎么保证模型能选对工具？选错了怎么办？（多工具核心题）**
> 老规矩，先有考卷再谈优化。我给模型的工具选择能力出了一份 20 题的考卷，五种类型：带单号的办事题、政策知识题、库存题、退款这种高危操作题，还有三道陷阱题——就是不该调任何工具的闲聊和投诉，专门抓"手痒"。指标两个：选择正确率抓漏调，陷阱误触发率抓乱调，两个一起看才完整——正确率再高，陷阱题全灭也说明它见题就调，生产上全是无效查询。基线测出来后，我的第一轮优化不动代码，只改工具描述：加何时用的场景约束、加不该用的负向约束、参数格式带例子，正确率就有可观提升——这证明工具描述本身就是提示词工程的一部分。后续的招是动态挂载：工具多了选择就糊，我们用 M13 就做好的意图分类器先判业务域，每次只把相关的三五个工具挂给模型。实在选错的兜底是代码侧的白名单和参数校验，选错了至少不会执行出事。整套思路和做检索优化时一模一样：先量、再改、改完再量，一次只动一个变量。
