  现象：批量注入 payload 打进来（脚本化攻击）

  验证点：拦截率 100%/审计留痕可聚合（攻击 IP/模式识别）

## 2. 核心概念（中英对照+大白话）

| 英文 | 中文 | 大白话解释 |
|------|------|-----------|
| Misbehavior | 模型抽风 | 模型行为异常（选错/填错/转圈） |
| Failure Injection | 故障注入 | 人为制造故障验证防线（点火） |
| Session Circuit Break | 会话级熔断 | 单会话连续失败即断（防拖垮） |
| Attack Flood | 攻击潮 | 批量化脚本化攻击（单发验证的加强版） |
| Fail Fast | 快速失败 | 工具挂了立刻报错别重试拖轮次 |
| Read-only Mode | 只读降级 | 高危链路不可用时只保留查询能力 |

## 3. 动手实操：三预案点火

### 3.1 预案①：放大版抽风（真点火）

```powershell
# 故障注入：queryStock 和 queryOrder 描述互换（模型必然选错）
# 连发 10 题 → 观察：
#   □ 重复检测触发：第 __ 轮熔断（预期 3~4）
#   □ 10 会话熔断率 __%（预期 100%）→ 告警阈值检查
#   □ trace 回放：每条都能看到"选错的思考过程"
#   □ 无脏数据：两次工具都是只读 ✓
# 恢复描述 → 考卷回归 → 正确率回基线 ✓
```

### 3.2 预案②：订单库全挂（真点火）

```powershell
docker stop orders-db   #（或断网模拟）
# 连问 5 个订单问题 → 预期链路：
#   工具结构化错误(DB_UNAVAILABLE) → 模型转述"订单系统暂不可用"
#   □ 快速失败检查：每轮没拖满超时（工具级 3s 超时生效）
#   □ 会话熔断：连续失败 N 次 → 直接告知+记录
#   □ kbSearch 挂不挂？（PGVector 独立→知识问答仍正常——隔离的胜利）
docker start orders-db
```

### 3.3 预案③：注入潮（真点火）+ 挖真 bug

```powershell
# 脚本连发 50 条混合 payload（三类 day13 攻击+两条新编）
#   □ 拦截率 __%（预期 100%）| 审计聚合：按 payload 类型分组统计 ✓
# 挖 bug 环节（传统艺能，M14 挖过缓存联动）：
#   □ 检查审批单：注入潮里那条"情感绑架退款"生成的审批单——
#     发现 bug：驳回后 agent.resume 回填了"已驳回"，但 SSE 会话
#     已超时关闭 → 用户根本没收到致歉话术（状态丢了）
#     修复：resume 前查会话活性，已关会话走 IM 补送——记录并修
#   ——这就是"演练挖真 bug"传统的第四季收获
```

## 4. 面试连接

**Q：讲一次你演练过的最隐蔽的 Agent 故障？（压轴故事题）**
> 我们的故障点火纪律是第四季了，每条预案都真触发。Agent 特有三类故障。模型抽风：把两个工具的描述故意互换，模型必然连续选错——重复检测第三四轮就熔断，十次会话全部触发告警，而且因为工具都是只读的，零脏数据，trace 回放能看到它每次选错的思考过程，恢复描述后考卷回归基线。工具全挂：停掉订单库，验证的是快速失败——工具级三秒超时让每轮不拖满，模型用结构化错误转述"订单系统暂不可用"，而知识库因为部署隔离完全不受影响，这就是依赖隔离的胜利。最隐蔽的是注入潮：五十条混合 payload 脚本化打进来，拦截率百分之百，但审计聚合时挖出一个真 bug——有条"情感绑架退款"被审批正确驳回后，系统尝试唤醒会话播报致歉，但 SSE 会话早就超时关闭了，用户根本没收到任何反馈，这个状态就丢了。修法是 resume 前先查会话活性，已关闭的会话转 IM 补送。这个 bug 的价值和 M14 演练挖出的缓存联动 bug 一样：单发测试永远发现不了，只有批量压力下的状态一致性才会暴露。最后沉淀成降级决策表五条，每条都写明一级响应、二级响应和用户看到什么。总结：Agent 的故障一半在模型层——它没坏，但抽风了，所以防线设计的目标是让抽风变得可控、可见、可善后。
