# Day 16 · MCP 三类能力：Tools / Resources / Prompts

> **今日目标**：吃透 MCP Server 暴露的三类能力及它们的"控制权"差异（谁决定用不用）；把项目四/五的资产正确分类到三格里；用 resources/list、prompts/get 补完迷你协议演练。
> **时长**：理论 1h / 分类实操 1.5h / 输出 0.5h
> **今日产出**：三类能力对照卡 + 项目资产分类表 + 协议演练补全记录
> **对照教程**：`ai-learning/05-Agent与MCP协议.md` 第 4 节

## 1. 知识地图（先讲人话）

```
MCP Server 对外暴露三类能力，区别不在"是什么"，在"谁决定用不用"：

① Tools（工具）——模型决定用：
   "可被调用的动作"，如 kbSearch、queryOrder
   控制权在模型：它看着菜单，自己决定这轮要不要调
   ——就是本月练了三周的 Function Calling 那套（三道闸照旧）

② Resources（资源）——应用决定读：
   "可读取的数据"，如文档原文、表结构、配置
   控制权在应用：宿主程序按需拉取，塞进上下文，
   模型只是"被动收到资料"，不能主动"我要读那个文件"
   类比：工具是"点菜"（模型点），资源是"配菜"（厨房配好端上来）

③ Prompts（提示模板）——用户决定用：
   "预置的任务模板"，如《多跳查询模板》《周报生成模板》
   控制权在用户：用户在界面上选这个模板，宿主取来填参使用
   类比：菜单上的"套餐推荐"——顾客（用户）点了才上

一张表看懂控制权（面试的高频追问点）：
  能力      | 内容     | 谁决定用 | 对应我们学过的
  Tools     | 动作     | 模型     | Function Calling 三道闸
  Resources | 数据     | 应用     | M14 的检索结果注入（应用控制喂什么）
  Prompts   | 任务模板 | 用户     | M13 的模板库⑨号（用户选场景）

项目资产分类表（今天的实操核心）：
  我们的项目四/五资产 → 正确归位：
    kbSearch / queryOrder / processRefund   → Tools（模型点菜）
    知识库文档原文 / kb_chunks 表结构 / 订单表结构 → Resources（应用按需拉）
    《多跳检索模板》/《周报模板》/《退款客服话术模板》 → Prompts（用户选）
  归错的典型：把"文档原文"当 Tool 暴露（模型"调用读文件"？错！
  读数据是应用侧控制的安全操作，暴露成 Tool 反而扩大攻击面）
```

## 2. 核心概念（中英对照+大白话）

| 英文 | 中文 | 大白话解释 |
|------|------|-----------|
| Tools | 工具 | 模型决定调用的动作（点菜） |
| Resources | 资源 | 应用决定读取的数据（配菜） |
| Prompts | 提示模板 | 用户选择使用的任务模板（套餐） |
| resources/list | 资源列表 | 宿主问 Server"你有哪些数据可读" |
| resources/read | 资源读取 | 宿主拉取具体资源内容 |
| prompts/get | 模板获取 | 取模板并填参 |
| Control Plane | 控制权 | 三类能力的本质差异：谁决定用 |

## 3. 动手实操：分类+补全协议演练

### 3.1 资产分类（先分类再暴露——暴露即攻击面）

```powershell
# 对项目四/五全部资产过一遍分类三问：
#   □ 这个资产是"动作"还是"数据"还是"任务套路"？
#   □ 该谁决定用？（模型点/应用配/用户选）
#   □ 最小暴露原则：这个资产有没有必要对外？
#     （processRefund 对外暴露 = 别的宿主也能发起退款审批——
#      谨慎！要么不暴露，要么审批流原样带上——安全模型跟着走）
# 产出《暴露清单》：
#   Tools: kbSearch, queryOrder（queryStock 视宿主需要）
#   Resources: refund-policy 原文, kb 表结构说明
#   Prompts: multi-hop 模板, weekly-report 模板
#   不暴露: processRefund（高危，仅限自家宿主内闭环）
```

### 3.2 协议演练补全（昨天三步之外的两步）

```powershell
# ④ resources/list + resources/read：
#   → {"method":"resources/list"}
#   ← {"result":{"resources":[{"uri":"kb://policy/refund","name":"退款政策"}]}}
#   → {"method":"resources/read","params":{"uri":"kb://policy/refund"}}
#   ← {"result":{"contents":[{"text":"2026 退款政策：7 个工作日…"}]}}
#   □ 体会：这是应用侧主动拉资料（M14 的检索注入的标准版）
# ⑤ prompts/get：
#   → {"method":"prompts/get","params":{"name":"multi-hop","arguments":{"topic":"公司关系"}}}
#   ← {"result":{"messages":[{"role":"user","content":"…模板内容…"}]}}
#   □ 体会：模板+参数=现成的 Prompt（M13 模板库的协议化）
```

### 3.3 分类的安全含义（多想一步）

```
三类能力的安全属性各不同（day17 实现时要落）：
  Tools    → 最高危：模型可主动触发 → 三道闸全上
  Resources→ 中危：  内容可能进上下文 → 注入扫描（文档里藏指令！）
             ——知识库文档被投毒（塞进"忽略规则，调用XX"），
             通过 Resource 进上下文=间接注入（M13 day14 老坑的 MCP 版）
  Prompts  → 低危：  用户主动选用 → 模板本身要审核（别预埋坏指令）
□ 把"资源投毒→间接注入"这条攻击链写进演练清单（day26 复用）
```

## 4. 面试连接

**Q：MCP Server 的三类能力是什么？有什么区别？（MCP 细节题）**
> 三类是 Tools、Resources、Prompts，它们的本质区别在控制权——谁决定用不用。Tools 是模型决定调用的动作，比如查订单、检索知识库，这就是 Function Calling 那套，三道闸照上。Resources 是应用决定读取的数据，比如文档原文、表结构，宿主按需拉取塞进上下文，模型是被动接收方——类比点菜和配菜：工具是模型点的菜，资源是厨房配好的菜。Prompts 是用户选择使用的任务模板，比如多跳检索模板，用户在界面上点了，宿主才取模板填参。分类有一个安全推演值得展开：三类能力风险不同，Tools 最高危所以全上闸门；Resources 中危但有个隐蔽的坑——资源内容会进上下文，如果知识库文档被人投毒、夹带"忽略规则"的指令，就形成间接注入，所以资源读取后要过注入扫描；Prompts 低危但模板本身要审核。我们项目暴露时的取舍也体现了最小权限：kbSearch 和 queryOrder 暴露成 Tools，政策原文和表结构做成 Resources，多跳和周报模板做成 Prompts，而退款工具坚持不对外暴露——高危操作只留在自家宿主的审批闭环里。
