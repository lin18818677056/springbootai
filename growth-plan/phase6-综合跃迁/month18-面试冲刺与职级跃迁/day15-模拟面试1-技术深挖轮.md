# Day 15 · 模拟面试 1：技术深挖轮

> **今日目标**：五轮模拟面试第一轮——60 分钟全真技术深挖（自我介绍→项目深挖→八股抽查→反问环节），AI 面试官人设"深挖型"，全程录音。
> **时长**：模拟 60min / 复盘 2h / 输出 0.5h
> **今日产出**：第一轮模拟录音 + 逐题评分表 + 弱点清单 v1

## 1. 知识地图（先讲人话）

```
技术深挖轮是什么（先讲人话）：
  像体检里的"抽血"——用一道道深挖题，
  抽出你知识的真实浓度。
  面试官人设"深挖型"：不聊虚的，抓着你简历上一行字
  连问四层（day12 的下钻链就是为今天准备的）。

60 分钟标准结构（各环节时间写死，防跑偏）：
  00~05  自我介绍（60 秒版！不是 3 分钟流水账）
  05~15  挑一个项目深挖（面试官从简历随机挑——
         所以六条 STAR 都要能扛）
  15~35  八股抽查 8 题（JVM/并发/MySQL/Redis/MQ 各抽）
  35~50  场景题 1~2 道（排查类：CPU 飙高/OOM/慢 SQL）
  50~57  反问环节（3 个问题提前备好——这也是考点！）
  57~60  面试官收尾客套（此时不问结果，礼貌收场）

今天的独特目标（和三场演练的区别）：
  演练考"设计能力"，本轮考"底盘扎实度"——
  八股抽查+场景排查是主菜。
  通关线：8 道八股 ≥6 道答到"四段模板"完整；
  场景题能按"排查流程"走而不是"背结论"。

反问环节的三问（提前背好，顺序有讲究）：
  问 1（业务向）："团队现在最需要解决的技术问题是什么？"
    ——让面试官讲，你在收集情报+展示关注点
  问 2（成长向）："这个岗位前三个月做什么会被认为
    超出预期？"
    ——暗示你已经在想入职后的事
  问 3（收尾向，视气氛）："以我的背景，您觉得我还需要
    补哪块？"——谦虚+直接要反馈，多数面试官会给真话
  不问：薪资（谈薪轮才谈）、加班（HR 轮再问）、
  百度能查到的公司信息（显得没做功课）
```

## 2. 核心概念（中英对照）

| 英文 | 中文 | 大白话 |
|------|------|--------|
| Deep Dive | 深挖 | 顺着你简历的一行字往下打四层——考真伪 |
| Behavioral Question | 行为面试题 | "讲一次你…的经历"——STAR 结构的用武之地 |
| Reverse Question | 反问 | 面试最后的双向选择环节——态度+情报收集双功能 |
| Think Aloud | 出声思考 | 排查题的灵魂：把推理过程说出来（过程分 > 结果分） |
| Red Flag | 红旗信号 | 面试官的扣分点：贬低前雇主/不懂装懂/答非所问 |

## 3. 动手实操（60 分钟全真模拟）

### 3.1 演练一：全真模拟（录音，严格计时）

```
准备（10 分钟仪式，day14 定的）：
  ① 重读昨天的改进点 ② 深呼吸 ③ 60 秒自我介绍热嘴
面试官人设卡（贴屏幕上，回答时想象 TA 在对面）：
  深挖型面试官·张工：15 年后端，话少，每个回答
  必追 1~2 层，不微笑，会突然打断："这块展开讲讲"
题本（从下面随机抽，不提前看答案）：
  自我介绍后，面试官动作序列：
  ① 从六条 STAR 随机点一条："详细讲讲这个项目"
    → 追问链 L2~L4（day12 的下钻剧本）
  ② 八股抽查 8 题（题池）：
    JVM：G1 和 ZGC 怎么选？/ 线上 Full GC 频繁排查？
    并发：ThreadLocal 内存泄漏？/ 线程池参数怎么定？
    MySQL：RR 隔离级别怎么解决幻读？/ 慢 SQL 排查？
    Redis：缓存三兄弟+方案？/ 大 key 怎么处理？
    MQ：消息丢失三段论？/ 消费幂等怎么做？
    （每题 90 秒上限，按四段模板：结论/原理/案例/边界）
  ③ 场景题（挑 1 道）：
    "线上服务突然大量超时，你怎么办？"
    ——要求 Think Aloud：先看什么/再看什么/为什么
  ④ 反问环节：三问按序出
```

### 3.2 演练二：逐题复盘（对照录音，答完立刻做）

```
评分表（每题一行）：
  题号 | 题目 | 四段完整? | 卡壳点 | 时间 | 追问存活?
  评分口径：✓ 完整 / ○ 缺一段 / × 散架
三个专项检查（听完录音再填）：
  ① 结论先行了吗？（数每题第一句是不是结论——
    还是先绕了 20 秒背景才到重点）
  ② 案例绑定了吗？（"我在 XX 项目里…"出现几次？
    八股题没案例 = 八股选手信号）
  ③ 被打断时什么反应？（慌乱重讲 / 接住继续 /
    请面试官明确问题——复盘你每次被打断的表现）
输出：弱点清单 v1（× 和 ○ 的题全部列入，标注对应
  月度文档——明 day16 按单抓药）
```

### 3.3 演练三：48 小时修复承诺

```
把弱点清单 v1 做成"药方"（明 day16 的课程表）：
  排序公式（沿用 day07）：出现频率 × 卡壳程度
  每道弱点题配"修复动作"：
    例：Full GC 排查题卡在 GC 日志解读 →

  纪律延续：一天最多补 5 题（day04 立的规矩）
```

### 3.4 思考题

为什么自我介绍只要 60 秒，而不是把简历念一遍 3 分钟？（提示：自我介绍的功能不是"介绍"，是"递钩子"——给面试官一个最想深挖的点，主动把面试引向你的主场。3 分钟流水账 = 把选题权全交给面试官，他可能挑你最弱的一段打。60 秒版结构：我是谁（一句话）+ 最亮的两个数字（P99 优化/AI 客服解决率）+ 我想找什么（和贵司岗位的连接点）。面试的前 5 分钟你就该开始"带节奏"——这和系统设计题先澄清需求定框架，是同一个主动权思维。）

## 4. 面试连接

**Q：请用一分钟介绍一下自己。（每场面试的第一题，示范）**
> 面试官您好，我是 XXX，7 年 Java 后端，最近两年主要做两件事：一是高并发性能优化——把一个秒杀系统的接口 P99 从 800 毫秒压到 480 毫秒，靠的是锁粒度、SQL 和线程池三条线的系统调优，不是单点 magic；二是 AI 工程落地——主导了 RAG 知识库和 Agent 客服两个项目，咨询解决率 78%，配套建了完整的评测考卷和安全护栏。我今天应聘这个岗位，是因为看到 JD 里的高并发场景和我们做过的高度匹配，也想把 AI 工程化的经验带到更大的业务里。（→60 秒：两个数字+一个连接，钩子已下，等面试官上钩）

**Q：（场景题示范）线上服务突然大量超时，你怎么办？（Think Aloud 完整版）**
> 我按"先止血再找根因"的顺序来。第一步看监控大盘三样东西：时间相关性（是不是刚发过版）、范围（单个接口还是全部）、资源水位（CPU/内存/GC/下游 RT）。假设看到是发布后开始的、单接口超时、下游 RT 飙高——我会先回滚止血，因为止损优先于定位（M6 应急 SOP）。止血后复盘根因：看链路追踪确认是下游哪个服务慢，再看是它代码问题还是容量问题。如果监控显示不是发布相关，比如是数据库连接池打满，那方向就是慢 SQL 或流量突增，用 explain 和访问日志定位。整个过程的要点是：每一步都有判断依据，不是"重启试试"。（→排查题的得分点在"决策树"，不在答案）
