> **今日目标**：第三场演练——"设计一个 AI 智能客服平台"，练"AI 类"题型（三线并行骨架）；这是你的差异化主场，目标是把 M13~M15 的资产讲成体系而非项目罗列。

## 1. 知识地图（先讲人话）

```
AI 类设计题和传统题的本质区别（先讲人话）：
  传统系统像自动售货机：投币→出货，结果 100% 确定
  AI 系统像新员工：能干活，但偶尔胡说、每句话都花钱、
    培训（调 prompt）效果要考过试才知道
  所以 AI 题的评分重点是"你有没有管新员工的制度"：
  ┌────────────────────────────────────────┐
  │ 效果线：怎么知道它答得对？（考卷三张/双指标/    │
  │         对拍——M14 方法论）                  │
  │ 安全线：怎么防止它闯祸？（注入拦截/工具三道闸/  │
  │         两级审批/全量留痕——M15 四层纵深）      │
  │ 成本线：怎么防止它烧钱？（TOKEN_BUDGET/单会话  │
  │         熔断/烧钱曲线——M13~M15 三本账）       │
  └────────────────────────────────────────┘
  多数候选人只讲效果线（RAG 准确率），
  三线齐讲 = 直接和 90% 的候选人拉开差距

你的主场优势盘点（别的候选人有，你没有的没有）：
  ✓ 真实数字：解决率 78%/MRR+30%/注入拦截 100%
  ✓ 真实踩坑：描述优化修 bug/会话活性 bug/成本熔断
  ✓ 方法论抽象：同构表 v8/对拍八次/三不信任原则
  ✓ 诚实边界：每份材料都有"未达清单"——
    这反而是最高级的加分项（面试官最怕听完美故事）
```

## 2. 核心概念（中英对照）

| 英文 | 中文 | 大白话 |
|------|------|--------|
| RAG | 检索增强生成 | 开卷考试：先翻资料再答题，减少胡编 |
| ReAct | 推理+行动循环 | 想一步做一步的循环：思考→调用工具→看结果→再想 |
| Guardrail | 护栏 | 给 AI 装的"刹车"——三层刹车（轮数/预算/敏感操作） |
| Evaluation Harness | 评测框架 | 给 AI 出的"考卷"——改任何东西先跑考卷再上线 |
| Human-in-the-loop | 人机协同 | 高危决策留给人的"终审权"——AI 建议人拍板 |

## 3. 动手实操（45 分钟全真演练）

### 3.1 演练一：限时实战（录音）

```
题目："为一个日咨询量 50 万的电商平台设计 AI 客服：
  覆盖售前咨询+售后办理（查订单/退款/改地址），
  要求答得准、不闯祸、成本可控。"

六步法走位（AI 版）：
  ① 需求澄清（5min）：
    关键分桶：咨询类（RAG 就够）vs 办理类（必须 Agent+工具）
    ——这一分桶是整个设计的地基（M14→M15 的演进逻辑）
    非功能：答案准确率目标？危险操作零容忍？
    成本约束：单会话预算上限（先问！AI 题不问成本=外行）
    现状：客服中心 78% 咨询是重复问题（开场就给数字）
  ② 容量估算（5min）：
    50 万/天 ≈ 6 QPS 均值，峰值 10 倍
    TOKEN 账：单会话平均 8 轮 × 2000 token × 单价 →
      日成本估算 + 熔断上限（M15 三本账的口径）
    向量库规模：知识条目 10 万 × 768 维 ≈ 300MB ——
      毫无压力（展示你敢说"这里不需要复杂方案"）
  ③ API（5min）：
    会话接口（流式返回）+ 工具注册接口（MCP 治理）+
    考卷管理接口（评测也是一等公民！）
    亮权衡：同步返回 vs 流式——客服场景流式是体验刚需
  ④ 数据模型（5min）：
    知识库：原文+切片+向量+元数据（版本号！知识也会更新）
    会话表：全量留痕（输入/检索结果/工具调用/输出——
      可回放=可审计=安全线的地基）
    工具注册表：声明+权限级别+调用配额（M15 五条军规）
  ⑤ 架构图（15min，三线一起画）：
    效果线：用户问题→混合检索（关键词+向量）→重排→
      生成（引用溯源）→（办理类）ReAct 循环+工具调用
    安全线：输入侧注入检测→生成侧敏感词→动作侧三层
      刹车（轮数/预算/高危两级审批）→全量留痕
    成本线：会话级 TOKEN_BUDGET→超限熔断→降级到
      FAQ 直出→成本大盘日报
  ⑥ 权衡演进（10min）：
    瓶颈 1：检索质量天花板 → 混合检索+重排（M14 数据：
      MRR+30%）→ 更进一步 Agentic RAG（主动点出）
    瓶颈 2：幻觉 → 检索增强+考卷回归+置信分层
      （低置信转人工，不硬答）
    成本演进：小模型初筛+大模型精答的分级调用
    诚实边界：解决率 78% 意味着 22% 转人工——
      转人工的识别准确率是下一个要攻的山头
```

### 3.2 演练二：双向评分

```
自评分表（通用五项 + AI 专属三项）：
  □ 咨询/办理分桶了（RAG vs Agent 的地基）
  □ 主动问了成本约束（不问成本=外行信号）
  □ 三线并行都讲了（效果/安全/成本）
  □ 每条线都有数字背书（78%/MRR+30%/拦截 100%）
  □ 讲了"拦完之后"（留痕/回放/审计）
  □ （AI 专属）考卷/评测作为一等公民出现在架构图里
  □ （AI 专属）诚实未达至少一条（22% 转人工）
  总分 ≥20 = P7 信号；15~19 = P6 稳；<15 = 复盘加练

AI 面试官追问三轮：
  Q1"Agent 循环失控怎么办？"
    → 三层刹车：轮数上限/预算熔断/敏感操作两级审批；
      全量留痕可回放；测试期演练挖出过会话活性 bug
      （真踩坑故事，M15）
  Q2"RAG 答错了怎么发现？用户先骂了才知道就晚了"
    → 三张考卷持续回归（改动必跑）+ 线上引用覆盖率
      监控 + 用户点踩回流进考卷（闭环）
  Q3"为什么自己搭 RAG 不直接用现成产品？"
    → 五步骨架（day05）：数据主权+定制检索是刚需；
      代价是工程量大；缓解是评测框架复用；
      演进口：知识规模小且无定制的团队直接用 SaaS
```

### 3.4 思考题

为什么 AI 类设计题"先问成本约束"是行家信号？（提示：传统系统算力成本近似固定（一台机器跑一万次和一百万次差别是容量问题），AI 系统成本和调用量线性相关（每次调用都烧 token）——成本从"运维问题"变成了"架构约束"。面试官用这个问题筛"只玩过 demo 的人"和"扛过生产成本的人"：前者脱口而出"用最好的模型"，后者第一句是"预算多少、单会话上限多少、什么场景可以降级"。你 M15 的三本账和 TOKEN_BUDGET 就是这个信号的弹药。）

## 4. 面试连接

**Q：设计一个 AI 客服系统，你会怎么开始？（AI 岗必考开场，2 分钟版）**
> 我会先做两个分桶再谈架构：第一桶分"咨询 vs 办理"——咨询类 RAG 检索增强就够了，办理类（查订单退款）必须上 Agent+工具调用，两者的风险等级完全不同；第二桶分"成本约束"——我会先问单会话预算上限，因为 AI 系统成本和调用量线性相关，这是架构输入不是优化项。然后我按三条线设计：效果线用混合检索+引用溯源+考卷回归（我们实测 MRR 提升 30%，引用覆盖率 95%）；安全线四层纵深，工具全过三道闸，高危操作两级审批，注入拦截 100%；成本线 TOKEN_BUDGET+单会话熔断+降级到 FAQ。上线效果是咨询解决率 78%，剩下 22% 识别转人工——这个数字我不藏，转人工的识别准确率是我正在攻的下一个山头。（→数字+权衡+诚实边界三件齐活，2 分钟立住"扛过生产"的形象）

**Q：怎么防止大模型胡说八道？（幻觉治理，高频）**
> 我的框架是"三层防御+一个闭环"：第一层检索增强——让模型开卷答题而不是裸背，引用溯源让每句话可查出处；第二层评测对冲——幻觉无法根除但可以度量，我们建三张考卷，改任何 prompt 或模型先跑考卷，正确率降了就不上线；第三层置信分层——低置信问题不硬答，转人工，宁可说"这个问题我需要人工帮您确认"也不编一个答案。闭环是用户反馈回流：点踩的问答进考卷，成为下一轮回归的用例。核心观点：幻觉治理不是把模型变完美，是建立"发现不完美的机制"——这也是 AI 工程和传统工程最大的思维差异。
