# Day 02 · 简历 STAR 改写与三层追问

> **今日目标**：把 day01 的骨架精修成简历级 STAR——每条过"三层追问测试"；学习简历写作的六条军规（动词/量化/归属/密度/诚实/匹配）。
> **时长**：改写 2h / 追问测试 1h / 输出 0.5h
> **今日产出**：六条简历级 STAR + 三层追问记录表 + 个人简历六军规

## 1. 知识地图（先讲人话）

```
简历 STAR 的三层追问测试（每条必须全过）：
  第一层"是什么"：数字/术语经得起解释吗？
    （"解决率 78%"→口径能秒答）
  第二层"为什么"：动作的取舍能讲出理由吗？
    （"为什么用 ReAct 不用 Plan-and-Execute"→day15 选型逻辑）
  第三层"还能怎样"：局限与演进路径能讲吗？
    （"这方案还有什么问题""流量×10 怎么办"→承认边界+给路径）
  一条 STAR 过不了第三层，就在简历上降格——
    把"主导"改成"参与"，或干脆删掉。

简历六军规：
  ① 动词开头，删"参与/协助/负责"这类没有信息量的词
    （负责=什么都没说；主导/设计/落地/治理=有分量）
  ② 每条必带一个数字（没数字的条目就是没做透）
  ③ 归属诚实（决策写主导，执行写实现——day01 的算法）
  ④ 一页纸纪律（3~5 年经验一页足够，两页=没提纯）
  ⑤ 每个项目配"一句话版本"放最前（10 秒筛简历的救命符）
  ⑥ 匹配度改写（JD 要什么，你的 STAR 就把对应关键词
    往前提——同一件事换个讲法，不是造假）

反面教材（多数 7 年简历的样子）：
  "负责订单系统的开发和维护，参与了秒杀活动的支持工作。"
  → 改后："主导秒杀链路 Redis+MQ 改造，5000 并发压测零超卖，
    库存热点分桶方案设计者。"
```

## 2. 核心概念（中英对照）

| 英文 | 中文 | 大白话 |
|------|------|--------|
| Keyword Match | 关键词匹配 | 简历机筛（ATS）按 JD 关键词打分——用 JD 的原词 |
| Bullet Point | 条目 | 简历正文以短条目呈现，每条一个动作一个结果 |
| Impact-first | 结果先行 | 每条条目把数字放前面或最后（视觉锚点） |
| Verifiable | 可验证 | 写上去的东西都有证据（博客/文档/代码/日报） |
| Tailoring | 定制化 | 对不同公司微调简历重点——一份简历投所有公司=不用心 |

## 3. 动手实操（演练）

### 3.1 演练一：六条 STAR 的简历级改写

```
改写示范（骨架→简历条目，注意压缩比）：
  骨架版（day01，60 字）：
    "S:知识库只能答问题不能办事…A:ReAct 循环+三层刹车+三道闸…"
  简历版（35 字，两行）：
    "·主导 AI 客服 Agent 架构（ReAct+三层刹车+MCP 工具治理）：
     咨询解决率 78%，注入拦截 100%，单会话成本熔断可控"
  改写动作清单：
    ① 删背景句（背景留给面试讲，简历只放动作+结果）
    ② 动作压成括号里的机制名（面试官想听细节会问）
    ③ 结果保留 2~3 个数字，业务翻译删掉（简历没空间）
  六条全部照此改写，每条 ≤40 字。
```

### 3.2 演练二：三层追问测试全记录

```
对每条简历 STAR 跑三层（AI 面试官，每层追问到底）：
| 条目          | 一层 | 二层 | 三层 | 断在哪/修法           |
|---------------|------|------|------|-----------------------|
| Agent 架构     | ✓    | ✓    | ○    | "流量×10"→补 day15 压测推演 |
| 性能优化       | ✓    | ✓    | ✓    | —                     |
| 秒杀          | ✓    | ○    | —    | "热点分桶怎么分"→回 M5 笔记 |
| …             |      |      |      |                       |
判定规则：
  三层全 ✓ = 简历级（放全文）
  断在三层 = 保留（面试前补课即可）
  断在一二层 = 降格或删除（这是"写了会翻车"的条目）
```

### 3.3 演练三：个人简历六军规自查

```
把六军规变成检查清单，对自己的简历草稿逐条过：
  □ 全文搜"参与/协助/负责"——出现几次？各改成什么动词？
  □ 每条都有数字吗？哪条没有？（要么补数字要么删）
  □ 归属检查：每条问"这是我做的还是团队做的"？
  □ 总字数：超过一页了吗？删哪 20%？（提纯不删骨）
  □ 每个项目第一行是一句话版本吗？
  □ 关键词表：目标 JD 的高频词（如"高并发/性能优化/AI 工程"）
    在简历里出现过吗？
输出：《我的简历军规补丁清单》（改了什么+为什么）。
```

### 3.4 思考题

为什么"断在第三层追问"的条目仍可保留在简历上，而断在一二层的必须降格？（提示：三层追问的第三层是"开放题"——没有标准答案，考的是思路和诚实，面试官对你的预期就是"承认边界+给演进方向"，这可以赛前速成；而一二层是"事实题"——答不上=简历注水实锤，直接出局。事实题零容忍，开放题可练。）

## 4. 面试连接

**Q：（面试官视角）你简历上写"注入拦截 100%"，我凭什么信？**
> 三个证据：一、方法可复现——50 条单发+50 条批量 payload 的对抗实验，payload 清单和拦截日志都在我的实验记录里；二、机制讲得清——四层纵深（白名单/参数三查/权限双保险/审计），拦截不是模型聪明，是模型根本看不到危险工具；三、我主动交代边界——这是本地测试口径，生产环境 payload 会持续更新，所以我配了注入相关的日报指标，拦截率跌破 100% 会告警。数字会说谎，机制和监控不会。

**Q：你的简历为什么只有一页？**
> 一页是提纯的结果不是限制：每个项目我只留"一句话版本+2~3 个数字"，因为筛简历的人平均 10 秒看一份，多的字不是加分是噪音。细节我都备着——面试官对哪个点感兴趣，我能从一句话展开成 10 分钟，这才是简历的正确用法：它不是传记，是钩子集。
