# Day 12 · 追问对抗训练

> **今日目标**：面试的胜负不在第一答，在追问链——今天专门练"被追问到第三层、第四层"的对抗能力；产出《追问话术手册》（README 验收标准：≥20 条）。
> **时长**：对抗 2h / 手册 1.5h / 输出 0.5h
> **今日产出**：追问话术手册 ≥20 条 + 三场压力追问录音 + 卡壳题清单

## 1. 知识地图（先讲人话）

```
追问的三种杀法（先认清对手）：
  ① 下钻型："为什么用 A？A 里面怎么实现的？那一步
     为什么这么处理？"——像钻头往深处打
     （考：你的知识是不是只有一层皮）
  ② 换角度型："如果场景变成 X 呢？流量 10 倍呢？
     团队只有 2 个人呢？"——像晃树看果子掉不掉
     （考：你的方案是背的还是理解的）
  ③ 挑衅型："你这方案我们生产上早不用了/这就是个
     demo 吧？"——故意激怒看你稳不稳
     （考：心理素质+诚实度——多数人此时开始吹牛）

对抗的三大心法（比技巧重要）：
  心法一：不懂就承认+给出路径
    "这块我没实际操作过，但我的理解是…如果面试官
    方便，也想请教生产上通常怎么做"——
    承认边界不减分，硬编必崩（面试官一追就穿）
  心法二：被挑战先接住再回应
    "您说的场景确实存在，我当时的约束是…如果按您
    说的场景，我会调整为…"——先肯定再补充，
    对抗感变协作感（M17 冲突调解的翻译术）
  心法三：永远留"演进口"
    "生产落地前我会先 POC 验证"——
    这句话让你从"答题者"变"工程师"，
    也给不确定的内容上了保险

追问链的衰减规律（为什么练三层就够）：
  第 1 问：考知识（80% 候选人过）
  第 2 问：考理解（50% 候选人过）
  第 3 问：考真实经历（20% 候选人过）
  第 4 问：已经极少问（除非前三个你都稳）
  ——你在前三问站稳，就赢了八成对手
```

## 2. 核心概念（中英对照）

| 英文 | 中文 | 大白话 |
|------|------|--------|
| Follow-up Question | 追问 | 第一答只是入场券，追问才是主战场 |
| Pressure Test | 压力测试 | 挑衅型追问的本质——测的是人不是知识 |
| Intellectual Honesty | 智识诚实 | "不知道"三个字的说出成本最高、回报也最高 |
| Anchor & Pivot | 锚定与转向 | 被问偏时先锚定（接住问题）再转向（拉回你的主场） |
| Depth-first Trap | 深度陷阱 | 追问链会一路打到你知识的岩层——提前知道岩层在哪（诚实边界清单） |

## 3. 动手实操（三场对抗）

### 3.1 演练一：下钻型对抗（对自己最熟的题）

```
拿 day01 的六条 STAR 中最强一条（性能优化 P99 800→480），
模拟追问链（自己扮演面试官，逐层录音作答）：
  L1"具体怎么把 P99 从 800 降到 480 的？"
    → （答：先定位——压测+链路追踪找到三个热点：
       锁竞争/慢 SQL/线程池配置…）
  L2"锁竞争具体是什么锁？为什么这里会有竞争？"
    → （答：库存扣减的 synchronized 粒度太粗，
       改成分桶锁+Redis 原子操作…）
  L3"分桶之后桶间不均衡怎么办？"
    → （答：哈希打散+热点桶监测+动态分裂…这一层
      开始出汗是正常的——打到岩层了）
  L4"你怎么知道桶该分裂了？阈值怎么定？"
    → （如答不出：诚实边界话术——"桶分裂的生产经验
      我还没有，我的设计思路是桶内计数超阈值告警+
      人工确认分裂，这个阈值我会用压测标定"
      =承认+思路+验证路径，三件套兜底）
  规则：每条 STAR 都打穿到 L4，把"岩层位置"记下来。
```

### 3.2 演练二：换角度型对抗（三个"如果"）

```
拿 day09~11 三场演练的设计稿，各做三轮"如果"：
  限流平台：
    如果"只有 2 台机器"→ 集中限流即可，别过度设计
      （主动说"这个规模我不会建平台"=反 P7 陷阱）
    如果"预算砍半"→ 砍观测面？不——砍精度（纯本地）
  风控系统：
    如果"要求 100% 不误杀"→ 那就没有风控了——
      量化讲账（误杀成本 vs 羊毛损失），引导对方给优先级
    如果"模型团队没人力"→ 纯规则引擎起步，预留模型接口
  AI 客服：
    如果"老板要求解决率 95%"→ 讲 78%→95% 的路径与
      成本（知识库覆盖工程+人工兜底优化），不拍胸脯
    如果"预算只够调 API 不能自建"→ RAG 仍可 SaaS 化，
      考卷和安全护栏不可省（底线思维）
  话术公式："如果条件变成 X，我的取舍是 Y，因为 Z"——
    先给取舍再给理由，别给"看情况"三个字。
```

### 3.3 演练三：挑衅型对抗（压力测试）

```
三句最刺的话，各录音作答（每题先深呼吸 2 秒）：
  Q1"你这些都是练习项目吧，生产上真跑过？"
    → 诚实口径（M17 交接卡）："秒杀和限流是演练项目，
      但压测方法、容量账、故障注入都是按生产标准做的，
      数据可复现；生产经验我确实在补，所以我把每个
      演练都做成了可验证的实验——这是我能带来的方法。"
      （不装+亮方法=最优解）
  Q2"你这数字听起来太完美了，真的吗？"
    → "有测量条件：78% 是 X 场景下的演练口径，考卷
      覆盖三类问题；您如果关心特定场景，我可以展开
      讲测量方法。"（给口径+邀请验证=可信）
  Q3"这个方案我们生产早不用了。"
    → "愿意听听你们现在的做法——我当时的约束是 A，
      如果你们场景是 B，确实该换。"（接住+请教+
      补约束=不卑不亢）
```

### 3.4 思考题

为什么挑衅型追问下"承认不足+给方法"反而比"据理力争"得分高？（提示：面试官的挑衅不是要否定你，是在测你的"反应模式"——被攻击时启动的是防御模式（争辩/夸大/恼怒）还是工程模式（摆事实/给口径/找共同点）。生产事故复盘时，第一种人甩锅，第二种人修复。面试官挑的不是现在的你，是三年后会坐在他对面一起值班救火的你。诚实是你中下水平翻盘的路径，这在面试对抗里同样成立。）

## 4. 面试连接

**Q：（连环下钻示范）你说缓存命中率从 52% 提到 85%，具体怎么做的？**
> 定位：分析 key 访问分布，发现两类问题——一批不存在的 ID 反复打库（穿透），以及一批冷 key 占了内存（污染）。动作：对穿透上空值缓存+布隆过滤器；对污染改淘汰策略并给热 key 加 TTL 续期。结果：命中率 52%→85%，DB QPS 降 60%。
> （预期 L2 追问："布隆过滤器误判怎么办？"→ 误判率公式由位数组大小和哈希函数数决定，我们按 1% 误判率配置，误判的请求有 DB 兜底+空值缓存二次拦截，不会击穿。）
> （预期 L3 追问："为什么不用 Cuckoo 过滤器？"→ 权衡五步：目标相同（存在性判断），Cuckoo 支持删除且误判更低，但实现复杂、内存布局对缓存不友好；我的场景 key 只增不删，布隆更简单够用；如果未来有删除需求我会切 Cuckoo——这个演进口我留着。）

**Q：（被挑战示范）你这个方案太重了，我们小团队根本玩不起。**
> 您说得对，这套是按 10 万 QPS 规模设计的，前提约束变了结论就该变。如果团队小、量级小，我会砍掉两层限流里的 Redis 校正层，只留本地令牌桶，牺牲一点全局精度换零运维成本；评测考卷这种轻投入高回报的部分我会保留。您团队现在的量级和人力大概是什么情况？我可以按您的约束给个更贴的裁剪版。（→接住+裁剪+反问，对抗变咨询）
