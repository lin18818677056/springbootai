# Day 18 · 模拟面试 3：架构与管理面

> **今日目标**：第三轮模拟——60 分钟架构决策+管理面混合（模拟 P7+ 交叉面）；兑现 M17 交接卡②：把"你带过几个人"答成诚实且有证据的满分题；面试官人设"管理面型"。
> **时长**：模拟 60min / 复盘 2h / 输出 0.5h
> **今日产出**：第三轮模拟录音 + 管理问题题答卡 + 带人问题话术定版

## 1. 知识地图（先讲人话）

```
架构管理面考什么（先讲人话）：
  前两轮考"你能不能干活"，本轮考"你能不能负责"——
  像从考司机升到考车队队长：
  技术题：考"决策力"（不只选方案，要讲决策过程和担当）
  管理题：考"影响力"（没头衔时怎么推动事情）
  情景题：考"成熟度"（冲突/失败/背锅怎么处理）

M17 交接卡②兑现：'你带过几个人'的诚实口径（背熟）：
  公式：主导设计 + 小范围推行 + 模拟演练 + 证据链
  "我没有正式的管理 title，但做了三件有管理含金量的事：
   ① 主导设计：团队的调参四连问、代码评审三级标准
     是我设计的，被采纳为团队规范
   ② 小范围推行：规范推广用了三部曲——先工具卡点，
     再试点话术，最后度量面板看效果，压测返工从月均
     4 次降到 1 次
   ③ 演练带教：M17 的四场演练里我担任过评审主持和
     冲突调解的角色
   证据都在我的项目文档里，可以展开讲任意一件。"
  ——为什么诚实反而加分：管理面官见过太多把自己
    算成"带过 5 人"的注水者，一追细节就穿。
    诚实+证据+方法论 = "他知道管理是什么"，
    这比 headcount 数字更有说服力

高频管理题的答法骨架（STAR 变体）：
  情景题答法 = 立场一句 + 处理三步 + 反思一句
  立场：先亮原则（"我先对事不对人"）
  三步：怎么了解情况/怎么推动/怎么收尾
  反思：一句"如果重来我会…"（没有反思的管理题=零分）
```

## 2. 核心概念（中英对照）

| 英文 | 中文 | 大白话 |
|------|------|--------|
| Cross Interview | 交叉面 | 跨团队面试官主考——考协作面不只考技术面 |
| Influence Without Authority | 无授权影响力 | 没头衔推动别人干活的能力——P7 的核心分水岭 |
| Ownership | 归属担当 | "这事是我的"心态——出事先找自己环节而非甩锅 |
| STAR-L | STAR+Learning | 讲完经历必带一句学到什么——反思是管理面的硬通货 |
| Constructive Conflict | 建设性冲突 | 对事观点碰撞（好）vs 对人情绪对抗（坏）——M17 调解四步法 |

## 3. 动手实操（60 分钟混合模拟）

### 3.1 演练一：全真模拟（录音，严格计时）

```
面试官人设卡：
  管理面型面试官·王总：技术总监，温和但句句带钩，
  喜欢问"为什么"和"如果重来"，
  会沉默 10 秒等你补充（压力测试）

60 分钟结构：
  00~05 自我介绍 + 为什么看机会（离职原因！
    三不原则：不贬前司/不说钱/说成长逻辑：
    "我想去更大规模的并发场景和更完整的 AI 落地环境"）
  05~20 架构决策题 2 道：
    题 1"你做过的最难的架构决策是什么？"
      → 用 ADR 格式答（M17 选型四步）：
        背景/选项/选择/代价/事后验证，
        最后必加"如果重来"段
    题 2"团队有成员坚决反对你的技术方案，怎么办？"
      → M17 调解四步法：分别倾听→找共同目标→
        翻译成规则（定验收标准而不是争偏好）→
        收敛回访；举真实例子（规范推广时的阻力）
  20~35 带人问题连环（今天的主菜）：
    "你带过几个人？"→ 诚实口径（见知识地图）
    追问"推规范时遇到最强阻力是什么？"
      → 讲工具卡点前的真实阻力故事+怎么化解
    追问"如果下属活干得不行，你怎么处理？"
      → SBI 反馈三段论（M17）：先说事实再说影响
        最后问原因；给改进期；区分能力问题和意愿问题
    追问"你自己被批评过吗？"
      → 真实案例（池子调大炸了那次 P99 翻倍，
        我的教训变成团队四连问——把批评变资产）
  35~50 失败与压力题：
    "讲一次你搞砸的经历" → STAR-L：技术债利息低估
      那次（M17 day09 借债话术的来源），学习点：
      现在借债必算利息+显式缓冲
    "如果老板要求和你的技术判断冲突？"
      → 先执行老板决策（权责清晰）+ 留数据验证 +
        用数据再沟通（两次机会法则：数据证明我对，
        下次话语权变大；数据证明我错，改判断）
  50~57 反问（换管理版三问）：
    "团队的技术决策机制是怎样的？"
    "这个岗位半年的成功标准是什么？"
    "您在这家公司印象最深的一件事？"
  57~60 收尾
```

### 3.2 演练二：管理题答卡定版

```
把今天答过的题固化成《管理题答卡》（一题一卡）：
  卡片格式：题目 | 立场一句 | 案例 | 学习点 | 追问预案
  必备八卡：
  ① 带过几个人（诚实口径+三件事证据）
  ② 最难架构决策（ADR 格式+重来段）
  ③ 方案被反对（调解四步法+真实阻力案例）
  ④ 下属不行（SBI+改进期+能力/意愿区分）
  ⑤ 被批评（池子案例+变资产叙事）
  ⑥ 搞砸经历（技术债低估+学习点）
  ⑦ 与老板冲突（执行+数据+两次机会法则）
  ⑧ 离职原因（成长逻辑三不原则）
  ——八卡背熟，管理面 80% 的题都在射程内
```

### 3.4 思考题

为什么"没有管理 title"的管理经验反而要用证据链讲足，而不是含糊带过？（提示：面试官问"你带过几个人"，真实想判断的不是 headcount，是"你有没有从执行者切换到负责者的思维"。含糊带过=放弃展示；注水=一追就穿且人品扣分；诚实口径+证据链=承认现状的同时展示"管理的本质我懂"——规范设计是制度化思维，推广三部曲是变革管理思维，演练带教是教练思维。这三件事证明的是"你已经在用管理者方式工作，只差正式授权"。对中下水平候选人，这是把履历短板转成方法论长板的教科书操作。）

## 4. 面试连接

**Q：你带过几个人？（M17 交接卡②的最终答案，背熟）**
> 我没有正式管理 title，但有三件有管理含金量的事可以展开。第一件，主导设计：团队压测调参总踩坑，我把踩坑经验沉淀成"调参四连问"（目标是什么/瓶颈在哪/参数怎么定/怎么验证），后来变成团队规范，压测返工从月均 4 次降到 1 次。第二件，小范围推行：推广规范时我用了三步——先做工具卡点让规范可执行，再找试点项目用话术拿到首肯，最后上度量面板让大家看到效果，没有硬推过一次。第三件，演练带教：我在内部技术演练里担任过评审主持，处理过两次方案分歧，用"分别倾听→共同目标→翻译成规则"的方式收敛的。所以严格说我"带"的不是人，是事和方法——但我觉得这正是管理的起点：先让人信你的方法，才谈得上带人。（→承认边界+三件事+升华一句：这段话把短板答成了记忆点）

**Q：讲一次你搞砸的经历。（失败题示范，STAR-L 完整版）**
> 做性能压测时我把线程池从 50 调到 500，预期吞吐翻倍，结果 P99 从 800 毫秒涨到 2 秒，当场下线回滚。事后复盘我错在三处：把"线程多=吞吐高"当公理，没先分析瓶颈；改动没有灰度，直接全量；没有预设回滚阈值。修复动作：按"下游容量÷单线程吞吐"重新定参，压测验证 P99 稳定在 480 毫秒；更重要的是我把教训沉淀成团队的调参四连问，写进了规范。这件事教会我两件事：一是参数是测出来的不是拍的；二是任何"看起来只会更好"的变更都值得怀疑——现在我做任何优化，先想"它会伤害什么"。（→失败讲得越具体，学习点越可信，这段比十个成功故事更能证明你成熟）
