# Day 01 · 弹药盘点与六项目 STAR

> **今日目标**：兑现 M17 交接卡①——把 18 个月的家底全部清点一遍（六项目/数字卡/演讲稿/模板库）；给每个项目写出 STAR 骨架（一句背景+一个动作+一个数字）。
> **时长**：盘点 1.5h / 输出 1h / 复核 0.5h
> **今日产出**：弹药清单总表 + 六项目 STAR 骨架（简历的原材料）

## 1. 知识地图（先讲人话）

```
为什么要先盘点再写简历：
  直接写简历的通病——凭记忆写，写出来的都是"负责了 XX 系统
  开发"这种空话；先盘点 = 把 18 个月 day30 存的数字卡翻出来
  摊在桌上挑，简历上只放"有数字、有证据、经得起追问"的料。
  类比：搬家先列清单再装箱，不然永远觉得少了东西。

STAR 骨架模板（每项目四行，今天先搭骨架，day02 精修）：
  S（Situation 背景）：一句话说清"当时什么局面"
  T（Task 任务）：你背的指标/目标是什么
  A（Action 动作）：你做的 2~3 个关键动作（动词开头）
  R（Result 结果）：一个数字+一句业务翻译
  检验线：R 里的数字必须能回答"怎么算的"（面试官必追）

18 个月弹药地图（今天的盘点范围）：
  六个项目 / M13~M17 数字卡 / 电梯演讲五版 / 博客 13 篇 /
  防翻车卡 / 模板库（汇报/评审/风险/ADR/价值说明书）/
  各月 day29 验收的判级记录
```

## 2. 核心概念（中英对照）

| 英文 | 中文 | 大白话 |
|------|------|--------|
| STAR | 情境-任务-行动-结果 | 讲项目故事的万能结构，简历和面试通用 |
| Quantify | 量化 | 结果必须带数字——"优化了性能"是废话，"P99 降 40%"是证据 |
| Ammunition | 弹药（本计划黑话） | 18 个月攒下的所有可引用素材：数字/截图/博客/模板 |
| Highlight | 亮点 | 每项目挑 1 个"面试官会'哦？'的点"（反常识/大数字/真事故） |
| One-liner | 一句话版本 | 每个项目 30 字说清——电梯演讲的最小单元 |

### 3.2 演练二：六项目 STAR 骨架

```
示范两条（照着写完六条）：

① 性能优化（项目六，M16）：
  S：AI 客服压测 P99 800ms，高峰期用户流失明显
  T：目标 P99 ≤500ms，且不能加机器
  A：性能台账 12 条"量→改→量"；缓存穿透治理+慢 SQL 改写+
     线程池按压测定参（拦住"调到 500"的反向优化）
  R：P99 降 40%（800→480ms）、成本降 70%；方法论沉淀为
     团队规范（返工 4→1，试点口径）
  一句话版：把 800ms 的接口优化到 480ms，还顺手把方法
  变成了团队检查清单。

② Agent 客服（项目五，M15）：
  S：知识库只能答"是什么"，用户问"帮我查订单"就抓瞎
  T：让 AI 能办事且可控——解决率、安全、成本三线都要达标
  A：ReAct 循环+三层刹车；工具三道闸+两级审批；MCP 划边界
  R：解决率 78%；注入拦截 100%；死循环从 50 轮刹到 3~4 轮；
     最坏损失可控可解释可回放
  一句话版：给 AI 客服装上"手脚"，每一步留录像、花钱有上限。

剩下四条自己写（秒杀/DDD 商城/实时数仓/RAG 知识库），
每条最后自检："数字能答怎么算的吗？"
```

### 3.3 演练三：AI 追问预演（三层追问第一层）

```
AI 人设："你是简历筛选官，对每条 STAR 至少追问一次
```

### 3.4 思考题

为什么 STAR 里"一句话版本"比完整版更重要？（提示：简历筛选平均 10 秒/份——一句话版本决定简历生死；面试自我介绍 1 分钟只够讲 2~3 个一句话版；完整 STAR 是追问展开后的形态。先有一句话版，再备完整版——传播结构是漏斗，不是倒过来。）

## 4. 面试连接

**Q：（热身）用一分钟介绍你最有代表性的项目。**
> 我讲性能优化这个：AI 客服压测 P99 卡在 800ms，我的目标是降到 500 以内且不加机器。我建了 12 条优化台账，每条都是"先量化、再动手、再量化"——比如缓存穿透治理把命中率从 52% 提到 85%，慢 SQL 改写砍掉最大的长尾。结果 P99 降到 480ms，成本还降了 70%。这件事最大的收获是我把排查动作沉淀成了四连问规范，团队压测返工从一个月 4 次降到 1 次。（=STAR 完整版，一分钟刚好）

**Q：简历怎么避免"参与感注水"？**
> 我的算法是动词+数字的归属检查：每个动作问"这是我的决策还是我的执行"——决策类（选型/方案/规范）写"主导/设计"，执行类写"实现/落地"，绝不把团队的活写成自己的。数字全部有出处（台账/考卷/日报），答不上"怎么算的"的数字宁可不写。注水能过筛子过不了追问，而面试全是追问。
