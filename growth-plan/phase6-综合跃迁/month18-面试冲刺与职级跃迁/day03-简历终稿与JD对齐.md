# Day 03 · 简历终稿与 JD 对齐

> **今日目标**：产出简历终稿（一页纸）；做 5 份真实 JD 的对齐分析（匹配点/差距点/话术调整）；完成 3 位"面试官视角"的模拟简历评审。
> **时长**：成稿 1.5h / 对齐 1h / 评审 1h
> **今日产出**：简历终稿 + 5 份 JD 对齐表 + 3 份模拟评审意见

## 1. 知识地图（先讲人话）

```
JD 对齐的原理（把简历当产品做匹配）：
  JD（职位描述）就是公司写的"需求文档"——
  它要什么，你就把对应的证据往前提。
  类比：面试是投标，JD 是标书要求——
  没人把 unrelated 的辉煌历史全写进标书。

JD 对齐三步：
  ① 拆 JD：把职位描述拆成"硬性要求/加分项/隐性期望"
    （隐性期望=字面没写但一定考的，如"能抗压"="on-call"）
  ② 配对：我的哪条 STAR 对应哪个要求？标上配对表
    （全配上的=高匹配公司，优先投）
  ③ 改写：同一段经历按 JD 换关键词和排序
    （JD 写"高并发"→秒杀项目放第一个；JD 写"AI 落地"→
     RAG/Agent 放第一个——内容不变，次序和用词变）

3 位面试官模拟评审（对照总 README 里程碑 M6）：
  评审 A（猎头视角）：10 秒能看出你是干什么的吗？
    关键词密度/职位连贯性/跳槽逻辑
  评审 B（业务面试官视角）：想约面哪个项目？
    亮点的钩子力/数字的可信度
  评审 C（ Strict 架构师视角）：哪条经不起追问？
    技术名词的准确性/架构描述的深度
  三份意见取交集修改——三人都提的问题才是真问题。
```

## 2. 核心概念（中英对照）

| 英文 | 中文 | 大白话 |
|------|------|--------|
| JD | 职位描述 | 公司的"征婚启事"：要什么人、干什么活、给什么价 |
| Fit | 匹配度 | 你的经历和 JD 要求的重合程度——决定约面率 |
| Screening | 简历筛选 | HR/系统 10 秒决定给不给你面试机会 |
| Pipeline | 投递漏斗 | 投 10 → 约 4 → 面 2 → offer 1 的正常转化 |
| Referral | 内推 | 跳过机筛的绿色通道——成功率是直投的 3~5 倍 |

## 3. 动手实操（演练）

### 3.1 演练一：简历终稿成型

```
一页纸结构（顺序即优先级）：
  ═══════════════════════════════════
  【头部】姓名/联系方式/GitHub/博客（13 篇博客是硬通货）
  【个人概述】3 行（=电梯演讲面试官版压缩）：
    "7 年 Java 后端，近 18 个月聚焦高并发与 AI 工程化：
     主导秒杀链路改造（5000 并发零超卖）、AI 客服
     Agent 架构（解决率 78%）、性能优化体系（P99 降 40%，
     方法论固化为团队规范）。"
  【项目经历】3 个（挑最匹配的，不是全部六个）：
    每个项目 = 一句话版 + 2 条 STAR + 技术栈标签行
  【工作经历】倒序，每段 2 行（公司/职级/一句话职责）
  【技能清单】分四组：架构/JVM与性能/中间件/AI 工程
    （与 JD 关键词对齐，别写"精通"——写"熟悉/深入理解"）
  ═══════════════════════════════════
  自检：10 秒测试——遮住名字，第 10 秒你能记住这个人
  是干什么的吗？不能就改概述。
```

### 3.2 演练二：5 份 JD 对齐分析

```
找 5 份真实 JD（招聘平台搜"Java 高级/架构 + 高并发/AI"），
每份做一页对齐表：
| JD 要求               | 我的对应证据         | 匹配 | 话术调整            |
|-----------------------|---------------------|------|---------------------|
| 高并发系统设计经验      | 秒杀 5000 并发零超卖  | 强   | 秒杀项目放第一位     |
| 有 AI 应用落地经验      | RAG+Agent 双项目     | 强   | 强调工程化（评测/成本）|
| 熟悉 JVM 调优          | M1 实验+M16 线程池    | 中   | 补"生产级 GC 调优"叙事|
| 带过小团队             | 主导设计+推行+演练    | 中   | 用 M17 诚实口径      |
| 英语读写               | 阅读英文文档/源码     | 弱   | 备个例证（源码笔记）  |
综合匹配分 = 强×3+中×2+弱×1，排投递优先级。
差距点处理：弱项写进"面试前补课清单"（如英语→准备
  一个"我常读哪些英文文档"的例子）。
```

### 3.3 演练三：3 位面试官模拟评审

```
AI 人设三件（每份评审 10 分钟）：
  猎头 A："我每天看 200 份简历。10 秒内告诉我你是干什么的、
    值不值一面对。跳槽逻辑讲不通我会标疑。"（审连贯性）
  业务面试官 B："我业务方出身，看简历先找'这人干成过什么'。
    数字太漂亮的我会追问。"（审钩子与可信度）
  架构师 C："简历上的每个技术名词我都可能追问。
    写了 RocketMQ 事务消息就等着被问 half message。"（审深度）
流程：把终稿发给三位 → 收意见 → 三人交集列表 → 改稿。
验收线（M6 里程碑）：三人都到"愿意约面"级别。
```

### 3.4 思考题

为什么简历上只放 3 个项目而不是全部 6 个？（提示：一页纸的注意力预算只有 6~8 个"视觉停留点"——放 6 个项目每个只能分到半行，等于全都没有钩子；放 3 个每个有完整钩子+数字。且 3 个可按 JD 换阵容（高并发岗换秒杀上前、AI 岗换 RAG/Agent 上前）——项目池是弹药库，简历是按需装弹的弹匣。）

## 4. 面试连接

**Q：你怎么看待自己简历与岗位的匹配度？（面试中真实会出现）**
> 我投贵司前做过对齐分析：JD 五条硬性要求我能强匹配三条——高并发（秒杀 5000 并发零超卖）、性能优化（P99 降 40% 且固化了团队规范）、AI 工程（RAG+Agent 双项目带评测体系）；两条中等——团队经验我是"主导设计+小范围推行"的口径，英语我读文档没问题但口语一般。我不擅长包装自己为完美匹配，但匹配的部分每个数字都能现场展开——这是我理解的诚实投递。

**Q：为什么从上家公司出来？（跳槽逻辑题）**
> 我的叙事线是"能力阶梯"：前几年把高并发打透了（秒杀），18 个月系统补了 AI 工程化和架构方法论（有博客和项目为证），下一步想在更大的业务场景里做架构决策——贵司这个岗位的场景和数据量正好是我下一步需要又暂时缺的。离开是为了找下一级台阶，不是为了逃离——每个选择都指向能力版图的补全。
