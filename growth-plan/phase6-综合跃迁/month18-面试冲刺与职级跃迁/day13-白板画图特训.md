# Day 13 · 白板画图特训

> **今日目标**：系统设计的隐形扣分项是"哑画"（画图不说话）和"乱画"（布局失控）——今天专项练"边画边讲"的肌肉记忆，产出个人画图规范。
> **时长**：特训 2h / 规范 1h / 输出 0.5h
> **今日产出**：个人画图规范一页纸 + 三次限时画图录音 + 哑画清零记录

## 1. 知识地图（先讲人话）

```
画图在面试里的真实作用（先讲人话）：
  图不是给面试官看的"美术作品"，
  是你思维的"外挂内存"：
  ① 帮你自己记（说到存储层时不用回头重问需求）
  ② 给面试官抓手（他指着图追问，比凭空问好答 10 倍）
  ③ 填补沉默（笔在动+嘴在讲 = 没有 20 秒哑场）

普通人的三个画图死穴：
  死穴一：先想清楚再画——想 40 秒画 10 秒（哑画现场）
    解法：笔永远比嘴快半格，讲哪画哪，图跟着话走
  死穴二：布局失控——画到右边发现左边没地方了，
    箭头交叉成蜘蛛网
    解法：动笔前先点 5 个"阵地"（五段流布局，见下）
  死穴三：图例混乱——方框/圆圈/云朵随手用，
    自己都忘了圆圈是什么
    解法：全程只用三种符号（见个人规范）

五段流标准布局（背下来，所有系统设计图通用）：
  ┌──────┐   ┌──────┐   ┌──────┐   ┌──────┐   ┌──────┐
  │ 客户端 │ → │ 接入层 │ → │ 服务层 │ → │ 中间件 │ → │ 存储  │
  │       │   │网关/CDN│   │微服务  │   │MQ/缓存 │   │DB/OSS│
  └──────┘   └──────┘   └──────┘   └──────┘   └──────┘
       ↑______________旁路（异步/监控）画在下方______________↑
  规则：主链路从左到右一横排；异步/监控画下方；
    用户请求用实线箭头，异步用虚线箭头。
  （布局先定，内容后填——和写文章先列提纲一个道理）
```

## 2. 核心概念（中英对照）

| 英文 | 中文 | 大白话 |
|------|------|--------|
| Whiteboard Interview | 白板面试 | 边画边讲的现场——考的图，评的是思路流畅度 |
| Talk While Drawing | 边画边讲 | 笔是嘴的节拍器——哑画超过 20 秒必扣分 |
| Layout First | 布局先行 | 先点阵地再填内容——动笔 30 秒内完成骨架 |
| Legend | 图例 | 三种符号走天下：方框=服务/圆柱=存储/虚线=异步 |

## 3. 动手实操（三次限时特训）

### 3.1 特训一：五段流布局肌肉训练（15 分钟 × 3 轮）

```
第 1 轮（只练布局不练内容，15 分钟）：
  随便报 5 个系统（秒杀/短链/风控/IM/ feed 流），
  每个只做一件事：90 秒内点出五个阵地并写出每格组件名。
  例：秒杀 → 客户端(倒计时/限流按钮置灰) | 接入(CDN/网关
  限流) | 服务(订单/库存服务) | 中间件(Redis扣减/MQ) |
  存储(MySQL/OSS)
  ——布局熟练后，45 分钟设计题的前 2 分钟就是"点阵地"，
    这 2 分钟决定了你后面 40 分钟的秩序。
第 2 轮（边画边讲，30 分钟）：
  拿 day09 限流平台设计稿重画一遍，规则：
  ① 笔永远在动（想的时候画框，不说话的时间不许超过
    一句话的长度）
  ② 每画一个组件必须说一句话（"这里是网关，做两件事：
    鉴权和限流"）
  ③ 主链路画完立即"走图"：用一条买家的请求从左走到右
    口述一遍
第 3 轮（盲画，20 分钟）：
  不看 day09 稿子，凭记忆重画 AI 客服三线并行图。
  ——盲画暴露的是"你以为懂了"和"真懂"的差距。
```

### 3.2 特训二：哑画清零训练

```
重听 day09/10/11 三场录音，统计自己的"最长沉默"：
  演练 1：____ 秒 / 演练 2：____ 秒 / 演练 3：____ 秒
  （>20 秒即哑画现场）
清零三招（练到形成反射）：
  招 1·口播过渡句（最简单）：
    "这里我先画主链路，异常流稍后补充"——
    一句话争取 10 秒思考时间
  招 2·复述确认：
    "我确认一下，您刚才问的是缓存层的降级策略对吧"——
    争取 5 秒+确保不答偏
  招 3·诚实缓冲：
    "这个点我想 10 秒"——直接说反而加分
    （慌乱的即兴发挥比短暂的沉默更减分）
再录一遍最哑的那场（只重画重讲，不全重来），目标：最长
  沉默 <10 秒。
```

### 3.3 特训三：个人画图规范定版

```
写成一页纸（贴在白板旁），内容含：
  ① 三符号规则：方框=服务 | 圆柱=存储 | 虚线箭头=异步
    （实线箭头=同步调用；数据库读写箭头标明读/写）
  ② 五段流布局（今天上午背的图）
  ③ 命名规则：框内写"服务名+一行职责"（写不下就缩写，
    职责用括号）
  ④ 走图收尾：画完必走一条请求（主链路成功流 +
    一条失败流），说"我用一条请求走一遍验证"
  ⑤ 三不画：不画装饰（云朵/星星）、不画超出需求的
    组件（画了就要能讲）、不画自己讲不清的箭头
    （箭头=承诺，画了就被追问）
```

### 3.4 思考题

为什么"箭头=承诺，画了就要能讲"？（提示：图上每一个箭头都是一次进程间通信——它有协议（HTTP/RPC/gRPC）、有超时、有失败模式。面试官指着一个你没讲清楚的箭头问"这条链路超时了怎么办"，答不上来，这个箭头就从加分项变成暴露点。所以画图的纪律和写代码一样：每一行都要经得起 review。这也呼应简历六军规——简历上每个字经得起三层追问，图上每根线经得起一次"超时了怎么办"。同一个证据思维，贯穿 18 个月。）

## 4. 面试连接

**Q：（现场画图时的自控话术，直接背）**
> 开场定阵地："我先点五个区域：客户端、接入、服务、中间件、存储，主链路从左到右，异步和监控画在下方。"（30 秒内完成，秩序感立现）
> 画中持续解说："网关这层做两件事：鉴权和限流，限流用我们之前聊的两层架构。"（每画必说）
> 收尾走图："画完了，我用一条下单请求走一遍验证：用户点击→网关限流判定通过→订单服务创建订单→Redis 原子扣减库存→MQ 异步通知下游→MySQL 落库。再走一条失败流：库存不足时直接在 Redis 层返回，不落到 DB。"（走图=自查，面试官看到的是严谨）

**Q：远程面试不能看白板，怎么"画图"？（新常态题）**
> 三个替代方案按优先级：首选共享文档里的画图工具（draw.io/Excalidraw），我提前把常用布局做成模板；次选纯文字排版——用缩进和箭头字符画"文字架构图"，层次一样清楚；最后兜底是口述结构："我描述一下这张图：从左到右五列…"。无论哪种，边画边讲的纪律不变——工具变了，"笔跟着嘴走"不变。我会提前在投递后测试一遍面试软件的屏幕共享和画图功能（这也体现候选人对外部依赖的预案意识——一致性习惯）。
