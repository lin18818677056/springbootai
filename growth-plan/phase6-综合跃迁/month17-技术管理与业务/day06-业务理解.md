# Day 06 · 业务理解：DAU、转化、客单价怎么读

> **今日目标**：补上技术人的最大短板——看懂业务指标。掌握互联网业务的五个核心指标；学会用"业务漏斗"定位技术优化点；把自己项目的技术指标翻译成业务指标。
> **时长**：理论 1h / 演练 1.5h / 输出 0.5h
> **今日产出**：业务漏斗图 + 自己项目的"技术→业务"翻译表

## 1. 知识地图（先讲人话）

```
业务指标就是"生意的好坏"用数字说出来：
┌─────────────────────────────────────────────┐
│ 漏斗（卖东西的店类比）：                        │
│  流量 → 转化 → 客单价 → 复购 → 留存           │
│  多少人  多少人  平均一人   多少人   多少人      │
│  进店   掏钱买   花多少钱   再来买   留下来     │
│                                              │
│  例：日活 100 万 × 下单转化 3% × 客单价 80 元   │
│      = 日 GMV 240 万元                        │
│  → 技术优化的杠杆在哪？转化率从 3%→3.3%（快 100ms │
│    可能就做到了）= 日增收 24 万——这就是你要讲的"人话"│
└─────────────────────────────────────────────┘

技术人读业务的三个动作：
  ① 记五个词：DAU/GMV/转化率/留存/ARPU（下面对照表）
  ② 画漏斗：把"用户从来到买"的路径画出来，标上每步百分比
  ③ 找杠杆：自己负责的系统卡在漏斗哪一段？卡点 100ms 值多少钱？

反面教材（技术自嗨）：
  "我把接口 P99 从 800ms 优化到 480ms" ——老板：所以呢？
  "下单转化率提升 0.3%，按当前流量日增收约 24 万" ——老板：继续说
```

## 2. 核心概念（中英对照）

| 英文 | 中文 | 大白话 |
|------|------|--------|
| DAU / MAU | 日活/月活 | 一天/一个月有多少人来用过（店每天进多少客） |
| GMV | 成交总额 | 一共卖了多少钱（流水） |
| Conversion Rate | 转化率 | 进店的人里多少掏了钱 |
| Retention | 留存 | 第二天/第七天/三十天后还回来的人（回头客率） |
| ARPU | 每用户平均收入 | 平均一个用户给我挣多少钱 |
| LTV | 用户生命周期价值 | 一个用户从来了到走，总共贡献多少钱 |

## 3. 动手实操（演练）

### 3.1 演练一：画一张通用电商业务漏斗

```
用项目五/六的"AI 客服"场景画漏斗（用户问问题到解决问题）：
  进入对话页 → 100%
    ↓ （页面加载慢会流失——M6 首屏优化管这段）
  提出问题 → 85%
    ↓ （答非所问会流失——M13 分类器/M14 检索管这段）
  得到满意答案 → 65%
    ↓ （还要转人工/等很久会流失——M15 熔断与轮次管这段）
  问题解决不转人工 → 78%

自己解决率 78% × 日均 2 万次咨询 = 每天 1.56 万次不用人工。
  → 人工客服单次成本 3 元 = 日省约 1.3 万元人力成本
这就是"技术指标→业务指标"的完整翻译链。
```

### 3.2 演练二：做一张"技术→业务"翻译表

```
| 我做的技术事              | 业务人话版                          |
|--------------------------|-------------------------------------|
| P99 降 40%（M16 台账）    | 用户等待时间砍近一半，急躁放弃的少了   |
| 缓存命中率 85%（M4/M6）   | 大部分请求不花数据库的钱，成本省 70%   |
| 解决率 78%（项目五）      | 每 5 个咨询 4 个 AI 直接搞定          |
| 注入拦截 100%（M15）      | 没有人能骗 AI 干坏事，资损为零        |
| TOKEN_BUDGET 精算（M15）  | AI 每单花销有上限，不会失控烧钱        |

练习：给上表每行加一句"对老板的意义"（省钱/增收/避险三选一）。
```

### 3.3 演练三：AI 陪练"不懂技术的老板"

```
让 AI 扮演"只会看报表的老板"，你用业务话术介绍项目六成果：
  你："我们优化后系统快了一倍，成本降了七成。"
  AI 老板："快了一倍能多卖货吗？降七成能省我多少钱？"
  你：（用翻译表回答：省 X 元/月，用户流失预计降 Y%）
  AI 老板："下季度我能看到这个数字吗？"
  你：（答：建议上线后看三个数——成本曲线/客服人力/客诉率）

录音回听：凡是卡壳的地方，就是还没真正翻译过去的指标。
```

## 4. 面试连接

**Q：你如何理解技术工作的业务价值？**
> 我的算法是"找漏斗找杠杆"：先画业务漏斗看我的系统卡在哪一段，再算这段的改善值多少钱。比如 AI 客服，我的检索和 Agent 循环优化把解决率做到 78%，按日均 2 万次咨询、人工单次 3 元算，每天省 1 万多人力成本。技术指标（P99/命中率/解决率）只是过程，业务指标（成本/转化/留存）才是成绩——面试里我一定两个都讲。

**Q：如果老板问"这个技术优化能带来多少收入"？**
> 诚实分两层答：直接影响好算的（成本节省：机器钱+人力钱），间接影响要讲逻辑链（体验改善→转化/留存改善→收入），并明确说"间接部分建议上线后用 A/B 验证"。敢说"这个数我算不准，但验证方案我有"比编一个大数字更能建立信任。
