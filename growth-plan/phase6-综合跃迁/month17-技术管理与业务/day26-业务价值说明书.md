# Day 26 · 业务价值说明书：技术对业务的三句话价值

> **今日目标**：完成"业务价值说明书"——把自己项目对业务的价值浓缩成业务方能复述的三句话；演练"给完全不懂技术的业务方讲清价值"，通过标准是对方能复述。
> **时长**：写作 1h / 演练 1h / 复盘 0.5h
> **今日产出**：业务价值说明书（一页纸）+ 业务方演练录音 + 复述通过记录

## 1. 知识地图（先讲人话）

```
三句话价值公式（业务价值说明书的骨架）：
  第一句·省了什么钱：成本视角（机器+人力）
  第二句·多了什么钱/少了什么损失：收入与风险视角
  第三句·凭什么信：验证方式（看什么数字，哪里看）

填进项目五/六的真实数字：
  ① "AI 客服能自己解决 78% 的用户咨询，
     按现在量每天省约 1.3 万的人工成本。"
  ② "系统快了一倍，高峰期用户放弃咨询的明显少了；
     另外没人能骗 AI 乱退款（注入拦截 100%），资损为零。"
  ③ "这些数字每天自动出报表，解决率跌破 70% 自动告警——
     不用信我，看数就行。"
  第三句最值钱：给业务方"不信任你的权利"——
    用系统说话而不是用人格担保，这是技术人的高级信用。

说明书的三条纪律：
  ① 零术语：P99/缓存命中率/QPS 全部禁用——
    "99% 的请求在半秒内返回"是上限不是黑话
  ② 数字有口径：每个数能回答"怎么算的"（day23 的教训）
  ③ 有下一步：说明书结尾永远带"下一步能多挣/省多少"
    （业务方看的是趋势，不是历史成绩单）
```

## 2. 核心概念（中英对照）

| 英文 | 中文 | 大白话 |
|------|------|--------|
| Value Prop | 价值主张 | 一句话说清"这事对生意有什么用" |
| Metric Mapping | 指标映射 | 技术指标↔业务指标的双语对照表（day06 的翻译表） |
| Verifiability | 可验证性 | 价值主张能被独立验证（报表/告警），不靠嘴 |
| Stakeholder Language | 干系人语言 | 对谁说人话：老板说钱、业务说漏斗、法务说风险 |
| Next Step | 下一步 | 永远给对方一个"所以呢"的答案——趋势比成绩重要 |

## 3. 动手实操（演练）

### 3.1 演练一：写一页纸业务价值说明书

```
格式（业务方 3 分钟读完，零术语）：
  ═══════════════════════════════════
  《AI 智能客服 · 业务价值说明书》
  【它是什么】
  一个能自己回答用户问题、能查订单能办退款的 AI 客服。
  【三句话价值】
  ① 省钱：78% 的咨询 AI 直接搞定，每天省约 1.3 万人工成本。
  ② 赚体验：回答快了一倍；高峰期用户跑掉得更少；
    资损风险为零（乱退款 0 起）。
  ③ 可验证：日报自动出数，解决率跌破 70% 自动告警。
  【三个老板/业务最关心的问题】
  出错了怎么办？→ 自动转人工，用户无感知，最坏损失可控。
  会不会乱花钱？→ 每单成本有上限，超了自动停（烧钱曲线实测）。
  什么时候能看到效果？→ 现在的数字就是效果，报表链接在这。
  【下一步】
  下季度上线物流查询（解决率 78%→82%），预计再多省
  每天 2000 元人工成本。
  ═══════════════════════════════════
  自检：找出所有术语（"灰度""熔断"删了吗？）
```

### 3.2 演练二：业务方复述测试（今天的验收线）

```
AI 人设（业务方，零技术背景）：
  "你是电商运营负责人，只关心 GMV、成本、客诉率。
   听不懂技术词，听到术语会直接打断'说人话'。
   听完会随机抽一段让你重讲。"

流程：
  第 1 遍：照说明书讲 3 分钟 → AI 抽查复述：
    "你刚才说我这系统能省多少钱来着？怎么省的？"
  通过标准：业务方能复述出"三句话"的骨架（数字可以记错，
    逻辑不能错——"AI 替人工省钱+快+能验证"）
  第 2 遍：AI 施压版："我不信 78%，你证明给我看。"
    → 你："这是日报链接，每天自动更新；我还可以开个只读
      账号给您，随时看。"（可验证性出手）
  第 3 遍：AI 问竞品："别的公司说他们 90%，你们怎么才 78%？"
    → 你："解决率和业务复杂度强相关，90% 的口径可能是
      只算'能答的题'。我建议看两个都认的数：转人工率和
      客诉率。同口径才能比。"（对口径不比裸数字）
录音复盘：被打断"说人话"的位置=术语残留位置。
```

### 3.3 演练三：说明书变体（三个受众三张嘴）

```
同一套数字，三种说法（贴在笔记里随时调用）：
  对老板（30 秒）："AI 客服替掉四分之三人工咨询，
    每天省 1.3 万，数字日报可查，下季度还能再省 2000。"
  对业务运营（3 分钟）：完整三句话版（说明书原文）
  对财务/风控（CFO 视角）："开发投入 4.75 万，保守口径
    13 天回本；每万次咨询成本 55 元 vs 人工 3 万元；
    有成本熔断不会失控。"（day20 三本账直接复用）
练习：同一页说明书口头切换三种版本（录音各一遍），
  检查有没有串词（对 CFO 说"体验"=浪费他的时间）。
```

### 3.4 思考题

为什么"给业务方不信任你的权利"反而能建立更强的信任？（提示：靠人格担保的价值是弱信用（人会错会走），靠系统验证的价值是强信用（报表不会撒谎、告警不会迟到）；敢把验证权交出去，说明你对数字有底——业务方和市场最终只为"可验证的东西"分配资源和预算。）

## 4. 面试连接

**Q：你怎么向业务方证明技术工作的价值？**
> 我会准备一页"业务价值说明书"：零术语、三句话结构——省了什么钱、多了什么体验/少了什么损失、凭什么信（可验证方式）。拿 AI 客服来说：78% 解决率对应每天省 1.3 万人工，注入拦截保证资损为零，日报自动出数、跌破阈值自动告警——我把"不信任我的权利"交给业务方，用系统说话。我练过业务方复述测试：对方能用三句话复述我的价值，才算真讲明白了——听懂和复述是两回事，复述通过才是价值传达完成的标志。

**Q：业务方拿竞品的数字压你怎么办？**
> 先对口径不比裸数字——解决率 78% 和别人说的 90% 可能统计的不是同一件事（有的只算"能答的题"）。我会提议看双方都认可的数：转人工率、客诉率，同口径才有比较意义。同时把差异变成需求：如果对方口径有我们没覆盖的场景，那就是下季度改进清单——把竞争压力翻译成 roadmap，比现场辩输赢值钱。
