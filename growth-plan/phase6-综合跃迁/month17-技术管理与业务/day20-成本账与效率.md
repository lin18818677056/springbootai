# Day 20 · 成本账与效率：机器钱/人力钱/机会成本

> **今日目标**：兑现 M16 交接卡①的深化——把"技术价值→业务价值"翻译升级成完整的三本账（机器钱/人力钱/机会成本）；给项目五/六算一笔"老板视角"的完整成本账。
> **时长**：理论 1h / 演练 1.5h / 输出 0.5h
> **今日产出**：项目五/六完整成本账（三本账齐）+ 效率杠杆清单

## 1. 知识地图（先讲人话）

```
工程师的成本观通常只有"机器钱"，老板的账本有三本：
  ① 机器钱（infra cost）：服务器/云服务/带宽/存储——
    最容易算，多数工程师也只算这本
  ② 人力钱（labor cost）：人天 × 全成本时薪——
    比机器钱贵一个数量级（一个中级工程师全成本
    ≈3 万/月 ≈190 元/小时；他一天烧掉的钱≈一台 4 核 8G
    云主机跑一个月）
  ③ 机会成本（opportunity cost）：干了这件事=没干那件事——
    最隐形也最贵：两个工程师磨一个月优化一个日 PV 100 的页面
    = 同时放弃了能省 20 人天/年的自动化工具

三本账联动看（"优化值不值"的完整算法）：
  例：优化 P99 从 800ms→480ms（项目六）。
    机器钱：省下的扩容机器 ≈3000 元/月
    人力钱：排查变快+客诉处理减少 ≈10h/月 ≈1900 元
    机会成本：团队不再每月开"性能救火会" ≈1 人天/月
    一句总账：月省约 7000 元 + 把救火时间还给了新功能开发
    （最后半句是老板语言——钱的终点是"干更有价值的事"）

效率的杠杆排序（对老板最有效的表达顺序）：
  人力效率 > 机器效率 > 微观性能
  （砍半人天 > 砍半机器 > 快 20ms——除非快 20ms
    正卡在转化漏斗上，那它就是钱，见 day06 漏斗）
```

## 2. 核心概念（中英对照）

| 英文 | 中文 | 大白话 |
|------|------|--------|
| TCO | 总拥有成本 | 买来花的钱只是开始，运维/升级/人力才是大头 |
| Unit Economics | 单位经济模型 | 一单请求赚多少花多少——规模化后这是生死线 |
| DevEx | 开发者体验 | 工具好不好用=隐性人力成本（构建慢 10 分钟×每天 20 次×20 人=?) |
| Automation ROI | 自动化回报率 | 做自动化花 X 人天，每年省 Y 人天，回本周期=X/Y |
| Runway | 现金跑道 | 公司还能烧几个月——理解这个，才懂老板为什么砍机器钱 |

## 3. 动手实操（演练）

### 3.1 演练一：给项目五算三本账

```
项目五（AI 客服 Agent）的完整成本账：

机器钱（每万次咨询）：
  模型推理（本地 Ollama 折算电费+GPU 折旧）≈40 元
  检索/存储/网络 ≈15 元
  合计 ≈55 元/万次
  对照人工：客服 3 元/次 = 3 万元/万次
  → 一句账："AI 处理一万次咨询的成本是一次人工处理的
     550 分之一"（夸张但真实的数量级，口径要诚实：
     未含开发成本——下面人力钱补上）

人力钱（开发+维护摊销）：
  开发投入 25 人天（项目五全程）×190 元 ≈4.75 万（一次性）
  维护 ≈2 人天/月
  回本账：日均 2 万次咨询 → 日省人力成本 6 万×（AI 承担 78%）
  ≈4.7 万/天??——不对，重算：2 万次×3 元×78% ≈4.68 万/天
  → 开发成本一天回本？？诚实校正：真实场景咨询量没这么高、
    人工不是全部可替代——演示"估算→发现离谱→校正假设"的
    过程本身就是价值（敢自我纠错的数字才可信）
  校正后保守口径：日 2000 次咨询、AI 可替代率 60%：
    日省 2000×3×60% = 3600 元 → 回本周期 ≈4.75 万÷3600 ≈13 天

机会成本：
  不做这个项目，2 人力用来做什么？（写明备选项）
  备选：营销活动系统（预计季度增收 30 万）
  → ADR 式记录：选 AI 客服的理由=人力成本趋势性下降+
    可复制到多业务线（长尾价值）
```

### 3.2 演练二：效率杠杆自检清单

```
对自己团队/项目过一遍（每条配估算）：
| 杠杆项                    | 估算                          |
|--------------------------|-------------------------------|
| 构建/部署等待时间         | 每人每天浪费 30min×5 人=?      |
| 重复手工操作（发布/对账）  | 每周 2h×N 次=?，自动化 ROI=?   |
| 环境问题（"我本地好的"）   | 每次排查 2h，月均?次           |
| 会议（day05 的账）        | 无效会议占比?                  |
| on-call 打扰              | 每次打断 25min 恢复成本（上下文切换税）|

练习：挑一项做成"自动化提案"（对老板的 pitch）：
  "手工对账每周 2 人天，自动化投入 5 人天，
   回本 2.5 周，之后每月净省 8 人天。"
```

### 3.3 演练三：AI 陪练"只看报表的 CFO"

```
让 AI 扮演"只看成本曲线的 CFO"（比老板更狠）：
  CFO："你们的 AI 客服项目 ROI 是多少？"
  你：（三本账：机器 55 元/万次 vs 人工 3 万/万次；
      开发 4.75 万，保守口径 13 天回本；机会成本备选项对比）
  CFO："那再降 50% 机器钱呢？"
  你：（M16 的账：trace 采样+分层省存储 70%；
      模型换小杯+缓存命中 → 列可降项清单和代价）
  CFO："代价是什么？"
  你：（采样后 7 天前细节丢失→排查靠摘要；换小杯→考卷
      正确率需重测——诚实报代价，CFO 反而点头）
录音复盘：哪个数字被追问倒了=哪本账还不扎实。
```

### 3.4 思考题

为什么说"砍半人天比砍半机器更值钱"在多数公司成立？（提示：数量级对比——一台 4 核 8G 月租几百元，一个工程师月全成本几万元；且机器钱有云厂商帮你优化（竞价实例/包年），人力钱的优化只能靠效率工具和流程。例外：超大规模公司机器钱就是主成本，所以大厂拼命优化资源利用率。）

## 4. 面试连接

**Q：你怎么评估一个技术优化值不值得做？**
> 我算三本账：机器钱（基础设施节省）、人力钱（人天×全成本，这项通常贵一个量级）、机会成本（做了这个=放弃什么）。举项目五的例子：AI 客服机器钱约 55 元/万次咨询，人工是 3 万元/万次；开发投入 4.75 万，保守口径（日 2000 次、可替代 60%）13 天回本。我还做了一次自我纠错：最初按日均 2 万次算出"一天回本"，明显离谱，回头校正了假设——我宁可数字保守可信，不要夸大惊人。

**Q：老板让你砍一半基础设施成本，你怎么做？**
> 先分类再动手：可立刻降的（存储采样+冷热分层，M16 实测省 70%；资源右尺寸化）、要权衡的（模型换小杯——用考卷正确率验证兜底）、不能碰的（生产稳定性冗余——砍这个是省小钱赌大钱）。我会给老板一张"降本清单"，每项标收益、代价、验证方式——降本不是拍脑袋砍配置，是带着数据做选择题。
