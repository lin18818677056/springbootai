# Day 16 · 技术布道与分享：把博客⑫讲给组内听

> **今日目标**：把写好的内容改成"讲"的内容——完成一次 15 分钟组内技术分享的全流程设计；理解布道的本质不是炫技，是"让别人省时间"。
> **时长**：理论 0.5h / 演练 2h / 输出 0.5h
> **今日产出**：15 分钟分享稿（含讲稿+PPT 大纲）+ 完整录音

## 1. 知识地图（先讲人话）

```
写文章和做分享是两门手艺：
  写文章：读者自己控制节奏，可以回读，信息密度可以高
  做分享：听众只能跟着你走，走神 10 秒就永远丢了——
    所以讲稿必须"一句一个台阶"，密度砍半，例子翻倍
  类比：文章是说明书，分享是导游——
    导游不能把说明书念一遍，要挑最值得看的路。

15 分钟分享的黄金结构（组内场景）：
  [0-2min] 钩子：从听众的痛点切入（不讲"我今天分享 XX 主题"）
    例："大家有没有遇到过：查询一慢就无脑加缓存，然后被
    数据不一致坑？今天讲我踩过的三个坑。"
  [2-5min] 问题：坏在哪里，用真实数据/事故/截图
  [5-11min] 方案：最多三个要点（超过三个听众记不住），
    每个要点配一个图/一个数字
  [11-14min] 收益：听完能带走什么（清单/工具/模板）
  [14-15min] 钩子回收：开头的问题现在有答案了吗？+ QA

布道的心法：
  分享的第一受益人是自己——费曼法在团队场景的应用；
  别怕"内容太浅"：对 3 个人是复习，对 3 个人是新知，
  浅而清楚永远好过深而糊涂。
```

## 2. 核心概念（中英对照）

| 英文 | 中文 | 大白话 |
|------|------|--------|
| Tech Talk | 技术分享 | 组内定期的经验交流，低门槛高回报的影响力建设 |
| Elevator Pitch | 电梯演讲 | 30 秒讲清一件事（M14/M15 练过的，分享开场也用它） |
| Demo-driven | 演示驱动 | 能跑 demo 就别放截图——眼见为实的说服力翻倍 |
| Takeaway | 带走项 | 听众散会后还能用的东西：清单/模板/命令 |
| Q&A 主持 | 提问应对 | 答不上就说"好问题我回去验证，明天群里回你"——诚实比逞强加分 |

## 3. 动手实操（演练）

### 3.1 演练一：把博客⑫改造成 15 分钟分享稿

```
选材：博客⑫《性能优化四连问》——改为组内分享
  标题：《池子调大反而炸？我踩过的三个性能优化坑》
  （比"性能优化方法论"更勾人：具体+悬念）

逐段改造（写文章→讲人话）：
  钩子："每次上线前压测，是不是总有人说'调大点池子'？
    我上个月亲眼看着把线程池从 50 调到 500，P99 从 800
    涨到 2 秒——今天讲为什么。"
  要点一：池子不是越大越好（上下文切换的账）——
    配一张切换开销曲线图
  要点二：瓶颈在下游时，上游扩容=堆积爆炸——
    配 day08 的类比（收费站堵车，多开车道只会更堵到收费站）
  要点三：先测再调：四连问清单——
    现场发 takeaways 清单（纸质/群文件）
  回收："开头那个'调到 500'的锅，用四连问第一步就能拦住。"

PPT 大纲：每页一句话+一张图，总共 ≤12 页。
  （PPT 页数 = 分钟数：15 分钟最多 12 页，多必超时）
```

### 3.2 演练二：三次彩排法

```
第 1 遍（对稿讲）：可以看稿，目标=顺下来不卡
第 2 遍（脱稿讲）：只看 PPT，目标=每页一句话过渡自然
第 3 遍（掐表讲）：全脱稿+计时，目标=14 分 30 秒内讲完
  （留 30 秒缓冲，超时是分享会第一大事故）
每遍录音回听，抓三个问题：
  ① 口头禅（"然后""就是说"——数一下出现几次，下次有意识删）
  ② 语速失控的地方（一紧张就快——那段刻意放慢）
  ③ 听不懂的术语（术语第一次出现必须给一句人话解释）
```

### 3.3 演练三：QA 应对预演

```
准备三个最可能被问的刁钻问题（自己当刁民）：
  Q1"你这个数据是单机测试的吧，生产能复现吗？"
    A：诚实答："是本地压测，量级和生产有差距；但方向性结论
    （切换开销/下游瓶颈）不受影响。有生产环境时我可以补一组。"
  Q2"为什么不直接上缓存中间件/框架？"
    A："方案对比里测过，场景是 X 时自建更可控——这是 RFC 第 3 节，
    会后我把链接发群里。"
  Q3"这套方法对我们组的 Y 业务适用吗？"
    A："四连问是通用的，但阈值要按你们的依赖结构重测——
    有兴趣散会后一起跑一次。"
  心法：答不上=诚实+给跟进时间，逞强编答案一次就信用破产。
```

### 3.4 思考题

为什么说"分享的第一受益人是自己"？（提示：写文章已经倒逼你理清逻辑（费曼法第一步），讲出来还要再砍一层——那些"写的时候糊弄过去、讲的时候讲不圆"的地方，就是你理解的真实洼地。三次彩排中卡壳的位置=你该回去重学的位置。）

## 4. 面试连接

**Q：你在团队内做过技术分享吗？**
> 做过。最近一次讲"性能优化三个坑"：从压测时'调大池子反而炸'的真实案例切入，15 分钟讲三个要点，散会给每人发了一份'调优四连问'清单。我坚持三个原则：开场从听众痛点切入不讲套话、要点不超过三个、每页 PPT 只放一句话一张图。三次彩排掐表，实际讲完 14 分半。分享后有两个同事在各自项目里用上了四连问，避了一次坑——这是分享最好的回报。

**Q：分享时被问到不会的问题怎么办？**
> 直接说"好问题，我回去验证，明天群里回你"——诚实+具体时间点。技术分享最忌讳现场编答案，编错一次全场都记住。我还会把没答上的问题记进分享的 FAQ 附录，下次讲的时候补上——不会的问题处理好了，反而是加分项。
