# Day 15 · 主持技术评审：评审会全流程与收敛技术

> **今日目标**：掌握主持评审会的完整流程（会前材料/会中控场/会后决议）；重点练"收敛"——把发散争论收回决议的三种技术；完成一次全流程模拟评审主持。
> **时长**：理论 1h / 演练 1.5h / 输出 0.5h
> **今日产出**：评审主持流程卡 + 模拟评审主持录音（45 分钟全流程）

## 1. 知识地图（先讲人话）

```
评审会翻车的经典现场：
  开场没人看过材料 → 从头讲 40 分钟 → 讨论发散到宇宙 →
  时间到没结论 → "下次再对一次"（下次同样剧本）。
  病根：主持人把"开会"当"讲材料"，忘了开会的目的是"做决定"。

会前三件事（决定会议成败的 80%）：
  ① 材料提前 24h 发（RFC 五件套，day03 的标准）
  ② 提前收集意见（每人先提 1 条，会上只谈有分歧的）
  ③ 议程写清楚：讨论哪 3 个分歧点、各多久、要什么决议

会中控场（主持人的三个动作）：
  破题（5min）：不说客套话，直接说"今天要定三件事：
    A/B/C，现在开始第 1 件，10 分钟"
  控时（每 10min）："时间到，这条先记分歧，下一条"
    ——没有人喜欢但所有人都需要
  收敛（每条议题结束前）：三种技术——
    ① 表决收敛："两案各有理，我们投票，少数服从多数，
      记录在案"
    ② 试验收敛："吵不出结果因为缺数据——周一各出个
      压测数，周三用数据定"（把观点之争变成数据之争）
    ③ 升级收敛："这事影响成本预算，超出评审权限，
      我带结论找老板拍板"（诚实承认边界）

会后一封邮件：决议+行动项（谁/何时/做什么）+遗留分歧，
  24h 内发出——没邮件的评审等于没开。
```

## 2. 核心概念（中英对照）

| 英文 | 中文 | 大白话 |
|------|------|--------|
| Facilitation | 引导/主持 | 让会议产出结论的技术活，不是坐主席台 |
| Parking Lot | 停车场区 | 会跑题的好想法"停车"记录，散会后单独跟进（不丢也不让它劫车） |
| Timeboxing | 时间盒 | 每个议题固定时长，到点强制切换 |
| Decision Owner | 决策人 | 谁拍板提前明示——评审可以吵，最后总得有人定 |
| Follow-up | 跟进项 | 会后待办，没跟进的评审是"集体聊天" |

## 3. 动手实操（演练）

### 3.1 演练一：搭一场模拟评审（靶子：项目六方案）

```
评审材料：项目六性能优化的 RFC（day03 重写版）。
设计三个真分歧点（评审会最容易吵的三类）：
  分歧 A：缓存 TTL 设 5 分钟还是 30 分钟？
    （数据之争：命中率 vs 数据新鲜度——适合试验收敛）
  分歧 B：trace 用同步写还是异步写？
    （权衡之争：简单可靠 vs 性能——适合表决收敛）
  分歧 C：优化方案下季度要不要全团队推广？
    （权限之争：涉及人力预算——适合升级收敛）
  每个分歧点预演双方论据（自己写两边的台词），
  这就是你主持时的"剧本"。
```

### 3.2 演练二：45 分钟全流程模拟主持（本日重头戏）

```
用 AI 扮演 3 个评审人（人设写好）：
  评审甲（较真型）：每个数字都要问来源，容易拖时间
  评审乙（发散型）：总把话题带偏到"要不要重构整个系统"
  评审丙（沉默型）：不提前看材料，会上嗯嗯啊啊
主持演练流程（录音全程）：
  [0-5min] 破题：今天定 A/B/C 三事，议程和时间盒宣布
  [5-18min] 分歧 A：限时辩论 → 试验收敛（周一各出压测数）
  [18-30min] 分歧 B：乙跑偏时用"停车场"接住 → 表决收敛
  [30-40min] 分歧 C：升级收敛（超出权限，带结论找老板）
  [40-45min] 复述决议：逐条念"决议+行动项+遗留"，散会
  会后：24h 内写决议邮件（写给自己的演练作业）。
自检三问：每个分歧都收敛了吗？跑题接住了吗？超时了吗？
```

### 3.3 演练三：主持人的救场话术

```
三个高频翻车场景的救场台词（背下来）：
  ① 两人吵起来了："两位说的其实是两件事——甲说的是成本，
    乙说的是风险，都记下来，我们逐个过"（拆解+降温）
  ② 有人一言堂："这个观点记下了，我们听听还没说话的两位"
    （给沉默者让位）
  ③ 时间到了没吵完："这是重要的分歧，值得单独一个会。
    今天我先按 X 方向推进，反对的会后 24h 内找我"
    （默认推进+给异议窗口——别让"没吵完"变成"没结论"）
```

### 3.4 思考题

为什么"试验收敛"（用数据吵架）比"表决收敛"（用人数吵架）优先级更高？（提示：数据能改变人心，人数只能压服——被压服的一方表面服从，落地时消极执行；而被数据说服的人会成为方案的拥护者。数据也有边界：拿不到数据或数据不可信时，表决是诚实的兜底。）

## 4. 面试连接

**Q：你怎么主持一次技术评审？**
> 会前：材料提前 24 小时发+预收集意见，会上只谈分歧；会中：破题直接宣布"今天定哪三件事"，每条分歧限时，用三种收敛技术收尾——能做实验的用数据定，纯权衡的表决定，超权限的带结论升级老板；会后 24 小时发决议邮件（决议+行动项+遗留分歧）。我主持过项目六的评审会，三个分歧点全部收敛，没有一条"下次再对"——评审会最贵的成本是"没结论的重复开会"。

**Q：评审会上有人跑题或一言堂怎么办？**
> 跑题用"停车场"：好想法记下来"这条很有价值，单独立项讨论"，把话题请回来；一言堂就点名让位："这个观点记下了，听听还没说话的两位"。主持人的职责不是自己辩赢，是让所有观点被听见、所有议题有结论——收敛比雄辩更重要。
