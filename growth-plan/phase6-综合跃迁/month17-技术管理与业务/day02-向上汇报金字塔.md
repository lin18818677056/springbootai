# Day 02 · 向上汇报金字塔：30 秒讲清楚

> **今日目标**：掌握金字塔原理（结论先行）；学会老板语言三要素；把 M16 压测报告改写成"一页纸汇报"。
> **时长**：理论 1h / 演练 1.5h / 输出 0.5h
> **今日产出**：项目六金字塔版一页纸 + 3 分钟口播稿

## 1. 知识地图（先讲人话）

```
工程师汇报的通病（自检）：
  "我先调研了……然后试了 A 方案……中间发现 B 问题……"
  ——这是"过程流水账"。老板在第 2 分钟已经走神。
  他的内心OS：所以呢？要多少钱？有什么风险？

金字塔原理（结论先行，以上统下）：
  ❌ 线性讲述：背景→过程→过程→过程→（最后憋出结论）
  ✅ 金字塔：结论 → 三个理由 → 每个理由的事实
    老板任何时候打断你，你都已把最重要的说完了。

  类比：新闻标题。先给你"某地地震 5.1 级无人伤亡"，
  再展开时间地点细节——没人愿意听五分钟才被告知结论。

老板语言三要素（day01 翻译的底层逻辑）：
  ① 钱：这事省/赚多少？（成本、收益、ROI）
  ② 风险：会不会出事？出了事多疼？（确定性、兜底方案）
  ③ 进度：什么时候见效？（里程碑、依赖项）
  技术细节（P99/GC/采样）是支撑这三样的证据，不是主角。

SCQA 开场（汇报的标准起手式）：
  S 情境：AI 客服上线三个月，用户量涨了
  C 冲突：但响应越来越慢、存储成本月增 30%
  Q 问题：不加机器能不能撑住？
  A 答案：能——两周性能治理，快一半省八成，一分钱没花
  （先勾住注意力再给答案，答案又必须是金字塔顶）
```

## 2. 核心概念（中英对照）

| 英文 | 中文 | 大白话 |
|------|------|--------|
| Pyramid Principle | 金字塔原理 | 结论先行、以上统下、归类分组、逻辑递进 |
| BLUF (Bottom Line Up Front) | 底线前置 | 军方叫法：第一句就是结论 |
| Elevator Pitch | 电梯演讲 | 30 秒版本（M14/M15/M16 已练三次，今天是方法论化） |
| Executive Summary | 摘要 | 一页纸的最上面三行——老板只看这三行 |
| Trade-off | 取舍 | 所有方案都有代价，主动讲比被问出来强十倍 |

## 3. 动手实操

### 3.1 一页纸模板（直接抄用）

```
【一页纸汇报模板 · 项目六】
结论（一行）：两周性能治理完成：响应快 45%、存储省 80%，
  零硬件投入，且建立防退化机制。
—— 三个支撑（每条 ≤2 行）：
  ① 效果：5 轮会话 P99 从 __ms 降至 __ms；日志成本月省 ___ 元
  ② 方法：测量驱动（台账四格证据链），四项优化全部复测闭合
  ③ 保障：看板三指标+评审四连问，性能退化当天可发现
风险与取舍（一行，主动讲）：
  模型推理耗时占大头，本地硬件无法再压；高危路径刻意未并行
  （安全优先）。
需要的支持（一行，要资源或授权）：
  建议：下季度给 AI 服务预留独立压测环境（当前结论性数字
  依赖本地环境，需稳定环境复测定稿）。
```

### 3.2 3 分钟口播稿（SCQA + 金字塔）

```powershell
# 按 SCQA 开场 → 三个支撑 → 风险 → 请求支持，写成逐字稿
# 录音计时：目标 180±15 秒
# 自检三问：
#   ① 我在第 10 秒内给出结论了吗？
#   ② 每个支撑都能被老板的一句话追问接住吗？
#     （"省的 80% 怎么算的？"→"等比模拟 1 万会话实测，方法可复现"）
#   ③ 风险是我主动讲的还是等着被问的？
```

### 3.3 反向练习：找出"反例汇报"的毛病

```
拿到一段典型流水账汇报（自写或找同事的），动手改：
  ① 圈出"结论出现在第几行"——超过第 3 行就要动刀
  ② 把技术黑话全部换成三要素语言（钱/风险/进度）
  ③ 删掉所有"我试了/我发现/中间过程"——老板不需要剧情
——改完对比：信息量没少，字数少一半，说服力翻倍
```

### 3.4 思考题

什么时候应该"过程先行"而不结论先行？（提示：老板要的是"教他判断"而不是"要他拍板"时——比如复盘教学场景；或结论太反直觉需要铺垫认知时。但默认场景 99% 是结论先行——先给结论，老板自然会问过程，把讲述节奏的控制权交给他）

## 4. 面试连接

**Q：讲讲你怎么向高层汇报技术工作？**
> 金字塔结构：结论先行，三个支撑，主动讲风险，最后明确要什么支持。我固定用一页纸模板——结论一行、支撑三行、风险一行、请求一行。口播用 SCQA 勾注意力：情境、冲突、问题、答案 30 秒讲完，然后把时间留给追问。我拿性能治理项目练过完整版：老板三连问（值多少钱/风险/何时见效）都接得住。

**Q：老板不同意你的技术方案怎么办？**
> 先确认分歧在哪层：是信息差（他不知道某个约束）→ 补数据；是风险偏好（他觉得风险大）→ 给兜底和回滚方案降风险感知；是优先级（这事根本排不上）→ 尊重，降级为小成本验证。不硬顶——说服的本质是帮他降低决策成本，不是赢得辩论。
