# Day 22 · 项目七总设计：把项目六包装成"团队项目"

> **今日目标**：开启本月大演练——项目七不是新代码，是把项目六（性能优化）重新包装成一个"要推广、要汇报、要带人"的团队项目；今天完成项目七的全景设计（角色卡/里程碑/风险表对齐）。
> **时长**：设计 1.5h / 演练 1h / 输出 0.5h
> **今日产出**：项目七全景图 + 四场演练的"剧本卡" + 角色卡

```
为什么项目七"不是写代码"：
  技术管理的核心能力全在"技术之外"——汇报/评审/推广/调解。
  项目六给了我们最好的剧本素材（真台账/真数字/真坑），
  本月把它从"个人作品"升级成"团队项目"来演练管理动作。

项目七设定（一场"虚拟晋升"的剧本）：
  背景：你在项目六把 AI 客服 P99 降 40%、成本降 70%，
    老板很满意，给你两个新任务：
    ① 把优化经验推广成团队规范（day17 已设计）
    ② 一个月后向总监做季度汇报（day23 演练）
  你的角色：技术负责人（Tech Lead）——
    带两个虚拟组员（A：激进新人，方案党；B：稳妥老哥，风险党）
  对手角色：老板（要结果）、业务方（要排期）、
    其他组（要资源）——全部由 AI 或朋友扮演

项目七四周地图（与本月 W4 对齐）：
  day22 总设计（今天）：全景图+剧本卡
  day23 模拟向上汇报：总监季度汇报（15 分钟版）
  day24 模拟架构评审主持：新需求（物流工具）的方案评审
  day25 模拟冲突调解：A 和 B 的方案之争收敛
  day26 业务价值说明书：给业务方的三句话价值
  day27 管理复盘与评分：四场演练打分+短板清单

素材清单（全是前 16 个月的家底，今天盘点一遍）：
```

## 2. 核心概念（中英对照）

| 英文 | 中文 | 大白话 |
|------|------|--------|
| Tech Lead | 技术负责人 | 不一定管人，但要对"技术方向+交付质量+团队成长"负责 |
| Stakeholder | 干系人 | 所有"这事的结果影响他/他的意见影响这事"的人 |
| Simulation | 模拟演练 | 低成本练管理动作的方式：错在剧本里，不错在真团队里 |
| Debrief | 演练复盘 | 打完仗立刻对镜头：哪步走样了、为什么、下次怎么改 |
| Runbook | 剧本卡 | 演练前写好的"台词+流程+评分点"，让练习可重复 |

## 3. 动手实操（演练）

### 3.1 演练一：画项目七全景图

```
一张图画完整个项目（对老板 3 分钟版也能画）：

  【输入】项目六成果：P99 800→480ms / 成本降 70% /
          四连问清单 / RFC / 台账
             ↓
  【动作 1】规范推广：四连问 → PR 模板+CI 卡点 →
          试点（2 周）→ 度量汇报（day17 方案）
             ↓
  【动作 2】团队协作：新需求（物流工具）排期评审（day08 估算表）
             ↓
  【动作 3】季度汇报：三本账+规范推广数据 → 总监答辩（day23）
             ↓
  【输出】团队采用率 ≥90% / 压测返工 4→1 / 总监认可
          （=你的晋升答辩素材，直接进 M18 简历库）

  【贯穿】风险登记表（day10 的 5 条）周更 +
          每周五给老板的一页纸周报（day02 模板）
```

### 3.2 演练二：四场演练的剧本卡

```
每场演练一张卡（写好台词锚点+评分点，演练时照着走）：

卡 1·向上汇报（day23）：
  场景：向总监汇报季度成果，15 分钟+10 分钟答辩
  台词锚点：金字塔开场（结论先行）→三本账→风险与请求
  评分点：①老板三连问（值多少钱/风险/何时见效）接得住吗
        ②超时了吗 ③数字被追问时能报出处吗

卡 2·评审主持（day24）：
  场景：物流工具方案的架构评审，A 激进 B 稳妥
  台词锚点：会前议程→时间盒→三种收敛
  评分点：①三个分歧都有结论吗 ②跑题接住了吗 ③决议邮件发出吗

卡 3·冲突调解（day25）：
  场景：A 说"直接上 XXL-Job"，B 说"@Scheduled 就够"，僵持
  台词锚点：分别倾听→找共同目标→定标试验→收敛
  评分点：①有没有变成"你评评谁对"的裁判 ②共同目标找到了吗
        ③收敛结论双方都认吗

卡 4·业务价值说明（day26）：
  场景：业务方问"你们搞这些对卖货有什么用"
  台词锚点：漏斗→三句话价值→验证指标
  评分点：①有术语没翻译吗 ②有数字吗 ③业务方复述得出来吗
```

### 3.3 演练三：搭好虚拟团队人设

```
给两个 AI 角色写人设（陪练质量取决于人设质量）：
  组员 A（激进新人）：
    "毕业 2 年，技术热情高，什么新东西都想上。
     说话直接，被反驳会不服。重视成长机会。"
  组员 B（稳妥老哥）：
    "工作 8 年，见过事故，口头禅'先想清楚再动'。
     不善言辞但坚持原则，需要被追问才展开说。"
  老板（结果导向）：
    "关注成本和交付时间，对技术细节不感兴趣，
     三连问：值多少钱/有什么风险/什么时候见效。"
  业务方（排期敏感）：
    "只关心能不能按承诺上线，听不懂架构词汇，
     会用'那你到底能不能搞定'施压。"
存档：四个人设贴在演练笔记开头，每次陪练直接复制使用。
```

### 3.4 思考题

为什么用"包装旧项目"而不是"造新项目"来练管理？（提示：管理演练的关键是剧本真实——项目六有真台账真数字真坑，A/B 之争、老板三连问都有真实锚点；新造项目数字是编的，追问两层就露馅。这和 M13~M16 一直用的"项目串门"是同一个原则：资产复用，不是重复建设。）

## 4. 面试连接

**Q：你做过技术管理相关的工作吗？（诚实口径版）**
> 我的路径是"主导设计+小范围推行"：在性能优化项目中担任技术负责人角色——方案我主导、评审我主持、规范我设计并试点推广（PR 模板卡点+CI 检查，试点数据返工 4→1 次）；同时我系统练过管理动作——向上汇报按金字塔结构做过模拟答辩、冲突调解用"定标试验"收敛过方案之争（这是真实发生的一次：新人要上调度平台，老哥坚持内置方案，最后用定标+POC 数据收敛）。带团队经验我没有虚构，但这套方法和肌肉是真的练过的。

**Q：技术负责人和管理者的区别？**
> 管理者靠组织赋予的职权，技术负责人靠技术判断力+影响力——没有"你听我的"的权力，只有"我讲得有理+我做得到"的信用。我练的就是后者：主持评审靠收敛技术不靠拍桌子，推规范靠卡点和试点数据不靠命令。这个角色在任何团队都能马上用起来。
