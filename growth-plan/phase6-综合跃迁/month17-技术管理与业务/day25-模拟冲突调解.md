# Day 25 · 模拟冲突调解：把方案之争收敛成共同行动

> **今日目标**：专攻"人和人"的冲突（区别于 day24 的"方案之争"）——掌握调解四步法（分别倾听/找共同目标/定标试验/收敛确认）；演练一次升级版冲突（情绪已上头+有历史积怨），录音复盘。
> **时长**：理论 0.5h / 演练 1.5h / 复盘 0.5h
> **今日产出**：调解四步卡 + 升级冲突演练录音 + 复盘记录

## 1. 知识地图（先讲人话）

```
先分清三种"冲突"（对症下药）：
  ① 事实之争：数据能解决（"接口平均 200ms 还是 800ms"——
    查监控）→ 最低级，别让团队耗在这
  ② 方案之争：目标一致路径不同（day24 的 X vs Y）
    → 定标+Spike 收敛
  ③ 人之争：情绪和立场已上头（"他就想抢功""她从来不尊重我"）
    → 今天的主菜，数据解决不了，要先处理情绪再处理事
  判断口诀：吵的内容能不能用一张数据表解决？
    能=①或②；不能=③。

调解四步法（针对③，也兜底②）：
  第 1 步·分别倾听（背对背）：先各聊 15 分钟，只听不判——
    让情绪先泄压（上头的人讲不出道理，先让他讲完委屈）
  第 2 步·找共同目标（当面）：把两人拉回"咱们共同要什么"——
    "你俩都想项目按时上线，对吗？"（先对齐再谈分歧，心法②）
  第 3 步·把人问题翻译成事问题：
    "他抢功"→"上线汇报里没有你的名字，你希望署名规则怎么定？"
    "她不尊重我"→"评审时被当众打断，你希望评审规则怎么改？"
    （情绪词全部翻译成可执行的规则请求——规则能改，人不 fun）
  第 4 步·收敛确认：产出 1~2 条双方都点的头的新规则+
    书面记录+两周后回访（调解不回访=白调）

红线：什么时候上报老板——
  涉及职场霸凌/价值观冲突/影响交付的死结——
  调解不是万能的，诚实上报比硬扛更职业（day10 上浮原则）。
```

## 2. 核心概念（中英对照）

| 英文 | 中文 | 大白话 |
|------|------|--------|
| Mediation | 调解 | 不做法官做媒人：让双方自己达成协议 |
| Active Listening | 积极倾听 | 听完+复述对方的话（"你的意思是我理解对吗"）——泄压第一神器 |
| Interest vs Position | 诉求 vs 立场 | 立场是"我要 XXL-Job"，诉求是"我要部署效率"——谈判在诉求层解决 |
| Psychological Safety | 心理安全 | 冲突不断的团队往往缺这个：敢暴露分歧的团队才健康 |
| Disagree & Commit | 异议且执行 | 亚马逊规矩：可以保留意见，但决策后全力执行 |

## 3. 动手实操（演练）

### 3.1 演练一：升级冲突剧本搭建

```
剧本背景（比 day24 更狠——加了"人和历史"因素）：
  组员 A（新人）：连续两次方案被 B 评审打回，认为 B
    "故意针对新人"；A 直接绕过 B 把方案发到大群@老板。
  组员 B（老哥）：认为 A "不守流程、越级上报、方案毛糙"，
    在组内小群说 A "基础差还不虚心"（传到 A 耳朵）。
  你（技术负责人）：两人都来找你告状，项目排期还压着。
  冲突等级：情绪上头 ✓ 立场对立 ✓ 历史积怨 ✓ 影响交付 ✓
  ——四级全中的"教学完美风暴"。
给 AI 写好双方人设+台词（告状时的原话要"情绪化"——
  "你就是评评理，他是不是针对我？"）。
```

### 3.2 演练二：四步调解实战（录音）

```
第 1 步·分别倾听（你 × A，再 × B，各 15'）：
  A 说"他针对我"→ 你复述："连续两次被同一个评审打回，
    你觉得不公平，还绕过流程发了大群，是这样吗？"
    （复述=泄压阀：感到被听见，火就小一半）
  B 说"他毛糙还不守规矩"→ 复述："你担心的是质量和流程
    被破坏，大群那下你觉得被架空了，对吗？"
  你的纪律：只复述不评判（"他确实不对"这句话第 1 步不许说）
第 2 步·共同目标（三人碰头开场白）：
  "今天不评对错，只解决一件事：项目按时上线，
   且你俩以后协作不内耗。同意吗？"（先要两个点头）
第 3 步·翻译（把告状词变成规则请求）：
  A 的"针对我" → "评审意见要写清理由和参考"（规则化 ✓）
  A 的"越级" → "对评审结果不满，先找评审人复议，
    24h 未决再找我"（升级路径规则化 ✓）
  B 的"小群发言" → "对人评价只在 1:1 说，群里只说事"（✓）
第 4 步·收敛确认：
  三条规则复述+双方点头+"两周后我们碰 10 分钟看执行"。
```

### 3.3 演练三：复盘（比演练本身值钱）

```
回听录音，逐段检查：
  ① 我有没有哪一刻站队了？（"B 你说话也过分了"——
    这就是站队，哪怕说的是事实；第 1 步只该听）
  ② A/B 的情绪词我翻译完整了吗？（漏翻的列出来——
    每个漏翻的情绪词都是下次爆炸的雷）
  ③ 规则是否可执行可检查？（"互相尊重"不可检查=废话；
    "群里只说事"可检查=好规则）
补课卡：把三条新规则写成"团队协作小宪法"存档——
  下次新人入职直接给他看（调解成果制度化=长效药）。
```

### 3.4 思考题

为什么"把人问题翻译成事问题"是调解的核心技术？（提示：人评价（"他针对我"）不可证伪也不可执行，只会激起防御；规则请求（"评审意见写清理由"）可执行可检查，且不针对人格——双方从"对抗彼此"变成"共同遵守规则"。翻译的本质是把战场从情绪层搬到工程层——而工程层是我们的主场。）

## 4. 面试连接

**Q：讲一次你处理团队冲突的经历。**
> 新人和老同事的方案之争升级成了互告状——新人觉得被打压绕过了评审，老人在小群说了重话。我的处理分四步：先分别倾听只复述不评判，让双方泄压；然后把两人拉回共同目标"项目按时上线+协作不内耗"；最关键的是把情绪词翻译成规则——"针对我"变成"评审意见写清理由"，"越级"变成"先复议再上报"的升级路径，"小群发言"变成"群里只说事"。三条规则双方点头，两周后回访确认执行。我的心得：调解不是评对错，是把战场从情绪层搬到规则层。

**Q：什么冲突你会选择上报？**
> 三种：涉及职场霸凌或价值观问题（超出我的权限和职责）；调解两次仍死结且开始影响交付（止损优先）；涉及薪酬晋升等我只知片段信息的事（信息不全时下判断会不公）。上报时我带事实记录和已做的调解动作，不带个人判断——让有权限的人做权限内的决策，这是对流程的尊重。
