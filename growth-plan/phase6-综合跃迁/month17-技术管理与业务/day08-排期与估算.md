# Day 08 · 排期与估算：人天的三坑与缓冲的算法

> **今日目标**：学会科学估算工作量——识破"拍天数"的三大坑；掌握"拆任务→估人天→留缓冲"全流程；理解为什么诚实上报风险比"先答应后跳票"更职业。
> **时长**：理论 1h / 演练 1.5h / 输出 0.5h
> **今日产出**：一个真实需求的估算表（含缓冲推导）+ 跳票预防话术

## 1. 知识地图（先讲人话）

```
为什么工程师估的天数总是不准？三个坑（对号入座）：
  坑① 遗漏隐藏工作：只算了"写代码"，漏了联调/测试/部署/
      写文档/开会/等环境——写作本身只占真实工时的 40%
  坑② 盲目乐观：只想象顺利路径。类比：你估"开车回家 40 分钟"，
      是按一路绿灯算的，没算堵车和找车位
  坑③ 没留缓冲：把理想值当承诺值报出去，一出意外就是跳票

科学估法四步：
  ① 拆任务：拆到"一个人 0.5~2 天能完成"的粒度（拆不细=估不准）
  ② 逐项估：每项按"顺利值"，但用"三点估算"校验——
      期望值 =（乐观 + 4×最可能 + 悲观）÷ 6（PERT 公式，包工头都在用）
  ③ 加缓冲：不是拍脑袋加 50%，是显式列风险清单——
      每个风险对应几天缓冲，说得出理由（缓冲要能解释）
  ④ 对承诺：报给别人的日期 = 期望值+缓冲；自己心里留 10% 私房缓冲

类比总结：
  估算像做预算，不是许愿——每个数字都要能被追问"怎么算的"。
```

## 2. 核心概念（中英对照）

| 英文 | 中文 | 大白话 |
|------|------|--------|
| WBS | 工作分解结构 | 把大任务拆成小任务清单，拆到能估为止 |
| PERT | 三点估算 | （乐观+4×可能+悲观）÷6，让悲观情况也有话语权 |
| Buffer | 缓冲 | 显式的"意外预备金"，必须列清楚防什么 |
| Velocity | 团队速率 | 团队一个迭代能稳定消化多少工作量（用历史数据校准估算） |
| Scope Creep | 需求蔓延 | 干着干着范围越变越大——跳票的头号元凶（day11 砍需求接这棒） |

## 3. 动手实操（演练）

### 3.1 演练一：给真实需求做完整估算

```
需求：给项目五的 AI 客服新增"物流查询"工具（查快递）。

WBS 拆解（示范，注意隐藏工作的占比）：
  ① 快递公司 API 调研与申请        0.5d
  ② 工具接口开发（含三道闸）        1d
  ③ 单元测试+对抗实验（幻觉参数）    1d
  ④ 工具描述编写+考卷补 5 题        0.5d   ← 描述和考卷最容易漏
  ⑤ 联调（快递 API 环境问题）       0.5d   ← 悲观 2d（对方响应慢）
  ⑥ 灰度上线+日报指标验证           0.5d
  ⑦ 文档与评审材料                  0.5d
  写码合计 2d，全任务 4.5d ← 印证"写码只占 40%"

三点估算（以③联调为例）：
  乐观 0.25d / 最可能 0.5d / 悲观 2d
  期望值 =（0.25 + 4×0.5 + 2）÷ 6 ≈ 0.7d

缓冲推导（显式列风险）：
  快递 API 申请审批延迟：+0.5d（外部依赖，概率中）
  首次灰度指标异常回滚：+0.5d（历史概率 30%）
  → 对外承诺 6d，内部私房缓冲再 +0.5d
```

### 3.2 演练二：跳票预防话术（最值钱的演练）

```
坏消息要提前说（心法③），话术模板：
  提前预警（还来得及的时候）：
  "物流工具联调依赖快递公司 API 审批，目前还没批下来。
    如果周三前批不下来，上线日期要顺延 2 天。
    我建议：A 方案先用模拟数据灰度，B 方案等审批。
    您倾向哪个？"
  要点拆解：
  ① 现象+影响+时间点（不猜、不藏、给_deadline）
  ② 带选项去（不是抛问题，是带方案）
  ③ 让老板做选择题，不是做阅读理解

对照反面话术："应该没问题，我加加班。"——
  （跳票时的信用破产，就是这句话埋的雷）
```

### 3.3 演练三：AI 陪练"追问式老板"

```
让 AI 扮演老板连环追问你的估算：
  "6 天怎么算的？" → 念 WBS
  "为什么联调要留 2 天悲观？" → 外部依赖历史数据
  "缓冲能不能砍？" → 能，但砍哪条风险你拍板，后果一起确认
  "能不能 3 天搞定？" → 能砍范围：只上主快递公司，
    四小厂下期做（范围换时间，day11 砍需求的伏笔）
录音回听：被问住的地方就是估算依据不足的地方。
```

### 3.4 思考题

为什么"用历史团队速率校准估算"比"个人拍脑袋"更准？（提示：速率是团队真实产出的平均值，天然包含了开会、等待这些隐藏工作——它不是更乐观的数字，是更诚实的数字。）

## 4. 面试连接

**Q：你怎么做工作量评估？准确率如何？**
> 四步：拆任务到 0.5~2 天粒度、逐项三点估算、缓冲显式列风险清单（每条缓冲能解释防什么）、对外报期望值+缓冲。我给自己定的规矩是每个数字能被追问"怎么算的"。经验上写码只占真实工时四成，联调测试文档占大头——漏这些就是新人估算最常见的坑。

**Q：项目要延期了你怎么处理？**
> 尽早说+带方案说。我的模板是"现象、影响、时间点、AB 选项"：延期多久、影响谁、什么时候是决策最后期限、我建议哪个方案。绝不拖到 deadline 当天才说"完不成"——提前一周说是风险管理，当天才说是事故。跳票的信用损失远大于提前暴露的印象损失。
