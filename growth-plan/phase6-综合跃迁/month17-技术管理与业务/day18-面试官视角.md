# Day 18 · 面试官视角：怎么面 P6、考什么、怎么评

> **今日目标**：站到桌子另一边——以面试官视角理解 P6 面试考什么、怎么评分；为自己 M18 的被面做"知己知彼"准备；完成一次模拟面试官出题+评分。
> **时长**：理论 1h / 演练 1.5h / 输出 0.5h
> **今日产出**：P6 考察矩阵 + 模拟出题 5 道（含评分标准）+ 一份自我评分

## 1. 知识地图（先讲人话）

```
面试官和候选人的视角差（换了座位才看得懂）：
  候选人想：我怎么展示我会的
  面试官想：我怎么确认"他真的会"而不是"背过"——
    所以面试官的必杀技是追问："为什么？""还有吗？"
    "你这个数字怎么来的？"——背的答案追两层就露馅。
  推论：准备面试的最好方式不是背答案，
    是把自己的每个项目追问三层（本计划 day29 验收一直在干这事）。

P6（3~5 年）考察矩阵（面试官的评分表长这样）：
  基础（30%）：JVM/并发/MySQL/Redis——不是背八股，
    是"能不能用原理解释现象"（如"池子调大为什么反而炸"）
  工程（40%）：做过什么项目、自己负责的部分能不能讲透、
    有没有"量→改→量"的证据（台账/数字/复盘）
  协作（20%）：冲突怎么处理/跨团队怎么对齐——
    用 STAR 要具体例子，说"我们团队很和谐"直接扣分
  潜力（10%）：学习习惯（有输出吗）/复盘意识/诚实度
    （答不上装会=一票否决项，面试官最烦这个）

面试官给分的秘密：
  通过=有一两个让面试官"哦？"的点（亮点记忆点）；
  挂掉=暴露"背的"痕迹+关键题答不上还绕。
  → 你的策略：准备 2~3 个深挖到底的"阵地项目"
    （项目五/六），把面试官往阵地上引。
```

## 2. 核心概念（中英对照）

| 英文 | 中文 | 大白话 |
|------|------|--------|
| Probing | 追问 | 面试官的深挖技术：连问"为什么/怎么做的/还有吗"直到边界 |
| STAR | 情境-任务-行动-结果 | 讲项目故事的万能结构（M18 主菜，今天先见个面） |
| Bar Raiser | 把关人 | 亚马逊式终面角色：有权否掉"及格但不优秀"的候选人 |
| Signal | 信号 | 面试官在答案里抓的关键证据（数字/取舍/反思） |
| Bias | 偏差 | 面试官也是人：首因效应/光环效应都存在——所以开场前 5 分钟最重要 |

## 3. 动手实操（演练）

### 3.1 演练一：站在面试官角度出 5 道题

```
给自己出 P6 题（附评分标准——出题比答题暴露更多）：
  ① "讲一个你排查过的性能问题，从头到尾。"
    评分：有没有量（瓶颈数据）→有没有假设验证过程（不是瞎猜）
    →有没有改后对比数字→有没有副作用交代。四层全有=优。
  ② "线程池参数你怎么定？直接说结论也行。"
    评分：说"看场景定"是合格线；能讲 IO 密集/CPU 密集公式
    再补"但公式只是起点，压测定参才是终点"是优秀
    （最后半句=不被八股框住的信号）。
  ③ "你和产品意见不合吵起来了，怎么办？"
    评分：说"听产品的"=差（没原则）；说"吵"=差（没方法）；
    讲具体案例+"区分价值判断/成本判断+三档方案"=优
    （day11 的东西直接能用）。
  ④ "你最近学了什么新东西？"
    评分：有具体主题+学习路径+输出物=优；"在学 XX"没下文=差。
    （本计划 18 个月的任何一个月都是弹药）
  ⑤ "有什么想问我的？"
    评分：问"加班多吗"不是不行，但只问这个=减分；
    问"团队目前最大的技术挑战""这个岗位三个月后的预期产出"
    =加分（问问题=你在评估他们，平等姿态的信号）。
```

### 3.2 演练二：用自己出的题给自己评分

```
流程：把 5 道题给自己答一遍（录音，每题 3 分钟），
  然后扮演面试官按评分标准给自己打分：
  题目①：____ 分  卡壳点：____
  题目②：____ 分  卡壳点：____
  ……
  自评最诚实的方式：隔一天再听录音——
  当时的自己觉得讲得挺好，隔天一听全是毛病的点，就是真毛病。
输出：自我评分表+三张"面试防翻车卡"（卡壳题写成卡片）。
```

### 3.3 演练三：AI 陪练"追问两层"

```
让 AI 扮演"职业追问型"面试官，规则说清：
  "你对每个回答追问两层：为什么？这个数字怎么来的？"
  示范链路：
  你："我把 P99 从 800ms 优化到 480ms。"
  AI："怎么定位到瓶颈的？"
  你："压测+链路追踪，发现慢在缓存穿透打库。"
  AI："为什么缓存会穿透？你们的 key 怎么设计的？"
  你：（第三层开始吃力？——这就是你准备的边界，
      M18 前把边界再往外推一层）
录音复盘：被追问卡壳的两层边界记录下来。
```

### 3.4 思考题

为什么说"准备 2~3 个深挖到底的阵地项目"比"全面复习"更划算？（提示：面试官追问的深度决定评价，而你有权引导话题走向——提到项目时给足钩子（数字/反常识点），面试官天然会追问你最熟悉的那个；主动权在自己手里时，挖多深你说了算。全面复习摊薄精力，阵地深耕集中火力。）

## 4. 面试连接

**Q：（这题本身就是演练——模拟面试官问）你的项目里最有挑战的技术决策是什么？**
> 性能优化里"先缓存还是先改 SQL"的那次。当时直觉是加缓存最快，但我先跑了四连问的第二步：用慢查询日志看数据，发现 80% 慢查询集中在一个聚合 SQL——先改 SQL（加覆盖索引+改写子查询）P99 就降了 60%，缓存反而只做兜底。这个决策教我的事：直觉方案和最优方案经常不是同一个，先用数据定方向。这也是我后来把"四连问"推广成组内规范的原因。

**Q：（反向题）你面过别人吗？你怎么评候选人？**
> 参与过组内面试（诚实口径：辅助面试+出题，不是主面官）。我的体会是换了座位才懂两件事：一是面试官靠追问辨真假，背的答案两层就露馅，所以我把自己的每个项目都自我追问过三层；二是面试官需要"信号"——具体数字、真实取舍、复盘反思，比形容词有用。这两个认知反过来改造了我自己的面试准备方式。
