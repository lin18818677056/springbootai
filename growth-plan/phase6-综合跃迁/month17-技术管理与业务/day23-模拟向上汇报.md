# Day 23 · 模拟向上汇报：项目六的成本账答辩

> **今日目标**：兑现 M16 交接卡①——把"P99 降 40%、存储省 70%"讲给老板听；完成一场 15+10 分钟的总监季度汇报全流程（汇报+三连问答辩），录音并按评分卡打分。
> **时长**：备稿 1h / 演练 1h / 复盘 0.5h
> **今日产出**：15 分钟汇报稿 + 答辩录音 + 自评分卡

## 1. 知识地图（先讲人话）

```
向上汇报的完整心法（前面学的全用上）：
  day02 金字塔：第一句话就是结论——
    "本季度我们系统性能提升 40%、成本下降 70%，
     并把方法论沉淀成了团队规范"（30 秒内说完这句）
  day06 业务翻译：技术指标→业务语言——
    P99 降 40% →"用户等待砍半，急躁放弃的少了"
    成本降 70% →"同样机器多扛三倍的量"
  day20 三本账：机器钱/人力钱/机会成本，老板问钱有三层答案
  day10 风险上浮：汇报必带风险——
    "有两个风险我盯着：压测环境资源和模型版本升级，
    都有触发信号和预案"（主动交底=信任倍增器）

15 分钟汇报结构（总监场景）：
  [0-1min] 结论先行：三个数字+一句"方法论已沉淀为团队资产"
  [1-5min] 三件事：性能台账（量→改→量的证据链）/
    成本三本账 / 规范推广（四连问+卡点，返工 4→1）
  [5-10min] 过程亮点（挑 2 个）：自我纠错的成本账/
    "池子调大反而炸"的坑（讲坑比讲成绩更可信）
  [10-13min] 风险与请求：风险 2 条+向老板要的支持
    （例：压测环境专属时段的授权）
  [13-15min] 下季度计划：三件事+预期数字
  答辩 10 分钟：老板三连问必来（见演练二）

老板三连问的答案库（提前写好）：
  Q1"值多少钱？" → 三本账（月省 7000 元+13 天回本+人力释放）
  Q2"有什么风险？" → 风险表前 2 条（带触发信号+预案）
  Q3"什么时候见效？" → 已见效+下季度三个可验证里程碑
```

## 2. 核心概念（中英对照）

| 英文 | 中文 | 大白话 |
|------|------|--------|
| Executive Summary | 执行摘要 | 一页纸/一分钟版本，先给这个，老板要细节再展开 |
| Ask | 请求 | 汇报的隐藏目的：要资源/要授权/要背书——不说出口=白汇报 |
| BLUF | 结论先行 | Bottom Line Up Front：先说底线结论，美军的汇报规矩 |
| AMBER | 亮黄灯 | 汇报风险的常用色：绿=顺利/黄=有风险但可控/红=需要介入 |
| Debrief | 复盘 | 汇报完立刻自评：哪里说错了、老板什么反应、下次怎么改 |

## 3. 动手实操（演练）

### 3.1 演练一：写 15 分钟汇报稿

```
用"一页纸"格式写（照抄模板填数字）：
  ═══════════════════════════════════
  【一句话结论】
  本季度 AI 客服性能优化：P99 降 40%、成本降 70%，
  方法论沉淀为团队规范（试点返工 4→1 次）。
  【三个支撑】
  ① 性能台账：12 条优化，每条"量→改→量"有证据
     代表案例：缓存穿透治理（命中 52%→85%）
  ② 成本三本账：机器月省 3000 元、人力月省约 1900 元、
     机会成本=救火会取消（1 人天/月还给开发）
  ③ 规范落地：四连问 PR 模板+CI 卡点，试点填写率 94%，
     拦截 3 次（含一次"池子调到 500"）
  【风险 2 条（黄灯）】
  压测环境资源紧张（应对：申请专属时段——今天要的授权）
  模型升级格式漂移（应对：考卷回归+版本锁定）
  【下季度三件事】
  物流工具上线（解决率 78%→82%）/ 规范全组推广 /
  压测自动化（返工目标再降 50%）
  【请求】压测环境周五专属时段授权（影响：优化迭代速度×2）
  ═══════════════════════════════════
  自检：第一段 30 秒能说完吗？有 Ask 吗？风险主动交底了吗？
```

### 3.2 演练二：全流程模拟（汇报 15'+答辩 10'）

```
AI 人设（day22 的老板人设+加狠）：
  "你是技术总监，时间紧张，听汇报只抓三件事：钱、风险、
   时间。习惯打断，听到模糊的数字立刻追问'这个数怎么来的'。
   对主动交风险的下属加信任分。"

流程：
  第 1 遍：完整讲完 15 分钟（掐表！超时重讲）
  第 2 遍：只讲 5 分钟版（总监说"我只有 5 分钟"——
    这才是真实世界的常态：金字塔这时救命）
  第 3 遍：15'+答辩 10'，AI 至少追问：
    "值多少钱？""这个 70% 怎么算的？""什么时候见效？"
    "试点 4→1 的样本是不是太小？""要的环境批了，
    一个月后给我看什么数字？"
录音复盘：第 5 分钟被打断时你还接得住吗？
```

### 3.3 演练三：答辩刁难题库预演

```
五个最刁钻的问题，答案提前写好：
  Q1"你这套数字都是本地压测，生产算数吗？"
    A：口径诚实："量级有差距，方向性结论成立。我建议生产
    灰度后用三指标验证（成本曲线/客服人力/客诉率），
    这是验证方案。"
  Q2"四连问试点才一个组，凭什么全组推？"
    A："所以我只申请扩大到 2 个组再评估，不一步到全组。
    扩组成本是零（卡点已自动化）。"
  Q3"优化空间还有吗？是不是该转去干别的了？"
    A："台账还剩 3 条低息债（列出来），预期合计再降 10%，
    边际收益递减——我同意主力转新功能，优化转常态维护。"
  Q4"如果下季度性能又劣化了怎么办？"
    A："日报六指标+回归考卷就是防劣化的哨兵，触发线写死
    （P99 超 600ms 告警），24h 内有响应 SOP。"
  Q5"你要的专属时段，别的组也要，凭什么给你？"
    A："我带了排期表：当前周四凌晨低峰期空置，我只要这个
    窗口，不影响任何组；两周后我拿优化数据向各位汇报。"
```

### 3.4 思考题

为什么汇报里"主动讲 2 个坑"比"全讲成绩"更有效？（提示：全讲成绩会触发老板的"水分探测器"——他不信没有坑的项目；主动讲坑+讲怎么爬出来的=既展示诚实又展示能力，还提前把"面试官式追问"的弹药递给了老板。注意配比：坑的比例不超过 1/3，且必须是"已解决的坑"。）

## 4. 面试连接

**Q：你怎么向高层汇报技术工作？（直接用今天的实践答）**
> 三条纪律：结论先行（30 秒内给三个数字和一句话总结）；讲业务语言（P99 降 40% 我会翻译成"用户等待砍半"，成本降 70% 翻译成"同样机器多扛三倍量"）；主动交底风险（永远带两条黄灯风险+触发信号+预案，外加一个明确的 Ask）。我完整演练过 15+10 分钟的总监答辩，被追问"70% 怎么算的"能报出三本账的口径——数字的出处比数字本身更能建立信任。

**Q：汇报被打断/时间被压缩怎么办？**
> 我永远同时备 15 分钟版和 5 分钟版。压缩时的取舍原则：保结论+三本账+Ask，砍过程细节——总监要的是决策信息，不是工作日志。被打断时不慌，用"您关心的这点在第三部分，我先一句话回答……细节需要展开吗"来接——打断不是危机，是他在告诉你他关心的重点。
