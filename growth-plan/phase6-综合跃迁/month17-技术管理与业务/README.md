# Month 17 · 技术管理与业务（M17）

> **本月一句话**：从"最好的球员"转型"教练"——技术管理的本质不是管人，是让事情成：把技术翻译成业务听得懂的价值，把经验沉淀成团队跑得动的规范。
> **主战场**：拿项目六（性能优化）当演练素材——它的台账、报告、四连问，本月全部升级成"对老板讲、对团队推、对业务说"的版本。

## 1. 开场先讲人话：管理者 = 让十一个人赢球的教练

```
球员思维 vs 教练思维（本月要完成的转型）：
  球员：我自己进球（写好我的代码）
  教练：让十一个人赢球（让团队产出，哪怕我一行代码没写）
  三种心态转变：
  ① 产出观：我的产出 = 团队产出之和，不是我个人代码量
  ② 成就感：别人因为我的指导做成了事 > 我自己做成事
  ③ 汇报观：让老板"看得懂、信得过、敢拍板"也是硬技能，
    不是"耍嘴皮子"——看不懂的方案永远通不过

管理三件套（本月主线，都是可练习的工程能力）：
  ① 沟通工程：向上汇报/向下反馈/跨团队对齐（day02/04/13）
  ② 组织工程：排期/风险/评审/带人（day08~15）
  ③ 判断工程：技术债/选型/砍需求/成本账（day09/11/19/20）

M16 交接卡（上月的病历）：
  ① "P99 降 40%、存储省 70%"怎么讲给老板听？
    → day23 模拟向上汇报：技术价值翻译成机器钱/用户体验/确定性
  ② "池子调大反而炸"这类坑怎么沉淀成团队规范？
    → day17 规范推广实战：四连问从"我遵守"到"团队真遵守"
```

## 2. 核心心法三句（本月反复出现）

```
① 管理不是玄学是工程——沟通/组织/判断都能拆步骤练
② 先同步认知再推进度——80% 的"执行走样"是"理解没对齐"
③ 好消息从下往上会缩水，坏消息要主动往上传——
  暴露风险是管理者的义务不是失误
```

## 3. 四个硬指标（月底验收要对数字）

```
① 向上汇报：5 分钟版项目六汇报完整通过模拟答辩（老板三连问
  全接得住：值多少钱/有什么风险/什么时候见效）
② 规范落地：评审四连问完成"工具卡点+推广话术"全套设计
③ 排期估算：一个真实需求完成"拆任务+估人天+留缓冲"全流程，
  误差复盘有方法（不是拍脑袋）
④ 冲突调解：一次评审争执的模拟调解有录音复盘（各让一步的
  依据写清楚）
```

## 4. 八条验收标准（day30 逐条对账）

```
1. 能讲清球员→教练三种心态转变，并举自己的真实例子
2. 金字塔原理写一页纸汇报（结论先行/三层支撑），模板可复用
3. RFC 技术方案按"团队可评审"标准重写项目六报告
4. 主持一次模拟架构评审：流程完整（破题/收敛/决议/记录）
5. 四连问规范推广方案：卡点工具+试点话术+度量指标
6. 需求评审能挑出 3 个真问题并给出砍/留决策依据
7. 完成"业务价值说明书"：自己项目对业务的三句话价值
8. 全月四个模拟演练（汇报/评审/调解/访谈）全部有录音+复盘
```

```

  项目五 Agent / 项目六 性能台账与压测报告 / 评审四连问 /
  日报六指标+性能三行 / 电梯演讲两版 / 博客⑩⑪⑫

  ② "对手"人选：让家人/朋友/AI 扮演老板/业务方/质疑者
    （AI 提问陪练：让 AI 扮演"不客气的 CTO"对你连环追问）
  ③ 一页纸模板：金字塔汇报/RFC/风险登记表（day02/03/10 交付）

  模拟的价值在于"动作标准化"，真上任时肌肉记忆已经在了；
  面试讲管理经验时口径要诚实（"我主导设计+小范围推行"，
  不虚构带团队经历——中下水平的诚实人设是本计划一贯原则）
```
