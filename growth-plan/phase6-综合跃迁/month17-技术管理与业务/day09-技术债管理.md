# Day 09 · 技术债管理：债的分级与偿还计划

> **今日目标**：像看待金融债一样看待技术债——会分级、会算利息、会排偿还计划；学会"跟业务借债"的话术（借债不可耻，失控才可耻）。
> **时长**：理论 1h / 演练 1.5h / 输出 0.5h
> **今日产出**：自己项目的技术债台账（分级+利息+偿还计划）

## 1. 知识地图（先讲人话）

```
技术债 = 为了快而欠下的"将来要还的账"：
    类比买房贷款：先借钱上车（快速上线），每月还月供（维护成本），
    利率高了会压垮现金流（维护成本吞掉新功能开发时间）。

技术债三种来源（别把屎山都叫技术债）：
  ① 明知故借：为了赶 deadline 有意走捷径（好债：借的时候想好了怎么还）
  ② 无知之债：当时不知道更好的做法（多数债，靠评审和学习还）
  ③ 被迫之债：历史原因+人员流动，没人说得清（最危险，利息最高）

债的利息怎么算（面试亮点）：
  利息 = 每次改动这块代码多花的时间 + 出故障的概率×故障成本
  例：无测试覆盖的老模块，每次改动要人工回归 2h，
      一个月改 4 次 = 月利息 8h + 线上事故概率 10%×事故成本 8h
  → 算出来才知道"这债值不值得现在还"

分级偿还策略：
  高息债（事故率高的核心链路）：马上还，优先级等同新需求
  中息债（常改动但没出事）：排进迭代，每个迭代还 10% 产能
  低息债（稳定没人碰的角落）：记账不还，季度复审一次
  → 关键认知：不是所有债都要还——稳定不动的代码，债其实不产生利息
```

## 2. 核心概念（中英对照）

| 英文 | 中文 | 大白话 |
|------|------|--------|
| Tech Debt | 技术债 | 为了快欠下的维护成本，像贷款有本金有利息 |
| Code Smell | 代码异味 | 不一定是 bug，但让人难受的坏味道（超长方法/重复代码） |
| Boy Scout Rule | 童子军原则 | 每次改代码顺手让这块比来时干净一点（小步还债） |
| Refactoring | 重构 | 不改功能的"整理房间"——还债的主要手段 |
| Blast Radius | 爆炸半径 | 这块代码出事会波及多大范围（决定还债优先级） |

## 3. 动手实操（演练）

### 3.1 演练一：给自己项目建技术债台账

```
台账模板（拿项目五/六的真实欠账填）：
| 债                       | 来源    | 利息估算              | 等级 | 还法          |
|--------------------------|---------|----------------------|------|---------------|
| trace 表无归档，日增几十 MB | 明知故借 | 磁盘 3 个月满+查询变慢 | 高   | M16 已还（采样+分层）|

  这些欠账 day30 复盘还要对一次账。
```

### 3.2 演练二："跟业务借债"话术

```
场景：产品要 2 周上线，正常要 3 周。砍范围不够，得走捷径。

话术四步（借债要说清本金利息还款日）：
  ① 给选项："按质量做要 3 周；要 2 周上线，我建议 X 处走捷径"
  ② 讲利息："捷径的代价是这块改起来会慢 20%，预计月维护多 4h"
  ③ 定还款："下个迭代我还这笔债，占 2 人天，已排进计划"
  ④ 留记录："以上写入方案文档和排期表，到期我们对账"

关键心法：工程师和业务不是"质量 vs 速度"的对立面——
  你把利息和还款计划说清楚，业务自己会做理性选择；
  不说清楚闷头走捷径，出事时双方都是受害者。
```

### 3.3 演练三：AI 陪练"急业务的 pressure"

```
让 AI 扮演"下周五必须上线的业务方"施压：
  业务："就 2 周，能不能行？"
  你：（用四步话术应对，不硬顶也不无脑答应）
  业务："利息以后再说，先上线！"
  你："可以。但我把捷径方案和还款计划写进邮件确认，
      到期请您给我排还款的 2 人天。"（书面化，day04 的规矩）
录音复盘：被带偏的点=话术还不熟练的点。
```

### 3.4 思考题

为什么说"稳定不动的代码，债不产生利息"？（提示：利息来自"每次改动的额外成本"和"故障概率×成本"——没人改、不故障的代码，两项都是零；但它仍是债，因为一旦要动，成本瞬间体现。所以季度复审的意义是盯"什么时候要动了"。）

## 4. 面试连接

**Q：你怎么管理技术债？**
> 三步：台账化（每笔债记来源、利息估算、等级）、利息化决策（利息=改动额外时间+故障概率×成本，算得清才决定还不还）、排期化（高息债等同需求优先还，中息债每迭代固定 10% 产能还，低息债记账季度复审）。跟业务借债时我一定说清"本金、利息、还款日"三件事并书面确认——借债不可耻，失控才可耻。

**Q：业务压得紧，没时间还债怎么办？**
> 我不把"还债"和"业务"对立，而是翻译成业务语言：这笔债每月利息 4 小时维护+一次事故风险，还债 2 天能消除它——这是一笔划算的保险。同时每个迭代固定留 10% 产能做小步还债（童子军原则），积少成多。真到极限时，我会用事故概率说话：不出事大家都好，出了事停机损失远大于这 2 天。
