# Day 04 · 跨团队协作：让别的团队愿意帮你

> **今日目标**：识别协作三大坑；学会 RACI 责任矩阵；掌握"协作翻译术"——把请求说到对方心动、把阻塞说到对方着急。
> **时长**：理论 1h / 演练 1.5h / 输出 0.5h
> **今日产出**：项目六的 RACI 矩阵 + 两次跨团队请求的话术稿

## 1. 知识地图（先讲人话）

```
跨团队协作三大坑（对号入座）：
  ① 目标不一致：你要稳定性，他要赶工期——各说各话，
    开三小时会全在"互相理解"原地踏步
  ② 信息不对称：你把他当黑盒，他把你当甲方——
    "你们那个接口什么时候好？"（他心想：你谁啊）
  ③ 责任模糊：三不管地带（数据口径/边界接口）——
    出事时两个人都有道理，事情没人在做

RACI 矩阵（责任划分的世界语）：
  R Responsible 执行者：干活的人
  A Accountable 负责人：最后背锅/拍板的（每件事只能有一个 A！）
  C Consulted 被咨询者：干之前要问他的
  I Informed 被通知者：干完了告诉他的
  一件事多个 A = 没有人负责；没有 C = 会踩别人的地雷；
  没有 I = 事后惊吓（"你们怎么把我们表给归档了？！"）

协作翻译术（把技术需求翻译成对方语言）：
  ❌ "我们需要你们 DBA 配合归档任务"（命令式，DBA 无感）
  ✅ "现在 trace 表已经拖慢你们的备份链路了（他的痛点），
     我们做了归档方案每天凌晨分批搬数据（打消顾虑：不影响
     主业务），需要你们帮我看下分批删除的锁风险（给对方
     专业尊重 + 明确小请求）"
  公式：对方痛点 + 你的方案（先消顾虑）+ 具体小请求（不要
  笼统的"配合一下"）

坏消息沟通（协作里的加分动作）：
  阻塞别憋着——"我们的归档依赖你们的一个字段，今天下午能给
  答复吗？不能的话我们切降级方案 B，不影响你们排期"——
  给对方台阶 + 给自己备胎，双方的体面都保住了
```

## 2. 核心概念（中英对照）

| 英文 | 中文 | 大白话 |
|------|------|--------|
| RACI | 责任矩阵 | 谁干/谁背/问谁/告诉谁 |
| Interface Person | 接口人 | 对面团队的"总机"（找对人比说对话更优先） |
| Win-Win | 双赢 | 帮你 = 也帮他自己的 KPI（找不到双赢点就先找他的痛点） |
| Escalation | 升级 | 谈不拢找两边老板（最后手段，先礼后兵，用一次少一次） |
| Dependency | 依赖项 | 你等的别人的活——风险管理的重点监控对象 |

## 3. 动手实操

### 3.1 给项目六画 RACI

```
任务拆解：归档任务上线 / 采样策略变更 / 看板指标对齐 / GC 参数变更
（假设协作者：DBA 团队 / 业务运营 / SRE / 直属老板）

任务             | R(执行) | A(负责) | C(咨询)      | I(通知)
归档任务         | 我      | 我      | DBA(锁风险)  | SRE/老板
采样策略         | 我      | 老板    | 运营(报表影响)| SRE
GC 参数          | 我      | 我      | SRE(变更窗口) | 老板
看板指标         | SRE     | 我      | 老板(口径)    | 全组
——检查三条：每行只有一个 A 吗？C 里有没有漏了会被炸的人？
  I 里有没有漏了会惊吓的人？
```

### 3.2 写两次真实请求的话术稿（录音练）

```
请求①（对 DBA，见上面翻译术示例）——结构：痛点+方案+小请求
请求②（对业务运营：采样策略变更，普通会话只留 10%）
  痛点：存储成本涨，快挤占预算（他的预算表）
  方案：客户投诉相关的会话和报错全量保留，运营报表口径不变
  小请求：确认报表数据源是不是这张表，周五前给个"能/不能"
——录音自检：对方第一句反应是"又来活了"（差）还是
  "这事和我有关且不难"（好）？
```

### 3.3 拒绝与被拒绝演练

```
场景 A：对方说"本周排满了，下周吧"——
  你的选项：等（默认）/ 缩小请求（"那先只确认字段口径，
  5 分钟的事"）/ 换方案 B（自力更生）/ 升级（找老板）
  决策依据：等的风险（阻塞多久）vs 升级的成本（透支人情）
场景 B：你要拒绝别人的插队需求——
  公式：确认价值 + 摆出队列 + 给选项（"可以插队，但要砍掉
  X；或者下周三做，你选"）——拒绝的是排期不是人
```

### 3.4 思考题

升级（找老板）为什么是最后手段？什么时候必须用？（提示：升级透支的是两边老板的信任账户和你的"能自己搞定"人设；但涉及安全红线、跨团队目标冲突无解、超期风险大到影响业务时必须升——升级前把事实/方案/你的建议打包好，别把矛盾裸提交）

## 4. 面试连接

**Q：讲一次你跨团队推动的经历。**
> trace 归档要动数据库删除策略，DBA 团队敏感。我的做法：先画 RACI 明确责任，请求话术按"对方痛点（表膨胀已拖慢他们的备份）+ 我的方案（凌晨分批+水位线幂等）+ 小请求（确认锁风险）"来写，一次过。中间字段口径有分歧，我给了降级方案 B 做备胎，没升级到老板层。总结：推动别人的关键不是嗓门大，是让他帮你=帮他自己的 KPI。

**Q：两个团队目标冲突怎么破？**
> 先把冲突从"人对人"翻译成"目标对目标"（他要工期我要稳定，不是他和我过不去）；再找交换空间（他的里程碑里哪个我帮得上，我的哪个风险他兜得住）；实在不行升级时带方案不带情绪。我在性能项目里对业务方就做过：采样降量 vs 报表口径，最终"错误和高危全存"保住了他的报表，我的存储目标也达成——双赢点是找出来的不是吵出来的。
