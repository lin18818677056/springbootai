# Day 01 · 从写代码到带队伍

> **今日目标**：先答 M16 交接卡两道思考题（本月第一件事）；认清球员→教练的三种心态转变；做一次"技术语言→老板语言"的翻译热身。
> **时长**：理论 1h / 演练 1.5h / 输出 0.5h
> **今日产出**：交接卡作答 + 项目六的"老板版三句话"

## 1. 知识地图（先讲人话）

```
M16 交接卡两道思考题（先答后翻）：

① "P99 降 40%、存储省 70%"怎么讲给老板听？
   答：老板不关心 P99 是什么，关心三件事——
   a) 省了多少钱：存储 -70% = 少买 ___ 块盘/晚半年扩容（机器钱）
   b) 用户会不会跑：回答快一半 = 卡顿投诉降 ___%，转化率稳住（体验钱）
   c) 会不会出事：台账+看板+四连问 = 性能退化当天抓出来（确定性）
   一句话模板："花了两周，回答快了近一半、存储省了八成，
   没买一台机器，而且以后谁改坏了性能当天就能发现。"
   → day23 用它打模拟答辩

② "池子调大反而炸"这类坑怎么变成团队规范？
   答：一个人的教训是笔记，团队的教训是规范。三步：
   a) 把坑变成问题（评审四连问——day27 已做）
   b) 把问题变成卡点（CI/PR 模板拦住——不填不放行）
   c) 把卡点变成共识（为什么有这四问——讲事故故事比贴规定管用）
   → day17 展开成"推广三部曲"

球员→教练的三种心态转变（本月总纲）：
  ① 产出观：我的产出 = 团队产出之和
    （写代码的手速有上限，让五个人各快 20% 的杠杆没上限）
  ② 成就感：教会别人做成事 > 自己做成事
    （第一次"我的方案让组里三个人少走弯路"的快乐，超过
      自己写完一个模块）
  ③ 汇报观：让老板看得懂、信得过、敢拍板，是硬技能不是嘴皮子
    （再好的方案，老板看不懂 = 不存在）
```

## 2. 核心概念（中英对照）

| 英文 | 中文 | 大白话 |
|------|------|--------|
| IC (Individual Contributor) | 个人贡献者 | 球员：靠自己的手艺产出 |
| Tech Lead / EM | 技术负责人 / 工程经理 | 教练：靠组织和判断产出（P7 常是 TL，P8 必须会 EM 视角） |
| Leverage | 杠杆率 | 你的一个动作撬动多少他人产出（写文档/定规范/带人都是高杠杆动作） |
| Stakeholder | 利益相关方 | 所有"这事跟他有关"的人：老板/业务/上下游/组员 |
| Buy-in | 认同与支持 | 别人真心觉得该干（强压下的执行=假 buy-in，走样只是时间问题） |

## 3. 动手实操

### 3.1 翻译热身：项目六的"老板版三句话"（交接卡①开箱）

```
技术原话（M16 压测报告版）：
  "双工具轮次 P99 从 400ms 降至 220ms；trace 采样分层后日增
  存储降 80%；G1 MaxGCPauseMillis=50 下 Young P99 控制在 50ms 内。"

翻译练习（逐句换成老板语言）：
  ① 快：AI 客服的回复速度提升近一半，客户等待焦虑显著下降
    （工具查询从排队改为并行，这是核心链路）
  ② 省：日志存储成本直降八成，按当前增速推算，晚半年扩容，
    约省 ___ 台服务器
  ③ 稳：系统卡顿（GC 停顿）从用户可感知降到无感；并且建立了
    性能监控防线，未来任何代码改动导致的退化当天即可发现
——三句话全过一遍录音，卡壳的地方就是你还没真理解的地方
```

### 3.2 心态自查表（对号入座）

```
给过去三个月的真实工作打分（1~5 分）：
  □ 我主动帮同事 review 过他们的方案（而不只是等别人 review 我）
  □ 我写过"给别人看"的文档（而不只是给自己看的笔记）
  □ 我推动过一个跨人的改进（哪怕只是让两个人统一了做法）
  □ 我在会上为团队争取过资源或解释过困难
  <3 条 ≥3 分 → 球员为主，本月从"多做一件利他的事"开始练
```

### 3.3 思考题

高杠杆动作排序：自己写一个缓存模块（3 天）vs 写一份"缓存选型+使用规范"文档（2 天）让全组正确用缓存。哪个杠杆高？什么前提下结论反转？（提示：5 人以上团队且都要用缓存→文档高；3 人小组且业务特殊→自己写可能更快。"杠杆"的前提是"别人真能照做"——规范的落地成本要算进杠杆）

## 4. 面试连接

**Q：你为什么想做技术管理？（P7/P8 高频题）**
> 不是"想管人"，是发现杠杆不够：我自己写代码一天快不了多少，但把性能优化方法沉淀成评审四连问后，全组的性能问题复发率降了；把项目经验讲成分享，新人上手快了一倍。我享受"让十个人赢球"的杠杆感——所以我想系统学管理，而不是等着被任命。

**Q：P7 到 P8 的分水岭是什么？**
> 我理解是从"把事做成"到"让一群人持续做成事"：P7 靠技术纵深攻坚，P8 要会向上翻译价值拿资源、向下建规范带梯队、横向对齐跨团队。我自己在练的是翻译和规范推广——项目里我把性能台账推成了团队评审卡点，这是从 IC 视角往 TL 视角迈的第一步。
