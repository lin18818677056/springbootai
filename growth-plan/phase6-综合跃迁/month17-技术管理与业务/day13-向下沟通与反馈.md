# Day 13 · 向下沟通与反馈：布置任务与 SBI 模型

> **今日目标**：学会"讲清楚"的布置任务法（背景/结果/边界/求助线四件套）；掌握 SBI 反馈模型（情境-行为-影响）；理解"你到底交代清楚了吗"的检验标准是对方的复述。
> **时长**：理论 1h / 演练 1.5h / 输出 0.5h
> **今日产出**：任务布置四件套模板 + SBI 反馈两则（表扬版/批评版）录音

## 1. 知识地图（先讲人话）

```
布置任务失败的经典现场：
  你："把这个接口优化一下，明天要看效果。"
  他：改了个 SQL 加了索引。你："我要的是整个接口 P99 下来，
      包括缓存，你重做。"他：委屈且返工。
  病根：你说的是"动作"，没说"背景、结果、边界"——
    他只能猜，猜错全白干。
  心法②呼应：80% 的执行走样是理解没对齐（先同步认知再推进度）。

布置任务四件套（下次交代事情照着说）：
  ① 背景：为什么做这事（关联哪个目标/哪次故障）
  ② 结果：做到什么样子算完成（可验收的描述，最好有数字）
  ③ 边界：什么是你不用做的/不要动的（防止范围自嗨）
  ④ 求助线：卡住了找谁、什么时候来对一次进度
  检验标准（关键动作）：让他复述一遍——
    "你理解下来要做什么？打算怎么做？"——复述有偏差当场纠。

SBI 反馈模型（表扬和批评通用）：
  S（Situation 情境）：什么时候、什么事
  B（Behavior 行为）：对方具体做了什么（只说行为不说人）
  I（Impact 影响）：这个行为造成什么影响（好影响/坏影响）
  对比："你最近不行"（无效攻击）
    vs "上周三的发布（S），你提前写了回滚预案（B），
        故障 5 分钟内恢复，避免了客诉升级（I）"（有效反馈）
```

## 2. 核心概念（中英对照）

| 英文 | 中文 | 大白话 |
|------|------|--------|
| SBI | 情境-行为-影响 | 反馈三段论：只讲事实链，不贴标签 |
| Micromanagement | 微观管理 | 事事插手——管理者的恶名，多为"没讲清楚不敢放手"引起 |
| Delegation | 授权 | 把事连同决策权一起交出去，不是只把苦力交出去 |
| 1:1 | 一对一沟通 | 定期和下属单独聊，听真实状态（不在会上说的话这里说） |
| Psychological Safety | 心理安全感 | 团队里敢说"我不会/我搞砸了"的氛围——出错不藏的前提 |

## 3. 动手实操（演练）

### 3.1 演练一：用四件套重写一次任务布置

```
场景：让组员给 AI 客服加"物流查询"工具（day08 的 WBS 直接用）。

反面布置（多数人的说法）：
  "加个物流查询工具，周五前完成。"（只有动作和时间）

四件套版（演练照着说）：
  ① 背景："客服解决率卡在 78%，物流类问题占比 15% 还在涨，
      是转人工大户——这是本季度降人力成本的关键一环。"
  ② 结果："用户问'订单到哪了'能直接返回快递轨迹；
      工具考卷补 5 题，选择正确率≥90%；灰度日报看一周。"
  ③ 边界："不用做推荐/催单，那俩是下期；快递公司 API 用
      统一网关，别自己直连。"
  ④ 求助线："卡住优先找接口人小王（网关他负责）；
      周三、周五各对一次进度，15 分钟站会就行。"
  最后："你复述下要做的事和计划？"（关键动作！）
```

### 3.2 演练二：SBI 反馈两则（表扬版+批评版）

```
表扬版（对做得好的事，SBI 让表扬具体可信）：
  "昨天灰度监控（S），你发现熔断率异常后主动查了 trace，
   十分钟定位是快递 API 超时并降级（B），
   避免了对用户的持续报错，这个主动排查的习惯特别好（I）。"
  要点：表扬行为而不是天赋——"你真聪明"会让人怕失败，
  "你排查主动"会让人重复这个行为。

批评版（对需要改进的事，SBI 让批评不带攻击）：
  "本周三联调（S），你直接在测试环境跑了压测，
   把共享的 orders-db 打挂了，两组人停工半小时（B）。
   以后压测前按规矩申请专属时段，或在预发环境做（I+期待）。"
  要点：只说行为和影响，不说"你怎么不长记性"——
   行为可以改，人格批判只会让人防御。

两条都录音演练（对着手机说，回听有没有夹带情绪词）。
```

### 3.3 演练三：AI 陪练"复述跑偏的组员"

```
让 AI 扮演布置任务后复述跑偏的组员：
  你：说完四件套让他复述。
  AI 组员："哦，就是加个查询接口，周五前弄完对吧。"
  你：（发现丢了两样：验收标准和求助线——当场补齐）
  AI 组员："那推荐功能我顺便做了吧？"
  你：（边界纠偏："推荐是下期范围，这期别碰，防止范围蔓延"）
  录音复盘：跑偏点=你没讲清楚的点——反馈给你自己。
```

### 3.4 思考题

为什么"让他复述一遍"是最便宜的纠错手段？（提示：复述发生在任务开始（成本 1 分钟），错解在此刻纠正零成本；不复述则错解在交付时暴露（成本=全部返工）。和需求评审"最便宜消灭错误"是同一个原理在不同层级的复用。）

## 4. 面试连接

**Q：你怎么给下属布置任务？**
> 四件套：背景（为什么做、关联什么目标）、结果（做到什么样算完成，最好带数字）、边界（什么不用做不要动）、求助线（卡住找谁、何时对进度）。说完一定让对方复述一遍——复述有偏差当场纠，成本最低。举例子：物流工具的布置，我连验收标准（考卷正确率≥90%）都说清楚，对方一次做对，没有返工。

**Q：怎么批评人又不伤人？**
> SBI 模型：情境、行为、影响，三段只讲事实链不贴标签。比如压测打挂共享库的事，我只说"周三你在测试环境压测把 orders-db 打挂了，两组人停工半小时，以后压测先申请时段"，不说"你怎么不长记性"。行为可以改，人格批判只会激起防御——批评的目的是改行为，不是出气。
