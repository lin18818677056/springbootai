# Day 27 · 性能看板与回归：让优化不回潮

> **今日目标**：给日报加上性能行（三项新指标）；兑现 day02 伏笔（流式分位统计上线）；把"性能回归卡点"焊进流程——优化的最后一步是防退化。
> **时长**：实操 1.5h / 设计 1h / 输出 0.5h
> **今日产出**：日报性能行 v1 + 回归卡点清单

## 1. 知识地图（先讲人话）

```
为什么优化会回潮（退化，Regression）？
  ① 新代码引入新热点（谁又写了 N+1 查询？）
  ② 数据量自然增长（热区表变大查询变慢）
  ③ 配置漂移（某人"临时"调了参数忘了改回）
  ——优化是逆水行舟，不设防线就会退回去。
  防线两层：看板（看得见）+ 卡点（拦得住）。

看板：日报性能行（在 M15 六指标基础上加三行）
  ① GC Young P99 停顿（红线 50ms）——JVM 健康
  ② trace 队列水位 + dropped 计数（红线：水位 >50% 或
    dropped 每小时 >0）——异步链路健康
  ③ 核心查询 P99（热区会话查询，红线 200ms）——存储健康
  兑现 day02 伏笔：分位统计不能每请求全量排序（O(n log n)
  会拖垮自己）——用 HdrHistogram/t-digest 流式分位，
  内存 O(1)、精度可控。一句话：监控统计用"存桶不存数"。

卡点：性能回归的三道闸
  ① CI 基准：核心接口挂 JMH/压测冒烟（低于基线 20% 就红）
  ② 评审清单：涉及"循环里调远程/大对象/无界集合/新线程池"
    的 PR 必须回答四连问
  ③ 值班响应：红线破了谁先看、先降级还是先排查（预案表）
```

## 2. 核心概念（中英对照）

| 英文 | 中文 | 大白话 |
|------|------|--------|
| Regression | 回归/退化 | 优化成果悄悄流失 |
| t-digest / HdrHistogram | 流式分位算法 | "存桶不存数"的分位统计（监控标配） |
| Baseline Test | 基准测试卡点 | CI 里跑性能冒烟，退化就拦 |
| Red Line | 红线 | 超过就告警的阈值（别太多，3~5 条要命值） |
| SLO | 服务等级目标 | 对内的承诺指标（红线应该从 SLO 倒推） |

### 3.2 流式分位替换（兑现伏笔，30 行）

```java
// 换掉 day02 的"全量排序版"（那是教学版，线上不能这么玩）
org.HdrHistogram.Histogram hist = new Histogram(TimeUnit.MINUTES.toNanos(10), 3);
// 每次请求结束：hist.recordValue(elapsedNanos);   // O(1)！
// 日报取值：hist.getValueAtPercentile(99)          // 流式算 P99
// 原理一句话：值域切对数桶，每桶计数——不存原始数据，
// 内存恒定（KB 级），精度 3 位有效数字（监控足够）
```

## 4. 面试连接

**Q：怎么防止性能优化回潮？**
> 两层防线：看板管"看得见"——日报三行性能指标（GC P99/队列水位+dropped/查询 P99），分位统计用 HdrHistogram 流式算法避免监控本身成为负担；卡点管"拦得住"——CI 性能冒烟低于基线 20% 就红，评审清单四连问（远程调用/大对象/有界/池参数）。核心思想：性能是持续运营的，不是一次性运动。

**Q：监控里怎么算 P99 才不会拖垮自己？**
> 不全量排序。用 HdrHistogram/t-digest：值域切桶、每桶计数，O(1) 记录、恒定内存。我项目里把教学版排序统计换成了 HdrHistogram，10 分钟窗口精度 3 位有效数字，监控开销微乎其微——能讲出"为什么不能全排"和"对数桶"两层就算真懂。
