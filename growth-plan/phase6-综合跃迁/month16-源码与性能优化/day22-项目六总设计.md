## 2. 项目定位与架构决策

```
项目六 = 对 M15 项目五的"性能与成本专项治理"（不是新项目，
        是给 Agent 装上"性能工程"这层能力——真实工作里最常见
        的项目形态：老系统优化，比新建系统更能考察功底）

四条架构决策（每条都写清"为什么"）：
  ① 优化对象锁定"模型之外"：Ollama 推理是大头但不归我们管，
     口径诚实——优化空间在工具执行/留痕/存储（归因清楚再动手）
  ② 并行必须带安全阀：只读工具才并行，写操作独占（M15 三道闸
     延续——性能不绑架安全）
  ③ 异步必须分级：可丢的走队列，高危的同步直写（可慢不可丢）
  ④ 存储必须可回放：采样用一致性策略，单会话要么全存要么不存
    （观测数据可以省，断案能力不能丢）
```

## 5. 面试 3 分钟版（先写后练）

```
背景：AI 客服 Agent 上线后，5 轮会话 P99 达 8 秒，trace 日增
几十 MB 有存储风险。
方法：四步法（定目标→测基线→单变量改造→复测），全程台账记录。
测量：Arthas trace 定位两个主链路瓶颈——工具串行 400ms、
同步留痕 45ms；火焰图证实模型等待占大头（口径诚实）。
改造：只读工具虚拟线程并行（写操作独占保安全）；留痕异步批量
（高危直写）；trace 价值分级采样+热温冷分层；G1 停顿目标 50ms
+大字段截断治 Humongous。
结果：双工具轮次 -45%，留痕增量 <1ms，存储 -70%，GC P99 <50ms。
沉淀：性能台账（四格证据）+ 看板回归防线——"优化会回潮，
测量要常驻"。
```
