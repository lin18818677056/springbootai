## 3. 博客⑫大纲：《我给 AI 客服做了次全身体检：一个 Java 后端的性能优化实录》

```
① 开头：AI 客服越用越慢，同事说"加台机器吧"——
   先别花钱，先测量（共鸣钩子）
② 四步法：定目标→测基线→改一处→复测（为什么"感觉变快了"
   不算数，附死代码消除实验）
③ 定罪现场：Arthas trace 抓出工具串行 400ms 和同步留痕 45ms
   （火焰图为什么看不见它——On-CPU vs Off-CPU 认知坑）
④ 三台手术：虚拟线程并行（含写操作独占的安全阀）/
   留痕异步批量（可慢不可丢的分级）/
   trace 采样+冷热分层（银行流水类比）
⑤ 一张台账走天下：四格证据链，谁质疑翻谁（附台账全景）
⑥ 演习挖真 bug：降级联动是根"没接电的保险丝"
   （预案要实弹验证）
⑦ 防回潮：看板三行+评审四连问——优化是持续运营
⑧ 诚实清单：三条未达原样列出（压测绝对值/JFR 精度/STS）
⑨ 预告：性能账本怎么翻译成老板语言（机器钱/体验/确定性）——
   下月技术管理与业务（M17 钩子）
```
