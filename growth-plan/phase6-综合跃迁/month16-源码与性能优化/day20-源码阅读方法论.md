# Day 20 · 源码阅读方法论：怎么读开源不迷路

> **今日目标**：把总纲的"源码三遍法"落到本月实战；复盘本月读过的两份源码；掌握一套"不迷路"的通用流程（含 AI 辅助时代的正确姿势）。
> **时长**：理论 0.5h / 复盘实操 2h / 输出 0.5h
> **今日产出**：本月源码阅读复盘卡 + "读源码不迷路"七条军规

## 1. 知识地图（先讲人话）

```
读源码最大的坑：从第一行读到最后一行。
  ——开源代码几十万行，逐行读 = 从北京走到广州还蒙着眼。
  正确姿势：带着具体问题，只走"主干道"。

三遍法（总纲方法论，本月怎么落地的）：
  第一遍：跑 Demo——day08 先跑 execute 实验（黑盒感受行为）
  第二遍：带问题读主线——"任务到底怎么被工人执行？"
    → 只跟 execute→addWorker→runWorker 一条线，不看异常分支
  第三遍：画图输出——execute 三步舞图 + ctl 位运算图（day08 已交）

"不迷路"七条军规（本月沉淀，面试可讲）：
  ① 先找入口：public API / main / 测试用例（测试是最好的文档）
  ② 带一个问题：读之前写下"我要搞清 X"，读完能答出才算完
  ③ 抓大放小：先主干（正常流程），异常/并发分支二刷再看
  ④ 断点 > 目测：IDE 打断点跑一遍真实调用栈，胜过干读十遍
  ⑤ 注释即地图：类头 javadoc 通常写了设计意图（Doug Lea 的注释
    就是设计文档）
  ⑥ 版本要对齐：读的源码版本必须和跑的版本一致（JDK 21/23/25
    虚拟线程行为都不一样，day10 的 pinning 就是版本差异）
  ⑦ 输出倒逼输入：读完画一张图/写 500 字，讲不清=没读懂

AI 辅助读源码（2026 年的正确姿势）：
  能干：让 AI 讲一个方法的调用链/对比两个版本 diff/解释陌生术语
  不能干：让 AI 替你"总结你懂了"——结论必须回源码验证
    （AI 会编造不存在的字段名；自己没走过断点的"懂"是假懂）
  姿势：AI 给地图，自己走地形。
```

## 2. 核心概念（中英对照）

| 英文 | 中文 | 大白话 |
|------|------|--------|
| Call Path | 调用路径 | 主干道：一个请求在代码里走的正路 |
| Design Intent | 设计意图 | 作者"为什么这么写"（注释和类头里） |

### 3.2 用七条军规读一个新类（现场演练）

```powershell
# 选 JDK 里没读过的 ArrayBlockingQueue，限时 30 分钟：
# ① 带的问题：put 和 offer 的区别在锁层面怎么实现？
# ② 断点跑一把：两个生产者线程一个 put 一个 offer
# ③ 看类头注释：一把锁两条件（notEmpty/notFull）的设计
# ④ 输出：500 字 + 一张"锁与条件"示意图
# ——演练完对照军规七条自评
```

### 3.3 思考题

为什么"断点 > 目测"？看代码以为的执行顺序和真实执行顺序，最容易在哪不一样？（提示：异常路径提前返回/并发时序交错/lambda 实际执行时机/懒加载首次触发——"以为"和"真实"的差距就是 bug 的藏身处）

## 4. 面试连接

**Q：你是怎么读源码的？举个例子。**
> 三遍法：先跑实验建立黑盒直觉，再带一个具体问题只读主线（比如读 ThreadPoolExecutor 我就盯 execute→addWorker→runWorker 一条线，异常分支二刷），最后画图输出讲给别人。本月读线程池和虚拟线程都这么走——先跑"max 失效"实验再读 execute，带着"为什么先排队后扩人"的问题，读完答案和图都留在笔记里。

**Q：AI 时代还需要自己读源码吗？**
> 更需要，但分工变了：AI 干"查地图"（讲调用链/对比版本/解释术语），我干"走地形"（断点验证/主线串联/输出输出）。红线是结论必须回源码验证——AI 会一本正经编造字段名，没走过断点的"懂"在面试官追问两句就露馅。
