# 第 8 月：高并发（High Concurrency）与高可用（High Availability）设计

> **本月一句话目标**：建立"流量来了不慌"的方法论体系——容量估算 → 多级缓存 → 异步削峰 → 弹性扩容 → 降级预案 → 全链路压测。P8 架构师的核心战场：8 个经典场景任点任讲，一次压测从方案到报告独立完成。

> **项目说明**：商城 step04（稳定性保障：限流熔断/降级预案/监控告警）已在 M6 提前落地。本月项目重心是**新增 mall-seckill 秒杀模块**（Redis 预扣+MQ 削峰+分布式限流的完整流量漏斗）与**全链路压测三连**（方案→执行→瓶颈修复）。M7 的思考题——"10 万 QPS 打到 Order.place()，充血聚合哪个环节先崩"——day08 开篇见分晓。

## 二、本月验收标准（6 条，月底逐项打勾）

- [ ] 讲清高并发万能公式：**缓存、异步、水平扩展**+细节手段；商城读/写/扩容三条链路的容量推演文档（每个系数有来源）
- [ ] 8 个经典场景任点任讲：**秒杀/热点 Key/Feed 流/计数排行/签到/红包/附近的人**（每个能主动说 3 个缺陷与应对）
- [ ] 流量防护四件套升级：M6 单机限流 → **Redis+Lua 分布式限流**（含库存分桶 Lua 脚本）

- [ ] mall-seckill 落地：完整流量漏斗（答题→网关限流→Redis 预扣→MQ 削峰→DB 兜底）+ 1000 并发压测不超卖
- [ ] 输出：《高并发 Checklist》《高可用 Checklist》《大促保障预案》《容量规划表》+ 博客 1 篇

## 六、伏笔清单（本月要兑现的前月连线）

- **M7 day30 思考题 → day08**：10 万 QPS 打到 Order.place() 哪个环节先崩？（答案：号段生成与锁库存网关，聚合本身不是瓶颈）
- **M6 day08 限流四算法 → day08/17/25**：单机 RateLimiter 升级 Redis+Lua 分布式限流
- **M6 day13 容量拐点×0.75 → day23**：拐点分析从单接口扩展到全链路
- **M6 day19 对账体系 → day13**：抢红包资金安全 = 幂等+对账双保险的又一实例
- **M6 day17 TCC → day25**：秒杀库存扣减选型对照（Redis 预扣 vs TCC 的取舍）
- **M7 day16 一事务一聚合 → day08/25**：Redis 预扣+MQ 异步落库 = 事务边界缩小到极致
- **M7 day24 状态机 → day25**：秒杀订单复用 OrderStatus 流转表
- **M4 Redis 基础 → day09/11/12**：热 Key 拆分/ZSet 榜单/BitMap 签到的场景化回收

> **学习方法不变**：每天 = 知识地图（图解）→ 核心概念（中英对照）→ 动手实操（可复现代码）→ 面试连接（Q&A）→ 验收清单（commit 收口）。
