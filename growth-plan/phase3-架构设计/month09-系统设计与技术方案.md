# 第 9 月：系统设计（System Design）方法论与技术方案写作

> **本月一句话目标**：把前两个月的知识沉淀为"可复用的系统设计方法论 + 4 份高质量技术方案"，这是 P8 面试系统设计轮的直接弹药库，也是架构师日常工作的核心产出物。本阶段（阶段三）收官。

## 本月目标与验收标准

- [ ] 掌握系统设计六步法：需求澄清 → 容量估算 → 接口设计 → 数据模型 → 架构演进 → 权衡与风险
- [ ] 独立完成 4 个系统设计：短链接、扫码登录、IM 即时通讯、支付系统
- [ ] 掌握技术方案文档（RFC）标准结构，写出 1 份可评审级别的完整方案
- [ ] 主持一次模拟架构评审（对商城或自选系统），输出评审纪要
- [ ] 阶段三毕业：达成 README 里程碑 M3 全部标准

## 每日计划

### 第 1 周：系统设计方法论 + 短链接系统

| 日 | 主题 | 知识点（中英对照） | 实战任务 | 验收标准 |
|----|------|-------------------|---------|---------|
| D1 | 六步法总览 | 系统设计六步法框架；面试/评审中如何用 45 分钟讲完一个系统（5/5/5/10/15/5 分钟分配） | 把六步法做成检查卡 | 能用六步法拆解任意题目 |
| D2 | 容量估算专项 | 存储估算（行数 × 行宽 × 副本 × 增长率）、带宽估算（QPS × 报文大小）、缓存估算（二八法则 × 热数据集）；常见量级：1 亿用户/日千万订单的量级感 | 对商城做一次完整容量估算 | 三个维度估算误差可解释 |
| D3 | 短链接(1) 设计 | 需求（跳转延迟/统计/防滥用）、ID 生成：自增 + Base62 编码 vs 哈希（MurmurHash + 冲突处理）、发号器设计 | 完成短链系统概要设计 | 能讲清 62 进制编码数学原理 |
| D4 | 短链接(2) 高频读优化 | 301/302 重定向选择（301 永久缓存无法统计 vs 302 临时可统计）、CDN + 多级缓存、布隆过滤器判黑名单、防爬虫 | 实现短链服务核心（发号 + 跳转 + 缓存） | 跳转 P99 < 5ms（缓存命中） |
| D5 | 短链接(3) 数据闭环 | 点击统计（异步聚合：本地聚合 + 定时批量入库）、过期与回收（懒删除 + 定期归档） | 补齐统计模块 | 统计不阻塞主链路 |
| D6 | 方案文档写作(上) | RFC 结构：背景与目标（Why）→ 现状与问题 → 方案详述（How）→ 多方案对比与取舍 → 风险与回滚 → 演进规划；写作原则：结论先行（金字塔原理） | 用模板重写短链方案为 RFC | 结构完整、结论先行 |
| D7 | 周复盘 | 方法论+短链串讲 | 周记 + RFC《短链接系统设计》定稿 | 可用于模拟评审 |

### 第 2 周：扫码登录 + IM 即时通讯系统

| 日 | 主题 | 知识点（中英对照） | 实战任务 | 验收标准 |
|----|------|-------------------|---------|---------|
| D1 | 扫码登录设计 | 三端交互时序：PC（生成二维码 Token）→ 手机（扫码确认）→ PC（轮询/SSE 获取状态）；二维码内容设计（一次性 Token）、状态机（待扫/已扫待确认/已确认/过期） | 实现扫码登录全流程 Demo | 状态机无并发漏洞（重复确认幂等） |
| D2 | 长连接技术选型 | 轮询（Polling）/长轮询（Long Polling）/SSE（Server-Sent Events 服务器推送）/WebSocket（全双工）对比；连接网关（Connection Gateway：百万长连接的接入层） | 四种方式各写最小 Demo 并压测 | 能按场景选型并说理由 |
| D3 | IM(1) 消息模型 | 读扩散 vs 写扩散（参照 month08 Feed 流）、消息表设计（会话表/消息表/序列号 Sequence：单调递增保序）、消息 ID 设计（发号器） | 完成 IM 概要设计文档 | 消息模型能推演收发全流程 |
| D4 | IM(2) 可靠投递 | 可靠性三件套：发送确认（ACK，Acknowledgement 确认应答）、离线消息（Offline Message）、去重（客户端去重表/幂等 ID）；时序问题（服务端序 vs 客户端序） | 实现可靠投递核心链路 | 断网重连后消息不丢不重 |
| D5 | IM(3) 万人群与推送 | 大群写扩散风暴问题（扇出 Fan-out）、读扩散大群、在线推送路由（用户 → 网关节点映射表 Redis）、多端同步（手机+PC 已读位） | 设计 10 万人群聊方案 | 能讲清为什么大群必须读扩散 |
| D6 | RFC 写作(下) | 方案对比的写法（表格对比 + 权重打分）、灰度与回滚章节怎么写、评审人视角自查清单（一致性/容量/故障/成本/安全） | 完成 RFC《IM 系统设计》 | 通过自查清单 ≥ 90% |
| D7 | 周复盘 | 长连接域串讲 | 周记 + 两份 RFC 互查 | 任一细节被追问可回答 |

### 第 3 周：支付系统设计（资金级严谨性）

| 日 | 主题 | 知识点（中英对照） | 实战任务 | 验收标准 |
|----|------|-------------------|---------|---------|
| D1 | 支付整体架构 | 收单（Acquiring）链路：下单 → 风控 → 收银台 → 渠道路由（微信/支付宝/银联）→ 渠道网关；账户体系（待结算/余额账户，复式记账 Double-Entry Bookkeeping 思想） | 画出支付系统全景图 | 复式记账概念运用准确 |
| D2 | 支付幂等与状态机 | 幂等设计：客户端 Token + 服务端唯一索引 + 状态机校验；订单状态机（待支付/支付中/成功/失败/退款中/已退款）；防重复回调 | 实现支付回调幂等处理器 | 重复回调/乱序回调均安全 |
| D3 | 对账与差错处理 | 对账体系：渠道对账单（Download & Parse）、日切（Cut-off Time 切账时间点）问题、三方对账（订单-流水-账务）、差错类型（长款/短款）与处理流程 | 写对账 Job（模拟渠道账单 vs 本地流水） | 能发现 3 类人为制造的差错 |
| D4 | 资金安全 | 资损防控：事前（风控/限额）、事中（双重校验/异步核对）、事后（对账/监控告警/熔断止损）；敏感数据加密与脱敏 | 输出《支付资损防控清单》 | 覆盖事前中后三段 |
| D5 | 退款与异步化 | 退款链路（原路退回）、异步任务可靠性（本地消息表 + 定时扫描 + 重试退避 Exponential Backoff 指数退避）、超时关单（延迟消息） | 实现退款 + 超时关单链路 | 关单与退款并发不冲突 |
| D6 | RFC《支付系统设计》 | 完成 RFC 第三份：支付系统 | 完成 RFC 文档 | 评审人视角自查通过 |
| D7 | 周复盘 | 支付域串讲 | 周记 + 博客素材整理 | 支付三讲（幂等/对账/资损）能脱稿 |
