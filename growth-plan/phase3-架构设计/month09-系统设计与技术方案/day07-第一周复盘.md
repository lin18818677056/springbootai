```
W1 一条主线：把"会做系统"变成"会说清系统"——六步法是骨架，短链是第一个完整血肉：

day01 六步法总览：45min 时间盒（5/5/5/10/15/5）+ 检查卡六节 20 项
  → 核心收获：系统设计答案=技术维度×组织维度（M8 day30 思考题的正式回答）
day02 容量估算专项：QPS 之外补三维——存储（行数×行宽×副本×复利×索引放大）、
  带宽（QPS×报文×8→CDN 决策）、缓存（热数据集×3 冗余→买多大内存）
  → 核心收获：每维估算必须通向一个架构决策，算完无结论=白算
day03 短链 ID 生成：三方案对比（自增/哈希/发号器）→ 发号器+Base62
  → 核心收获：code=Base62(id) 可逆性是枢纽——免映射表+免冲突+分片键一次到位；
     发号器双 buffer 兑现 M8 day08"号段是秒杀第一个崩溃点"的修复
day04 短链高频读：301vs302（统计资产决策）+五层漏斗（浏览器→CDN→Caffeine→Redis→DB）
  → 核心收获：不可变数据消灭缓存一致性问题；布隆前置兑现 M8 day12
day05 短链数据闭环：统计四层（内存聚合→flush→MQ→对账）+UV 分级（HLL 展示/T+1 结算）
  → 核心收获：异步化的丢失上界要有估算（5s=0.006%）；对账三铁律移植
day06 RFC 写作：九节结构+结论先行（TL;DR）+非目标防火墙+数字密度
  → 核心收获：ADR 是决策粒度、RFC 是系统粒度，文档质量=评审效率

六步法检查卡 v1→v1.1（实战发现的修订）：
  ②估算节新增："每维估算写明通向的决策"（day02 教训：只算数不决策是常见废稿）
  ④数据模型节新增："可逆性/不变性检查——能否用纯函数或不可变数据消灭一类问题"
    （day03 Base62 与 day04 缓存的共同启示，升级为通用设计原则）
  ⑥风险节新增："崩溃丢失上界估算"（day05：异步化方案必答"最多丢多少"）
```

## 2. 12 题自测（先答后翻答案）

```text
1. 六步法 45 分钟怎么分配？哪步最长为什么？
2. 存储估算的两个修正因子是什么？各影响多少？
3. 日千万短链，3 年存储量级口算？（行宽 100B×2 副本）
4. 为什么哈希截断输给发号器+Base62？三个硬伤？
5. code 为什么不需要唯一索引？
6. 发号器双 buffer 解决什么问题？号段太长/太短各什么毛病？
7. 301 vs 302 决策依据？"短缓存"折中的代价是什么？
8. 跳转 P99<5ms 的五层漏斗每层命中率？
9. 短链缓存为什么没有一致性问题？（一句话：不可变数据）
10. 统计崩溃最多丢多少？怎么论证可接受？
11. UV 用 HLL 误差多少？结算数据为什么不用它？
12. RFC 的 TL;DR 要包含什么？为什么"非目标"是防火墙？
```

<details>
<summary>参考答案（先自己答完再展开）</summary>

1. 5/5/5/10/15/5；架构演进 15min 最长——演进叙事是区分"背模板"与"有工程经验"的分水岭。
2. 索引放大 1.5~2 倍（二级索引是另一棵 B+ 树）；增长率复利（年增 50%→3 年 1.5³≈3.4 倍）。
3. 1000 万×100B×365×2≈0.7TB/年→复利 3 年约 2.1TB，含索引约 4TB。
4. ①冲突需探测重试②不可逆无法定位分片③长度不稳；Base62 纯函数可逆、零冲突、主键命中。
5. code=Base62(id) 是纯函数，id 有主键约束则 code 必唯一——唯一索引是给"无函数依赖的列"用的。
6. 隐藏 DB 取号延迟（切换零等待）；太短取号频繁、太长重启浪费且乱序加剧。
7. 统计是核心资产→302；代价是每次跳转都回源（读 QPS 不降）→60s 短缓存把重复点击挡在浏览器，统计精度降到分钟级（与业务确认过）。
8. 浏览器 40% → Caffeine 70%（剩 4200）→ Redis 至累计 99.9%（剩<15）→ DB<1。
9. 映射创建后永不修改，只有新增没有失效。
10. 5s 窗口≈1.7 万次/日增量，占 0.006%；统计非资金、业务方接受分钟级延迟。
11. 0.81% 标准差；结算要精确可审计，HLL 是估计值无法对账。
12. 做什么/方案一句话/关键数字/状态；非目标把 scope 谈判前置，防评审蔓延与上线后扯皮。
</details>

## 4. 面试连接

**Q：讲讲你设计过的最有代表性的系统？（简历题，用 W1 素材给出 3 分钟版本）**
> 短链接系统——题小而全，最能展示方法完整性。需求侧：日千万链、跳转 P99<5ms、统计是收费资产；决策侧四个关键点：ID 用发号器+Base62（code 可逆反解 id，免哈希冲突、分片键一次到位，发号器双 buffer 预取把取号延迟完全隐藏）；跳转五层缓存漏斗每层有命中率数字，累计 99.9% 到 DB 趋零，且短链是不可变数据，缓存天然无一致性问题；统计走内存聚合+5 秒 flush+MQ+小时对账的异步闭环，崩溃丢失上界 0.006% 有估算支撑；安全用布隆黑名单前置，90% 流量 O(1) 放行。整个方案 RFC 化——结论先行、决策带被否备选、每节有数字，评审一次通过。这个项目还体现我的演进观：首版刻意不上分库分表，3 年 2TB 触发再上——技术选型和组织能力匹配，复杂度分期交付。
