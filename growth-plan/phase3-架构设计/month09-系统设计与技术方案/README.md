# Month09 · 系统设计与技术方案（阶段三收官）

> **本月一句话**：把 M7-M8 的工程能力沉淀为**方法论与文档资产**——六步法拆任意系统、4 份可评审级 RFC、2 轮模拟评审、阶段三毕业答辩。P8 面试系统设计轮的直接弹药库。

## 本月项目说明

- **主线不是写代码，是"方案工程"**：4 份 RFC（短链接/扫码登录+IM/支付/选型报告）+ 2 轮评审纪要 + 毕业答辩——文档质量就是本月代码。
- **商城资产全面复用**：M8 的估算（day01）、压测（day23）、评审 Checklist（day27）、对账（day13）全部作为 RFC 的素材与方法；扫码登录与 IM 落地为 `practice-projects/02-microservice-mall` 新模块（轻实现重设计）。
- **环境准备**：现有 docker 全家桶即可（Redis/MySQL/RocketMQ/Nacos）；新增 `learning/month09-system-design/`（纯 javac，六步法检查卡与估算脚本）；RFC 统一放 `docs/rfc/`。

## 验收标准（day30 逐条对账）

1. **六步法**：45 分钟内按"需求澄清→容量估算→接口设计→数据模型→架构演进→权衡风险"完成任一新题目设计（白板可查）
2. **4 份 RFC**：短链接、扫码登录、IM 即时通讯、支付系统——结构完整（背景/目标/方案对比/灰度/回滚/演进），自查清单 ≥90%
3. **2 轮模拟评审**：评审纪要（10 问+答复+行动项），方案修订闭环
4. **技术选型报告**：MQ 选型正式版（结合 M5/M6 实测数据，含 PoC 与打分表）
5. **阶段三毕业**：对照总 README 里程碑 M3 三条全过（3 份方案过评审/订单模块等价/45 分钟设计新题）
6. **博客 1 篇**：《支付系统对账设计：让每一分钱都有迹可循》或自选
