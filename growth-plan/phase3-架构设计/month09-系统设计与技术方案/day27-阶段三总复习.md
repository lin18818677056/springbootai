## 3. 动手实操：45 分钟新题演练

```text
新题：设计分布式任务调度系统（45min 计时，六步法走全——只记录要点，完整稿进 docs/）

① 需求澄清（5min 用了 4min）：
  用例：定时任务（日切对账 day17 就是！）+延迟任务（订单关单 day19 就是！）+分片任务（大表扫描）
  非功能：万级任务注册/调度延迟秒级/不重复执行/故障转移/可视化运维
  不做：工作流编排（DAG 另立项）/流式任务（Flink 域）
  ——发现：需求居然全在 M5-M9 用例里出现过（对账 Job/延迟关单/归档扫描）——模式映射生效
② 容量估算（5min）：万级任务×平均 1min 周期 → 调度决策 ~200/s（轻）；任务执行借 worker 集群
  存储任务元数据：万任务×1KB=10MB（毛毛雨）——瓶颈在"调度决策正确性"不在性能
③ 接口（5min）：register(task)/trigger(taskId)/pause/resume/查询执行记录
④ 数据模型（8min）：任务表（cron/分片数/路由策略）/执行记录表（分片键=taskId）/锁表
  分片键三判据：taskId 查询模式✓/均衡✓——执行记录按 taskId 分
⑤ 架构演进（12min）：
  MVP=DB 行锁抢占（SELECT...FOR UPDATE SKIP LOCKED 扫描待执行）——单调度器，任务少够用
  V1=调度器集群+Redis/DB 分布式锁+分片广播（触发：任务>5000 或 调度器单点焦虑）
  V2=时间轮+一致性感派生调度+故障自动转移（触发：任务>5 万 或 秒级精度要求）
  ——每级触发量化 ✓ 留缝：taskId 分片键第一天定 ✓
⑥ 权衡风险（6min）：
  风险1 重复调度（调度器脑裂）→ 分布式锁+执行端幂等（taskId+执行日期唯一）
  风险2 任务长时间运行阻塞 → 超时熔断+心跳续约
  被否：纯 XXL-Job 引用（定制分片策略受限，自研 MVP 学习价值+可控性）
  ——45min 实际用 41min；六步法在"零准备新领域"跑通了（毕业标准③达标）
```

## 4. 面试连接

**Q：你如何评估自己的架构能力到达了什么水平？（自省题，P8 晋升答辩风格）**
> 用证据化自评表回答，不打虚分。六个能力域每个给分数带证据：系统设计方法论 4.5 分——六步法加四份 RFC，45 分钟新题（分布式任务调度）41 分钟六步走全；高并发 4.0 分——秒杀五层漏斗从估算到压测全链路，但缺超大流量生产实战，扣在这里；资金与安全 3.5 分——支付 RFC 理论闭环，但没有真实资损处理经验，这是我和生产型 P8 的最大差距，我不回避。自评的关键纪律是每个分数必须有证据链接和差距说明——打分的价值不在数字在定位短板：我的结构性短板是"个人项目与生产系统"的差距，具体是真实流量、真实故障、真实博弈三类经验。对应的补强路径也清楚：真实流量靠生产机会，真实故障靠演练向桌面推演外扩展，真实博弈靠 next level 的跨团队评审。P8 的自评能力本身就是架构能力的一部分——不知道自己不知道什么，才是最危险的状态。

**Q：45 分钟设计一个你完全没做过的系统，你怎么保证质量？（压力题）**
> 靠方法论的可迁移性，刚在毕业演练里验证过：分布式任务调度，一个我从没设计过的领域，41 分钟六步走全。质量来自三个机制。第一，需求澄清把陌生领域翻译成熟悉问题：问出来"定时+延迟+分片"三类需求后，我马上意识到全在旧存货里——延迟关单做过、对账定时 Job 做过、大表分片扫描做过，"新领域"瞬间变成"旧模式的新组合"。第二，量级估算定位真瓶颈：万级任务调度决策每秒 200 次，性能根本不是问题，瓶颈在"不重复执行"的正确性——这个判断直接决定了后面的架构重心（锁和幂等，而不是堆机器）。第三，演进叙事保底：MVP 用 DB 行锁抢占说明"最简为什么够"，V1 的触发条件（任务超 5000）写死，评审人挑战任何一级我都有"为什么现在不做"的量化依据。所以我的答案是：陌生领域的质量不靠领域知识靠提问质量加模式映射加量化纪律——这三样是跟着方法论走的，领域知识只是加速器。
