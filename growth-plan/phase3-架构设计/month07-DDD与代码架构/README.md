# 第 7 月：DDD（Domain-Driven Design，领域驱动设计）与代码架构

> **本月一句话目标**：从"面向数据库表编程"升级为"面向领域建模编程"。DDD 是区分"熟练工"与"架构师"的第一道分水岭，P8 面试聊架构必问业务建模。本月底商城订单模块完成"贫血→充血"完整重构——兑现 M6 day28 的伏笔。

> **项目说明**：微服务商城的 step03（分布式事务）/step04（稳定性）已在 M6 提前落地（Seata/Sentinel/可观测全链路）。本月项目重心是 **DDD 重构订单模块**——把 step01 只搭了"骨架"的领域建模（Order 充血模型/Money 值对象）展开为完整方法论。

## 五、本月术语表

| 英文 | 中文 |
|------|------|
| Bounded Context | 限界上下文（模型的适用边界） |
| Ubiquitous Language | 通用语言（业务与技术统一词汇） |
| Aggregate Root | 聚合根（一致性与事务边界入口） |
| Anti-Corruption Layer (ACL) | 防腐层（隔离外部模型污染） |
| Anemic / Rich Domain Model | 贫血 / 充血领域模型 |
| Event Storming | 事件风暴（工作坊式领域建模方法） |
| CQRS | 命令查询职责分离 |
| Event Sourcing | 事件溯源（事件序列作为唯一事实来源） |
| God Object / God Method | 上帝对象 / 上帝方法 |
| Fitness Function | 适配度函数（架构特性的量化度量） |
