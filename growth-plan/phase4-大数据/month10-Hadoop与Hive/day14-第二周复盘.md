## 1. 知识地图：一周六线串讲

```
本周主线一句话："数据进了 HDFS，怎么把它用好"——资源怎么分、表怎么建、SQL 怎么写：

① 资源怎么管？（day08）——YARN 三角色
  RM 总包工头（只管批资源）/ AM 工程包工头（管自己的活）/ NM 车间工头（管本机）
  Container 刚性资源包（配大浪费/配小被杀）/ 职责分离让 YARN 能跑 MR 也能跑 Spark

② 资源怎么分才公平？（day09）——调度器与队列
  FIFO 一个队 / Capacity 划摊位（保底+可借）/ Fair 按缺的补
  三级队列设计（prod/offline/dev）三原则：物理隔离/硬保底/硬上限

③ Hive 是什么？（day10）——SQL 翻译官，不是数据库
  HQL→翻译→YARN 作业→HDFS 读文件 / Metastore 只存账本
  读时模式：宽进严出，脏数据靠中间层清洗还债

④ 表的"生死权"归谁？（day11）——内外部表
  内部表删表删数据 / 外部表删表留数据 / ODS 强制外部表（原始数据不可侵犯）
  INSERT OVERWRITE = 幂等重跑的根基

⑤ 数据怎么组织才快？（day12）——分区与分桶
  分区=目录级（裁剪跳目录，Hive 的"粗索引"）/ 分桶=文件级（Bucket Join+采样）
  动态分区要上限（防跑飞）/ 半动态写法（天写死其余动态）

⑥ SQL 怎么写才强？（day13）——窗口函数
  GROUP BY 并行、窗口函数保留行 / 五函数选型 / TopN·环比·连续三板斧
```

## 3. 动手实操：《Hive 建表规范 v1》

```markdown
<!-- docs/hive/table-spec-v1.md —— 本周踩坑的制度化（每条都有本周实验背书） -->
# Hive 建表规范 v1
## 1. 表命名与分层
- 前缀强制：ods_ / dwd_ / dws_ / ads_；库名=业务域（shop/order/user）
- 分区字段统一 dt STRING（yyyyMMdd），小时任务加 hour STRING
## 2. 表类型
- ODS 一律 EXTERNAL（原始数据不可侵犯，day11 实验：误删账本 1 分钟自愈）
- 中间层 INTERNAL（可重算，删表自动清空间）
## 3. 分区与分桶
- 事实表按天分区；动态分区必须设 hive.exec.max.dynamic.partitions（≤2000）
- 亿级+且高频 Join 的大表按业务主键 32/64 桶（Bucket Join 备用）
## 4. 存储格式
- 中间层与应用层 ORC + Snappy（day19 实测后补充具体参数）
- ODS 保持 TEXTFILE（保真，重放友好）
## 5. 数据写入
- 加工任务一律 INSERT OVERWRITE + 分区级重写（幂等，day11 实验）
- 禁止不带分区条件的定时任务（审计脚本每周扫）
## 6. 安全
- 生产表 ACL：写权限收紧到任务账号；删表需双人复核
```

## 4. 面试连接

**Q：如果让你从零建一个团队的 Hive 建表规范，你会怎么制定和推行？（治理题）**
> 三步：先抄事故再定规则最后靠工具。制定阶段，规则不凭空想，每条背后必须是一个真实或亲手复现的事故——我这一周的实验就是"事故库"：内部表误删实验→"ODS 强制外部表"条目；动态分区的上限实验→"max.dynamic.partitions ≤2000"条目；无分区条件的全扫→"定时任务必须带 dt 过滤"条目。有事故背书的规范才有说服力，评审时没人能说"这条没必要"。推行阶段分两档：新表强制过 Checklist（建表 PR 模板里就是规范本身），存量表不搞运动式整改，按"改到谁谁顺手迁"的节奏。固化阶段靠工具替代人肉：写一个审计脚本每周扫两张清单——无分区条件的定时任务、单分区文件数超标目录——结果发群里，让数据说话。我的体会：规范的最高境界不是"大家记住"，是"违反的成本比遵守高"——工具自动拦住了，就没人在意规范存在了。

**Q：本周内容里，你觉得最值得向 Java 后端同事科普的一个点？（检验内化）**
> "INSERT OVERWRITE 的幂等思维"。后端同学写数据同步任务最容易犯的错是"跑失败就手动重跑，重跑完数据翻倍"——因为默认用追加写。数仓的答案是把幂等做进写法里：永远按分区重写（INSERT OVERWRITE dt='xxx'），任务失败自动重试都不怕，重跑十次结果一致。这个思想搬回后端一样值钱：我们的积分结算 Job 从"DELETE 再 INSERT"改成"按天分区整段重算重写"之后，重跑从"提心吊胆半小时"变成"无脑点重试"。一句话科普版：批处理的世界里，幂等不是可选项，是敢自动化的前提——把"可重跑"设计进写法，比事后加对账便宜十倍。这其实也是 M9 支付对账和 M8 红包对账反复出现的那条底线：任何写操作都要能安全地重来一遍。
