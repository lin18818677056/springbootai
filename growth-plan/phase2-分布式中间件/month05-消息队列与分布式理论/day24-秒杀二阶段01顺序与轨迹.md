# Day 24 · 秒杀二阶段①：顺序消息接入 + 消息轨迹

> **今日目标**：秒杀项目增量升级（不重复 step04/05）：订单事件改用顺序消息保障同一订单状态机有序；开启消息轨迹，用 Dashboard 追踪一条消息的完整生命周期。
> **时长**：改造 2.5h / 轨迹追踪 1.5h / 记录 1h
> **今日产出**：秒杀工程顺序消息代码 + 消息轨迹截图 + 改造说明

## 1. 知识地图

```
为什么秒杀二阶段要上顺序消息？
  M4 版本：订单事件（创建/支付/关单）用 Concurrently 消费——并发高但同一订单可能乱序
  乱序的真实风险：关单消息先于支付消息被处理 → 把已支付的单关了（状态机错乱）
  M4 靠 DB 状态机兜底（UPDATE ... WHERE status='UNPAID' 天然防错）——没出事故是运气+兜底
  二阶段改造：同一订单的事件按 orderId 路由到同一队列 + Orderly 消费
  → 状态机错误从"靠 DB 兜底"升级为"链路上就不会发生"（纵深防御再加一层）

改造清单（在秒杀工程 practice-projects/01-seckill-system 上增量）：
  ① 生产端：订单事件发送改 send(msg, selector, orderId)——day08 的队列选择器
  ② 消费端：订单事件消费者改 MessageListenerOrderly
  ③ 队列数规划：ORDER_EVENT_TOPIC 8 队列（并行度与顺序的平衡，day08 结论）
  ④ ⚠ 保留秒杀核心链路（Lua 预扣）为 Concurrently——它无顺序需求，别为顺序牺牲吞吐
     （"按需顺序"：只对有状态机语义的 Topic 用 Orderly——方案品味）

消息轨迹 Message Trace（今天第二主题）：
  是什么：Broker 把每条消息的"一生"记录到轨迹主题（RMQ_SYS_TRACE_TOPIC）
    生产端信息：发送耗时/结果/重试次数
    存储信息：落在哪个 Broker/队列/offset
    消费端信息：谁在何时消费、耗时、状态（成功/重试）
  开启：producer.setSendMsgTrace(true)、consumer.setConsumeMsgTrace(...)（traceTopic 默认）
  价值：排查"这条消息到底发出去没/谁消费了/为什么失败"从 30 分钟降到 1 分钟
  ——day13 积压排查三板斧之外的第四板斧：轨迹直查

与对账的关系（W5 day26 伏笔）：
  轨迹是"微观镜"（单条消息的一生）
  对账是"宏观账"（库存/订单总量核对）
  故障演练时两个都用：先对账发现不一致 → 用轨迹定位到具体消息 → 修复 → 复盘
```

## 2. 核心概念（中英对照）

| 概念 | 说明 |
|------|------|
| Message Trace | 消息轨迹（全生命周期记录） |
| RMQ_SYS_TRACE_TOPIC | 轨迹系统主题 |
| Async Trace Dispatcher | 轨迹异步上报（不阻塞主链路） |
| Ordered Event | 有序事件（同一实体的事件按序消费） |
| State Machine Guard | 状态机防护（DB 条件更新兜底） |
| Defense in Depth | 纵深防御（链路有序+DB 兜底双层） |

## 4. 面试连接

**Q：你的秒杀为什么要做顺序消息改造？改了哪里？**
> 场景故事化：压测与演练中发现"关单与支付事件并发时依赖 DB 状态机兜底"——功能没错但链路上存在乱序窗口，大促极端场景下会把排查变复杂。改造：订单事件 Topic 用队列选择器按 orderId 路由 + Orderly 消费，链路级有序；同时明确"按需顺序"——秒杀预扣链路保持并发消费，避免全局顺序拖垮吞吐。量化：改造后 0 乱序（压测验证），消费 TPS 从 X 降到 Y（队列内串行的代价），在可接受范围。——"发现问题→权衡→改造→量化"完整叙事。

**Q：线上反馈"一条消息好像没消费"，你怎么查？**
> 三步：①Dashboard 轨迹直查（按 Key/MsgId）——看生产端是否成功（重试几次）、消息在哪个队列 offset、消费端处理状态与耗时，1 分钟定位；②轨迹缺失（没开轨迹的老消息）→ mqadmin queryMsgById + 消费者日志反查 + offset 对照；③定位后分类处理：消费失败→看 DLQ 与重试记录；未投递→查路由与队列；消费慢→day13 的积压三板斧。收尾："所以轨迹要常开（异步上报损耗 <5%），这是我把秒杀二阶段必做项之一。"——体现"预防优于排查"的意识。
