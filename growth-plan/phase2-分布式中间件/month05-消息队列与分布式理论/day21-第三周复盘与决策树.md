## 2. 主菜①：《理论→中间件映射表》正式版（≥15 行，存 learning/docs/theory-map.md）

```text
| 理论/原则          | 中间件实例          | 具体机制                                |
|--------------------|---------------------|------------------------------------------|
| AP（分区选可用）   | RocketMQ NameServer | 无状态+客户端 30s 缓存容忍旧路由          |
| CP（分区选一致）   | Kafka unclean=false | ISR 空时分区拒绝服务                      |
| AP/CP 可切换       | Nacos               | 临时实例(Distro)/永久实例(Raft)           |
| BASE-软状态        | RocketMQ 事务消息   | 半消息（存储了但消费者不可见）            |
| BASE-最终一致      | 秒杀三层幂等+对账   | 重试收敛+对账兜底+SLA 5min                |
| 多数派 Quorum      | Kafka min.insync=2  | RF=3 写 2 副本才 ACK                      |
| 多数派 Quorum      | Raft/KRaft/DLedger  | 选举+日志复制都要 N/2+1                   |
| 共识-选举          | Redis Sentinel      | 简化 Raft 选"切换主持人"                  |
| 共识-选举          | Kafka Controller    | KRaft 模式协议选主（ZK 时代靠临时节点）   |
| 逻辑时钟           | Raft Term           | 消息带 term，旧 term 被拒                 |
| 随机化避峰         | Raft 选举超时       | 随机 150-300ms 防瓜分选票                 |
| 两阶段提交         | 事务消息            | 半消息→本地事务→commit/rollback           |
| 补偿事务           | TCC                 | Try 冻结/Confirm 扣减/Cancel 释放         |
| 一致性哈希         | Rebalance 策略      | CONSISTENT_HASH 队列分配                  |
| 哈希环+虚拟节点    | 我的手写路由器      | 迁移率实测 11%（8→9 节点）                |
| 退避重试           | RetryTopic 16 级    | 1s→2h 递增，给下游恢复时间                |
| 幂等               | 幂等生产者(PID+Seq) | Broker 单分区去重                         |
（这就是面试"理论联系实际"的弹药库——每行都是一句完整回答）
```

## 3. 主菜②：七题自测（每题 2.5 分钟，覆盖全周）

```text
1 有人跟你说"我们系统选 CA 不选 P"，你怎么纠正他？（+举一个 AP 判例一个 CP 判例）
2 为什么两个多数派必相交？这个性质保证了 Paxos 的什么？（写出 N/2+1 证明）
3 Raft 选举时为什么要检查"日志新鲜度"？不检查会发生什么？（新 Leader 丢已提交日志）
4 旧任期的日志为什么不能被新 Leader 直接提交？（论文图 8 反例，白板画）
5 一致性哈希 vs 普通取模的迁移率数据？虚拟节点解决什么？（报你的实测数）
6 TCC 三个坑分别是什么？统一解法是什么？（事务控制表+唯一键+状态机）
7 现场需求：跨行转账（要预留语义）+ 订单发货通知（可异步）——各选什么方案，为什么？
```
