## 3. 动手实操

### 3.1 主菜：AggService 全链路（五个组件串联）

```java
// AggService.java —— 限流 → 线程池 → CF 扇出 → 连接池 → 超时降级
import java.util.concurrent.*;
import java.util.concurrent.atomic.LongAdder;

public class AggService {
    // ① 限流闸门：50 TPS，桶 50
    static final TokenBucket GATE = new TokenBucket(50, 50);
    // ② 业务线程池：4 核心、8 最大、队列 50、命名工厂（day15 的 NamedFactory 精简版）
    static final ThreadPoolExecutor BIZ = new ThreadPoolExecutor(4, 8, 60, TimeUnit.SECONDS,
            new ArrayBlockingQueue<>(50),
            r -> new Thread(r, "biz-" + System.nanoTime() % 1000),
            new ThreadPoolExecutor.CallerRunsPolicy());            // 打满让调用者干活=背压
    // ⑤ 监控计数（day09 LongAdder）
    static final LongAdder total = new LongAdder(), degraded = new LongAdder();

    public static void main(String[] args) throws Exception {
        // 模拟 200 个并发请求（超过限流 50 的会被闸门挡掉）
        ExecutorService callers = Executors.newFixedThreadPool(200);
        CountDownLatch latch = new CountDownLatch(200);
        long begin = System.currentTimeMillis();
        for (int i = 0; i < 200; i++) {
            final long uid = i;
            callers.execute(() -> {
                String resp = aggregate(uid);
                if (resp.contains("降级")) degraded.increment();
                total.increment();
                latch.countDown();
            });
        }
        latch.await();
        System.out.printf("总请求=%d 降级=%d 耗时=%dms%n",
                total.sum(), degraded.sum(), System.currentTimeMillis() - begin);
        BIZ.shutdown(); callers.shutdown();
    }

    static String aggregate(long uid) {
        if (!GATE.tryAcquire()) return "限流响应：稍后再试";          // ① 闸门
        try {
            CompletableFuture<String> user = call("用户服务:" + uid, 80);
            CompletableFuture<String> order = call("订单服务:" + uid, 120);
            CompletableFuture<String> mkt = call("营销服务:" + uid, 400); // ★故意慢，触发超时
            CompletableFuture.allOf(user, order, mkt)
                    .orTimeout(150, TimeUnit.MILLISECONDS)            // ④ 150ms 大限
                    .exceptionally(e -> null).join();
            return user.join() + " | " + order.join() + " | "
                    + safe(mkt);                                      // 单独给慢下游降级
        } finally {
            // 演示从简：连接的借还封装在 call() 里
        }
    }
    static CompletableFuture<String> call(String name, long costMs) {
        return CompletableFuture.supplyAsync(() -> {                  // ② 跑在业务池
            try { Thread.sleep(costMs); } catch (Exception e) {}      // ③ 模拟下游耗时
            return name + "(ok)";
        }, BIZ).orTimeout(140, TimeUnit.MILLISECONDS)
          .exceptionally(e -> name.split(":")[0] + "(降级默认值)");    // ④ 单下游降级
    }
    static String safe(CompletableFuture<String> f) {
        try { return f.join(); } catch (Exception e) { return "营销(降级)"; }
    }
}
// 预期：50 个请求拿到完整数据，150 个被限流；营销服务 400ms>140ms 全部降级
// ——限流、超时、降级三道防线的活体演示
```

## 4. 面试连接

**Q：介绍一个你做过的并发优化。**
> 完整叙事模板（把今天的 Demo 讲成项目）：背景（聚合接口串行 300ms，大促流量下超时）→ 方案（CF 并行扇出 + 下游池隔离 + 令牌桶限流 + orTimeout 降级）→ 数据（300ms→100ms，压测 TPS 从 X 到 Y，限流/降级命中率）→ 追问准备（线程池参数依据、AQS 原理、伪共享、连接池耗尽排查——全部有对应 day 的实验背书）。

**Q：限流、超时、降级三道防线的关系？**
> 限流管"进门"（保护自己不被打垮）、超时管"等待"（不无限拖住资源）、降级管"出口"（坏情况也给用户体面响应）。三者组合 = 最坏情况可控；并行聚合 = 最好情况更快。今天 Demo 三道防线全部真实触发过。
