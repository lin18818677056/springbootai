# 07 · AI 应用架构与安全：架构师的收官课

> **本篇目标**：从系统架构视角收束整个 AI 学习：AI 能力如何嵌入企业架构（AI 网关/模型路由/RAG 平台化）、成本治理体系、安全合规清单、团队落地路径。读完你应能独立主导一个企业 AI 平台的技术方案（RFC，Request for Comments，技术方案评审文档）。

## 术语表

| 英文 | 中文 |
|------|------|
| AI Gateway | AI 网关（统一模型接入/鉴权/路由/限流/计量的中间层） |
| Model Router | 模型路由（按任务难度/成本路由到不同模型） |
| Fallback / Circuit Breaker | 降级 / 熔断（传统稳定性技术在 AI 场景复用） |
| Prompt Management | 提示词管理（版本化/灰度/评测）平台能力 |
| Evaluation Pipeline | 评测流水线（模型/Prompt 变更的回归保障） |
| Data Privacy | 数据隐私 |
| Compliance | 合规（备案/算法审核等监管要求） |
| Shadow Traffic | 影子流量（新版本只看不生效，对比用） |
| Unit Economics | 单位经济模型（单次调用成本 vs 产生价值） |

## 1. 企业 AI 应用参考架构（背下这张图）

```
业务系统 A/B/C
     │
┌────▼────────────── AI 平台层（架构师的主战场）────────────────┐
│ AI 网关：统一鉴权 · 模型路由 · 限流熔断 · Token 计量 · 审计日志 │
│ Prompt 管理：版本化 · 灰度 · A/B（对照实验）· 模板市场          │
│ RAG 平台：知识库管理 · 索引流水线 · 检索服务 · 权限过滤         │
│ Agent 运行时：工具注册中心 · 执行沙箱 · 迭代限制 · 审批流       │
│ 评测体系：评测集管理 · 自动回归 · 线上反馈回流                 │
│ 可观测：调用量/Token成本/延迟/质量抽检 四维大盘                │
└────┬──────────────────────────────────────────────────────┘
     │
模型层：云 API（DeepSeek/通义）+ 自建 vLLM 集群（合规域）+ 路由降级链
```

**核心架构决策**：所有业务**不直连模型**，一律走平台层——模型可换、成本可控、安全可管、能力复用。这一条就是 P8 级别的 AI 架构主张。

## 2. 成本治理体系（AI 项目最容易失控的地方）

```
四步管控闭环：
1. 计量：网关记录每次调用的 模型/用户/租户/Token数/费用（没有计量就没有治理）
2. 预算：租户级月度 Token 预算，80% 预警、100% 熔断（可申请扩容）
3. 优化：模型路由（简单问题→小模型，成本降 60%+）
         Prompt 瘦身（资料精选 Top5 而非 Top20）
         结果缓存（高频 FAQ 直接命中，不进模型）
4. 复盘：周报——总成本/单次成本/成本 TOP 调用方/优化收益
```

**单位经济检查**（立项必答）：这条 AI 功能单次调用成本多少？它替代的人工成本或创造的转化价值是多少？**算不过来的场景不做**——这是架构师对业务的守门职责。

## 3. 安全与合规清单（上线 Checklist）

**数据安全**：
- [ ] 敏感数据不出域清单明确（哪些数据可进 Prompt、哪些必须脱敏/拦截）
- [ ] 用户输入与 RAG 检索内容中的 PII（个人身份信息）自动脱敏
- [ ] 向量库/对话日志的存储加密与保留期限策略

**模型行为安全**：
- [ ] 输入侧：提示注入（Prompt Injection）检测、敏感词过滤
- [ ] 输出侧：内容安全审核（涉政/涉黄/侵权）、PII 二次脱敏、结构校验
- [ ] Agent 侧：工具白名单、参数校验、高危操作人工确认（Human-in-the-loop）
- [ ] 幻觉防线：RAG 引用溯源 + 忠实度抽检 + 免责声明

**合规**（国内场景）：
- [ ] 生成式 AI 服务备案（对公众提供服务时）
- [ ] 用户协议告知"内容由 AI 生成"
- [ ] 训练/检索语料的版权合规审查

## 4. 稳定性设计（把后端稳定性经验平移过来）

| 传统招式 | AI 场景落地 |
|---------|------------|
| 限流 | 双层限流：用户级 QPS + 全局 TPM（Tokens Per Minute，每分钟词元数） |
| 熔断降级 | 模型 5xx 率超阈值 → 自动切备用模型 → 最终降级为检索直出（不做生成） |
| 超时治理 | 三段超时：网关总超时 / 模型首 Token 超时 / 流式空闲超时 |
| 容量冗余 | 云 API 与自建集群互为灾备（注意合规：敏感流量只走私有域） |
| 全链路灰度 | Prompt 灰度 + 模型灰度 + 功能开关三层独立 |

**面试金句**："AI 应用的稳定性 = 传统稳定性理论 + 概率性组件的新特性——错误是概率性的（幻觉）、容量按 Token 计费、质量需要持续评测回归。传统工程能力是地基，AI 特性是增量。"

## 5. 落地路线图（给团队的提案模板）

```
Phase 1（1~2 月）单点验证：一个场景（智能客服/知识库）跑通 RAG 全链路 + 评测基线
Phase 2（2~3 月）平台化抽离：AI 网关 + Prompt 管理 + 评测流水线，第二个场景快速复用
Phase 3（3~6 月）规模化：多场景接入 · 成本治理 · 安全审计 · 私有化部署选项
每个 Phase 的退出标准：量化指标（回答准确率/成本/延迟 SLA）而非"感觉能用"
```

**向上汇报话术**："我们不是做一个 ChatBot，而是建 AI 基础设施——第一批场景验证价值，平台层让后续每个场景的边际成本递减。"

## 6. 终极自检：你是否达到了"AI 应用架构师"水平

- [ ] 能白板画出企业 AI 平台参考架构并解释每个子系统的存在理由
- [ ] 能为一个新场景做完整技术选型（模型/RAG/Agent/部署）并写出 RFC
- [ ] 能算清单位经济账并用数据说服业务方立项或砍需求
- [ ] 能逐条讲出安全合规 Checklist 并指定落地Owner
- [ ] 能设计三层灰度与四段可观测的发布与监控方案
- [ ] 团队提案：完成 Phase 1~3 路线图并在部门评审通过

## 结语

AI 技术月月剧变，但架构师的价值在于**不变的东西**：抽象（平台层隔离变化）、评估（用数据代替感觉）、成本（单位经济）、安全（最小权限与纵深防御）。这四件事，就是传统后端工程师穿越 AI 时代的护城河。
