# 04 · RAG 检索增强：企业级知识库方法论

> **本篇目标**：RAG（Retrieval-Augmented Generation，检索增强生成）是当前企业 AI 落地**第一场景**。本篇覆盖方法论全貌：为什么 RAG 而不是微调、入库链路设计、检索策略全家桶、评估体系与生产优化。理论框架为主，动手代码见项目四。

## 1. 先想清楚：RAG vs 微调 vs 长上下文

| 方案 | 适合 | 不适合 |
|------|------|--------|
| RAG | 知识频繁更新、要溯源、私有数据、成本敏感 | 深度风格定制（那是微调的活） |
| 微调 SFT | 输出格式/语气/领域话术定型 | 知识注入（贵、难更新、无法溯源） |
| 长上下文直塞 | 文档总量小（< 窗口）、一次性任务 | 文档大（贵且"中间遗忘"）、高频调用 |

**决策金句**："知识 → RAG（可更新、可溯源）；行为 → 微调（格式语气）；数据量小 → 长上下文直塞。三者常组合使用。"

## 2. RAG 全链路地图（三代演进，直接学 Modular 思维）

```
【入库链路】
文档 → 解析(Layout) → 清洗 → 切分(Chunking) → 向量化(Embedding) → 索引(向量+倒排)

【查询链路】
问题 → 预处理(改写/扩展/路由) → 检索(混合多路) → 融合(RRF) → 重排(Rerank)
     → 组装(模板+引用编号) → 生成(Grounded) → 后处理(引用校验/脱敏)

【优化杠杆从左到右排】切分 > 检索 > 重排 > Prompt > 模型
```

Naive RAG 的三大经典病与药方：
1. **检索不准**（垃圾进垃圾出）→ 混合检索 + 查询改写 + Rerank。
2. **上下文污染**（噪声挤占窗口）→ 重排精选 Top5 + 父子块策略。
3. **生成幻觉** → Grounding Prompt + 引用溯源 + 拒答策略。

## 3. 切分策略详解（RAG 效果第一决定因素）

| 策略 | 做法 | 适用 |
|------|------|------|
| 固定长度+重叠 | 300~500 Token，重叠 10~20% | 快速兜底起步 |
| 递归切分 | 段落→句子→词逐级降级切 | 通用推荐（LangChain RecursiveSplitter 思想） |
| 结构感知 | 按标题/章节/表格边界切 | 手册/规范类（首选） |
| 父子块 | 子块（100T）检索命中 → 父块（500T）喂模型 | 检索精度与上下文兼得 |
| 语义切分 | 相邻句向量相似度骤降处切 | 效果好成本高，二阶段优化用 |
| 表格特殊处理 | 表转 markdown 整块 + 行级补充 | 价格表/参数表 |

**验收标准一句话**："每块独立可读，不看上下文也知道在说什么。"

## 4. 检索策略全家桶（按需叠加）

```
Level 1（必做）：向量检索 + topK + 相似度阈值过滤
Level 2（强烈推荐）：+ 关键词路(BM25) + RRF 融合 + 元数据过滤（权限！）
Level 3（效果优化）：+ 查询改写（多轮指代消解）+ Rerank 重排
Level 4（疑难场景）：HyDE（先编假答案再检索）+ Multi-hop（多跳拆解子问题）
```

**容易被忽略的三件事**：
1. **权限过滤必须在检索前**（元数据 where 条件），否则跨部门泄密。
2. **多租户隔离**：向量库按租户分区/collection（集合）隔离，别只靠字段过滤。
3. **知识更新链路**：文档改了 → 增量重嵌入 + 旧块删除（按 doc_id 幂等）——没有更新机制的 RAG 一上线就过期。

## 5. 评估体系：没有评估就没有优化

**离线评估（RAGAS 四指标）**：

| 指标 | 问题 | 及格线经验 |
|------|------|-----------|
| Faithfulness 忠实度 | 答案是否忠于资料（防幻觉） | > 0.85 |
| Answer Relevancy | 答案与问题相关吗 | > 0.8 |
| Context Precision | 命中的资料里有用的排前吗 | > 0.7 |
| Context Recall | 该找到的资料都找到了吗 | > 0.8 |

**线上评估（双闭环）**：
- 显式反馈：答案点赞/点踩 + "没找到想要的信息"按钮 → 每周归因分析。
- 隐式信号：追问率（同一问题换说法再问 = 没答好）、会话放弃率。
- **坏例回流**：线上坏例 → 修复 → 进评测集 → 评测集持续长大，回归防护网越织越密。

## 6. 生产优化与成本账

| 优化点 | 手段 | 收益 |
|--------|------|------|
| 延迟 | 检索并行化（向量/关键词并发）、Rerank 只对 Top20、流式输出 | 首 Token < 3s |
| 成本 | 缓存高频问答（Q→A 缓存）、Prompt 精简、小模型路由（简单问题小模型） | Token 成本降 40%+ |
| 质量 | 意图路由（闲聊走普通对话，知识问答才走 RAG） | 避免无谓检索污染 |
| 可运维 | 知识库版本化、重建索引灰度、灰度切流 | 变更安全 |

**成本估算模板**（拿去就能用）：
```
单次问答 ≈ 输入(系统提示 300T + 资料 2000T + 问题 50T) + 输出 500T ≈ 2850T
日活 1 万 × 人均 5 次 × 2850T × 单价（如 ¥2/百万T 输入价）≈ 日成本可控可预算
```

## 7. 面试高频问答

- **Q：RAG 答不准，你的排查顺序？** → 数据看两头：先 Context Recall（检索侧：切分/检索/融合）再 Faithfulness（生成侧：Prompt/模型）；评测集定位到环节再优化，不做无据调参。
- **Q：为什么不用微调？** → 知识时效、溯源要求、更新成本三连答，收尾"微调管行为，RAG 管知识，不冲突可组合"。
- **Q：RAG 最大的坑？** → "把 demo 当产品：没有评估体系、没有知识更新链路、没有权限过滤——工程闭环比模型效果更难也更重要。"
