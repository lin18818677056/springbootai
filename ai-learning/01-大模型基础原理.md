# 01 · 大模型基础原理（工程师版）

> **本篇目标**：建立工程够用的原理认知——LLM（Large Language Model，大语言模型）怎么"生成文字"、Token 与上下文窗口意味着什么、预训练/SFT/RLHF 三段训练在造什么、选型看哪些指标。不推导数学，只建立"能做正确决策"的模型。

## 1. LLM 的本质：超大规模的"下一个词预测"

```
输入：中国的首都是
模型概率分布：北京 89%，上海 3%，南京 1%，...
输出：采样一个词 → 拼回输入 → 继续预测下一个词（自回归生成）
```

**由这个本质推出的工程结论**（比背原理重要）：
1. 它是**概率模型**，没有"查数据库"式的确定性 → 同一问题两次回答可能不同（温度参数控制随机度）。
2. 它**没有记忆**：所谓对话记忆，是把历史消息重新发给它（上下文窗口装不下的就"忘了"）。
3. 它会**编造**：不知道时也会"顺着说"（幻觉）→ 这就是 RAG 与引用溯源存在的理由。
4. **知识截止**：训练数据有时间终点，新事件它不知道。

## 2. Transformer 与注意力（工程级理解，30 秒能讲清）

- **Self-Attention（自注意力）**：处理每个词时，计算它与句中所有词的"关联度"，按关联度加权融合信息 → "它"能关联到前文的"订单"，"首都在"能关联到"中国"。
- **并行**：注意力让整句并行计算（对比 RNN 逐词串行）→ 这是 LLM 能训练出千亿参数的算力前提。
- **工程影响**：注意力计算量随上下文长度**平方增长** → 长上下文贵且慢，这就是"Prompt 越长越贵、越慢"的底层原因。

## 3. 训练三部曲：模型是怎么"长大"的

```
① 预训练 Pre-training：万亿级 Token 学语言与世界知识 → 基座（会说话，不懂事）
② 监督微调 SFT：十万级人工标注问答 → 学会按指令回答
③ 人类反馈强化学习 RLHF：人类对答案排序 → 学会有用、诚实、无害
```

**选型启示**：
- **基座模型 vs 对话模型**：调 API 用的都是"对话模型"（三步全做完的成品）。
- **微调（Fine-tuning）什么时候用**：风格/格式/领域术语的深度定制；**知识注入用 RAG 不用微调**（知识更新快、可溯源）——"RAG 管知识，微调管行为"是选型金句。
- LoRA（Low-Rank Adaptation，低秩适配微调）：不训全参数，只训小插件，成本低一个量级 → 企业微调首选。

## 4. 推理参数：调 API 时你在控制什么

| 参数 | 含义 | 工程建议 |
|------|------|---------|
| temperature 温度 | 采样随机度（0≈贪心确定） | 知识库/代码 0~0.3；创意文案 0.7+ |
| top_p | 核采样（只从概率累计 p 内的词中采样） | 与温度二选一调，另一个保持默认 |
| max_tokens | 生成上限 | 控成本与防失控输出 |
| stop / n | 停止序列 / 生成候选数 | 结构化提取时用 stop 截断 |
| seed | 随机种子 | 需要可复现的测试场景固定它 |

## 5. 模型选型：架构师要看什么

| 维度 | 看什么 | 实操 |
|------|--------|------|
| 能力 | 权威评测榜单（如 SuperCLUE/LMSYS 竞技场）+ **自建业务评测集** | 榜单只做初筛，业务集才是一票 |
| 成本 | 每百万 Token 单价 × 你的调用量 | 估算：一次 RAG 问答 ≈ 输入 2K + 输出 0.5K Token |
| 延迟 | 首 Token 延迟（TTFT）/ 生成速度（Tokens/s） | 交互式应用 TTFT < 2s 体验才可接受 |
| 合规 | 数据出境、备案、私有化许可 | 政企客户基本必须私有化或用备案国产模型 |
| 生态 | OpenAI 兼容？结构化输出？Function Calling 支持？ | 兼容协议决定你换模型的成本 |

**选型流程模板**：列 3~5 个候选 → 用 50 条业务样本跑同一套 Prompt → 人工盲评打分 → 结合单价与延迟出对比表 → 小流量灰度验证 → 决策。

## 6. 动手实验（1 小时）

```bash
# 用 Ollama 本地跑一个小模型，体感 Token/温度/上下文
ollama run qwen2.5:7b
>>> 你是谁？--verbose    # 看每秒 Token 速度
# 同一个问题问三遍，体会随机性；改 temperature 再试
```

再用 curl 调一次 OpenAI 兼容接口，看懂响应里的 `usage.prompt_tokens / completion_tokens`（用量.提示/生成词元）——成本意识从这里开始。
